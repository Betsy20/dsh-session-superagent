## 一、必须修

### M1　`load()` 没有请求序号/取消，四条调用路径可并发，后到的旧响应覆盖新数据

**位置**：`client.js:1004-1021`（`load` 本体），并发入口在 `client.js:1046`、`2020`、`2064`

```js
1004:      const load = useCallback(async () => {
1005:        try {
1006:          const payload = await call('/state', stateEtag ? { headers: { 'if-none-match': stateEtag } } : undefined)
1007:          // 304：内容没变，别白白重渲染 —— 前提是本地已经有一份能渲染的 body
1008:          if (payload && payload.notModified) {
1009:            if (hasBodyRef.current) return null
1010:            // 本地没有数据：这次 304 是被状态栏的 etag 带出来的，清掉 etag 重取一次全量
1011:            stateEtag = null
1012:            return load()
1013:          }
1014:          const body = payload
1015:          setSnap({ loading: false, error: null, body })
```

**触发条件**：任意两次 `load()` 在途。

`load` 自己没有任何 in-flight 去重（`usePoll` 的 `busy` 只拦「轮询拍自己」），而下面四条路径都能同时发：

| 入口 | 行 | 说明 |
|---|---|---|
| 轮询拍 | `915` `await ref.current()` | 每 5 秒一次 |
| 工具栏「刷新」 | `2020` `onClick: () => load()` | 直接绕过 `busy` |
| 错误卡片「重试」 | `2064` `onClick: () => load()` | 直接绕过 `busy` |
| 任何写操作成功后 | `1046` `await load()` | 与轮询拍天然重叠 |

于是 `call()` 的 `await fetch(...)` 谁先 resolve，谁后写入 —— 没有序号比较，没有 `AbortController.abort()`，也没有「响应里的 etag 是不是比我手里的新」。

**怎么确认的**（真跑，附录 B 的 S1）：让两次 `/state` 都挂住，第一次（快照 V2）后发、第二次（快照 V3）先回，再放第一次：

```
挂载后（服务端 V1）界面含 V1 = true
在途请求数 = 2（A 的快照 V2 / B 的快照 V3）
B 回来后界面含 V3 = true
A 回来后界面含 V2 = true　含 V3 = false　← 旧响应赢了
```

**影响**：慢请求一回来，界面就退回到更旧的快照。真机上表现为「刚点完立刻/保存，界面又跳回上一条状态」；再点一次才对。数据不丢（下次轮询会纠正），但会让人以为写失败又点一次，反而制造 M2 那种覆盖。

**建议**：给 `load` 加自增序号（`const seq = ++loadSeq; … if (seq !== loadSeq) return`），或在 `usePoll` 之外统一用 `AbortController`。`setSnap` 前比较序号即可，不必动服务端。

**触发条件**：打开某条守的行内编辑器（`draft` 定格），期间这条守被别处改动（另一个标签页保存、或服务端自己改了 `intervalSec`/`goal`/`filters`），然后在本标签页点「保存」。

`draft` 只在 `onClick` 那一刻赋值，**之后没有任何 re-sync**（全文件搜 `setDraft` 只有 `1195` 这一处初始化 + 若干 `onChange`）。轮询每 5 秒更新 `snap.body.watchers`，列表跟着变，编辑器里的 `draft` 不变；`saveEdit` 又把整个表单（包括客户没碰过的字段）原样 POST 回去。

**怎么确认的**（真跑，附录 B 的 S6）：打开编辑器（30 秒 / old-goal）→ 服务端改成 300 秒 / new-goal → 轮询刷新 → 点「保存」，抓 POST body：

```
展开编辑器后，行里显示 = 每 30s
轮询拉到 V2 后，行里显示 = 每 300s（列表已经变了，编辑器里的 draft 没变）
点「保存」实际发出的 body：intervalSec=30，goal="old-goal"，sessionId=session-abc
```

**影响**：跨标签页 / 跨客户端的 lost update。服务端 `/watch` 是全量覆盖语义（`lib/index.js:1893` `entry.intervalSec = intervalSec`、`1895` `entry.goal = …`），没有任何版本号或 `If-Match` 兜底，旧快照一定赢。

**建议**：`saveEdit` 只 POST 客户真正改过的字段（`draft` 与快照做 diff），或给 watcher 加 `updatedAt` 做乐观并发（不一致时拒绝并提示「这条守刚被别处改过，请重开编辑器」）。

### M3　模块级 `stateEtag` 被两个组件共享，各自却持有独立 body → 面板永久落后一版

**位置**：`client.js:58`（模块变量）、`client.js:82-86`（任何 `/state` 响应都覆盖它）、`client.js:1006-1012`（面板拿它做条件请求）

```js
 58:    let stateEtag = null
```

```js
 82:        if (etag) stateEtag = etag
 83:        return { notModified: true }
 84:      }
 85:      const freshEtag = res.headers && res.headers.get('etag') ? res.headers.get('etag') : null
 86:      if (freshEtag && path.startsWith('/state')) stateEtag = freshEtag
```

**触发条件**：`StatusOrbit`（状态栏圆环）的轮询比面板先看到服务端变化。

两个组件共用同一个 `stateEtag`，但各有一份 body：

- `StatusOrbit` 的 `load` 是 `await call('/state')`（`703`，**不带** `if-none-match`）→ 永远 200 → 顺手把 `stateEtag` 推到新值；
- `ZhuliPanel` 的 `load` 带 `if-none-match: stateEtag` → 服务端 304 → 走 `1008-1009`：`hasBodyRef.current` 为真（面板**有** body）→ 直接 `return null`，不 `setSnap`。

它信的是「我手里有 body」，而不是「我手里有**这个 etag 对应的** body」。

**怎么确认的**（真跑，附录 B 的 S2）：服务端从 V1（只有 `a/b`）加到 V2（多一条 `c/d`），先让圆环的 `setInterval` 跑，再让面板连跑三拍：

```
初始（V1 = 只有 a/b）：弹层含 a/b = true，弹层含 c/d = false
圆环拉到 V2：弹层含 c/d = true（顺手把模块级 stateEtag 推到 E2）
  面板第 1 次轮询后：含 a/b = true　含 c/d = false　（面板 renders=3）
  面板第 2 次轮询后：含 a/b = true　含 c/d = false　（面板 renders=4）
  面板第 3 次轮询后：含 a/b = true　含 c/d = false　（面板 renders=5）
```

**影响**：只要圆环先看到变化，面板就停在这一版，**直到服务端内容再变一次**（不是 5 秒后自愈）。`intervalSec=300` 时那个窗口最长 5 分钟；守全部暂停、`/state` 不再变化时是无限期。症状就是「圆环说 2 条、列表面板只有 1 条」——`client.js:997-1000` 那段注释记的正是同一个坑的另一半（当时只补了「本地没有 body」的分支）。

**建议**：把 etag 跟着 body 一起存进 `snap`（`setSnap({ ..., etag })`），条件请求用 `snap.etag`，不要用模块变量；304 时只跳过**同 etag** 的重复渲染。

**触发条件**：dock 弹层里点「立刻 / 暂停 / 恢复 / 确认删除」，而 `/watch` 返回非 2xx（`lib/index.js:1841` 的 `409 watcher is paused`、`1840` 的 `404 unknown watcher`、`1876` 的 `503 插件实例已失效`、断网、宿主重启）——全部都被 `802` 吞掉。

**怎么确认的**（真跑，附录 B 的 S3）：打开弹层 → 让 `/watch` 全部 500 → 点「立刻」：

```
POST /watch 次数 = 1（服务端全部 500）
界面文字完全没变 = true
出现的错误提示 = 没有
```

**影响**：这是「静默失败」的教科书形态 —— 客户点了，界面既没报错也没变化，只能得到一个结论「这功能坏了」。对比面板里的 `run()`（`1047-1050` 至少 `setNotice` + `notify`），dock 弹层这一路完全没有出口。

**建议**：`catch (error) { /* 至少 */ notify('操作失败：' + error.message, 'error') }`。弹层里没有 toast 容器的话，退化成 `window.alert` 也比空 catch 强（或把失败写进该行的 `title`）。

## 二、值得改

### W1　`Modal` 的 effect 依赖 `onClose`（内联箭头）→ 每次重渲染重挂 keydown、抢回焦点

**位置**：`client.js:442-463`；两处调用都是内联箭头 —— `client.js:2076`、`client.js:2094`

```js
442:      useEffect(() => {
443:        if (!open || typeof document === 'undefined') return undefined
444:        restoreTo.current = document.activeElement
445:        // 打开后把焦点挪进对话框，否则键盘用户还停在背后的页面上
446:        const timer = setTimeout(() => {
447:          const node = dialog.current
448:          if (!node) return
449:          const first = [...node.querySelectorAll('*')].filter((el) => el.matches(FOCUSABLE))[0]
450:          ;(first || node).focus()
451:        }, 0)
...
456:        document.addEventListener('keydown', onKey)
457:        return () => {
458:          clearTimeout(timer)
459:          document.removeEventListener('keydown', onKey)
```

**触发条件**：弹层打开期间，父组件重渲染一次（每次 `/state` 200 都 `setSnap(新对象)`，见 `1015`；打字、toast 同样触发）。

**怎么确认的**（真跑，附录 B 的 S4，effect 从 `442-463` 逐字复制）：

```
挂载：effect 提交 1 次，keydown 监听器 1 个，焦点动作 ["把焦点抢回弹层第一个控件"]
重渲染 1 次：effect 提交 2 次，keydown 监听器 1 个，焦点动作 ["…","…"]
重渲染 2 次：effect 提交 3 次，keydown 监听器 1 个，焦点动作 ["…","…","…"]
```

监听器数量没涨（cleanup 成对了，这点是好的），但**每渲染一次就重跑一次 focus timer** —— 键盘用户 Tab 到第 3 个控件，5 秒后被打回第 1 个；`restoreTo.current`（`444`）也会被 `456-461` 的 cleanup 先 `focus()` 再重新捕获，注释 `424-425` 承诺的「关闭后焦点回到触发元素」在最需要它的场景（长驻弹层）反而不可靠。

**建议**：`onClose` 用 `useRef` 固定（`const onCloseRef = useRef(onClose); onCloseRef.current = onClose`），effect 依赖只留 `[open]`。

### W2　`run()` 的 `busyRef` 静默丢弃并发点击；批量部分失败后不回读

**位置**：`client.js:1038-1054`

```js
1038:      const busyRef = useRef(false)
1039:      const run = async (work, done) => {
1040:        if (busyRef.current) return
1041:        busyRef.current = true
1042:        setNotice(null)
1043:        try {
1044:          await work()
1045:          if (done) notify(done)
1046:          await load()
1047:        } catch (error) {
1048:          const text = String((error && error.message) || error)
1049:          setNotice({ ok: false, text })
1050:          notify(text, 'error')
1051:        } finally {
```

**怎么确认的**（真跑，附录 B 的 S5）：

```
连点两次「全部暂停」实际发出 POST 次数 = 2（两条守各 1 次；第二次点击被 busyRef 静默丢弃，否则应该是 4 次）
批量恢复中途失败后：「恢复」按钮仍在 = true，错误提示 = 有
```

两件事：① `1040` 的早退没有任何反馈 —— 第二次点击等于没点（`ConfirmBtn` 已经把 armed 清掉了，客户看到的是「确认删除」闪回「删除」）；② `actBulk`（`1094-1100`）串行 `await`，第 3 条失败时前 2 条**已经写进服务端**，但 `catch` 只 `setNotice` 不 `await load()`（`1046` 在 try 里、catch 里没有），界面停在操作前的状态，要等下一拍轮询（5 秒）才纠正。

**建议**：`busyRef` 早退时 `notify('上一次操作还没完成', 'info')`；catch 里补一次 `await load()`（或 `finally` 里 load）。

### W3　渲染期写 ref

**位置**：`client.js:898-900`、`client.js:1001-1002`

```js
897:    function usePoll(task, intervalMs = POLL_MS) {
898:      const ref = useRef(task)
899:      ref.current = task
900:      const busy = useRef(false)
```

```js
1001:      const hasBodyRef = useRef(false)
1002:      hasBodyRef.current = Boolean(snap.body)
```

**为什么算问题**：这是 render 期的副作用，只是目标恰好是 ref 而不是 state —— React 并发渲染下 render 可能被丢弃/重放，而 `hasBodyRef.current` 正是 `load()`（异步闭包）读的那个值（`1009`）。当前是单次同步渲染，**不会死循环**（附录 B 里每次轮询只多 1 次渲染：`renders=3→4→5`，可证没有渲染期 `setState` 自增），但 `usePoll` 里 `ref.current = task` 完全没必要在 render 里做。

**建议**：`useEffect(() => { ref.current = task })`；`hasBodyRef` 改成从 `snap` 现算（`snap.body != null`），或把 `setSnap` 的函数式更新用起来（`setSnap(prev => …)` 里已经能拿到 `prev.body`）。

### W4　圆环的 `setInterval` 不降频、无 in-flight 保护（与 `usePoll` 口径不一致）

**位置**：`client.js:709-711`

```js
709:        load()
710:        const timer = setInterval(load, POLL_MS)
711:        return () => { alive = false; clearInterval(timer) }
```

对比 `usePoll`（`911-917`）：隐藏时 `intervalMs * 6` 降频、`busy` 跳过未完成的上一拍。圆环两样都没有 —— 标签页在后台也每 5 秒全量拉一次 `/state`（`lib/index.js:1599` 注明单份最大约 100 KB），且 `/state` 超过 5 秒时请求会堆叠（`setInterval` 不等上一拍）。

**建议**：圆环也走 `usePoll(load, POLL_MS)`（`load` 已经是 `703-708` 的 async 函数，签名一致）。

### W5　全文件没有 `AbortController`；卸载后 in-flight 请求仍会 `setSnap`

**位置**：`client.js:901-922`（`alive` 只挡住「排下一拍」）、`client.js:1014-1015`（响应回来照样 `setSnap`）

```js
913:          if (!busy.current) {
914:            busy.current = true
915:            try { await ref.current() } catch {}
916:            finally { busy.current = false }
917:          }
918:          if (alive) timer = setTimeout(step, delay)
919:        }
920:        step()
921:        return () => { alive = false; if (timer) clearTimeout(timer) }
```

`load` 本身没有 `alive` 检查：卸载后 `fetch` 仍会跑完、`setSnap` 仍会被调用。React 18 会忽略已卸载组件的 `setState`（不报 warning），所以**不是可见 bug**，但请求没被取消，且闭包（含整份 body）要等到 resolve 才释放。`discoverBase`（`26-53`）同理：卸载后还会把 8 个候选前缀挨个试完。

**建议**：`useEffect` 里建 `const ac = new AbortController()`，cleanup 时 `ac.abort()`，`call()` 把 `signal` 透传下去。

## 三、确认没问题

逐项核对过、**没有**发现问题的：

1. **定时器全部成对释放** —— 5 处 `setTimeout`/`setInterval` 都有对应 `clear*`：
   - `Modal` `446→458`（`clearTimeout` 在 cleanup 里）
   - `StatusOrbit` 轮询 `710→711`（`clearInterval`）
   - `StatusOrbit` 焦点 `731→736`（`clearTimeout`）
   - `usePoll` `918→921`（`clearTimeout`）
   - `useToast` `935→931`（`useEffect(() => () => clearTimeout(...), [])`）
2. **`document` 监听全部成对** —— `456→459`、`727→738` 两处都是同一个 cleanup 里 `removeEventListener`，且都传了同一个 `onKey`/`onDown` 引用（不是内联箭头，所以能删掉）。
3. **卸载后不再排下一拍** —— `usePoll` 的 `alive`（`902/906/918/921`）、`StatusOrbit` 的 `alive`（`699/704/706/711`）、`useEffect` 的 `alive`（`1853/1856/1859`）都正确。
4. **render 里没有 `fetch`/`setState` 死循环** —— 三个 `fetch` 调用点（`36` `discoverBase`、`67` `call`、`612` `note`）全在 async 函数里；`setState` 全在事件回调/effect/async 里。实证：每次 200 只多 1 次渲染（`renders=3→4→5`，附录 B 的 S2），`rerender` 的 50 次保护从未触发。
5. **渲染期没有改模块级变量** —— `BASE`（`18`）只在 `discoverBase` 里改，`stateEtag`（`58`）只在 `call()`（`82/85-86`）和 `load()`（`1011`）里改，都是 async 上下文。
6. **没有乐观更新，所以没有「失败不回滚」** —— 所有写操作（`saveEdit`/`act`/`actBulk`/`addWatcher`/`saveCredentials`/`saveGoal`）都是「先 await，成功后才改本地状态」；`setEditing(null)`（`1087`）、`setToken('')`（`1137-1139`）、`setGoalTouched(false)`（`1144`）全在 `await` 之后。失败时本地状态不变 —— 这是对的（M4 的问题是**不报错**，不是回滚）。
7. **`note()` 的 fire-and-forget 有 `.catch`** —— `612` `fetch(...).catch(() => {})`，不会产生 unhandled rejection；`1855-1857` 的 `/update` 请求也有 `alive` + `catch`。
8. **`goalDraft` 的同步是有意为之** —— `1033-1036` 只在 `!goalTouched` 时用服务端值覆盖，客户一开始打字（`1814` `setGoalTouched(true)`）就不再被覆盖。这是「非受控草稿」的正确写法，和 M2 的 `draft` 不是同一类问题（`draft` 缺的是「保存前 diff」）。
9. **ETag 回退（旧 etag 写回模块变量）自愈** —— 旧 etag 与服务端不匹配时服务端回 200 全量（`lib/index.js:1774`），所以 `stateEtag` 倒退不会导致「永远 304」。有害的只有前进（M3）。

/** 建一个沙箱，返回 { mount, registrations, React, listeners }。 */
export function createRuntime({ fetchImpl } = {}) {
  const listeners = new Map()
  timers = { timeout: [], interval: [], seq: 0 }
  doc = {
    hidden: false,
    activeElement: null,
    getElementById: () => null,
    createElement: () => ({ id: '', textContent: '' }),
    head: { appendChild() {} },
    addEventListener(type, fn) {
      if (!listeners.has(type)) listeners.set(type, new Set())
      listeners.get(type).add(fn)
    },
    removeEventListener(type, fn) { listeners.get(type)?.delete(fn) },
  }

  // ── 假 React：hook 位置索引 + 每次渲染后的 effect 提交 ───────────────
  let current = null          // 当前正在跑的组件 store；null = 静态展开（子组件）
  const Fragment = Symbol('Fragment')

  const React = {
    Fragment,
    createElement(type, props, ...children) {
      const node = {
        type,
        props: { ...(props || {}), children: children.flat(Infinity).filter((c) => c !== null && c !== undefined && c !== false) },
      }
      const ref = props && props.ref
      if (ref && typeof ref === 'object' && 'current' in ref) ref.current = makeElement(String(type))
      return node
    },
    memo: (fn) => fn,
    useState(init) {
      if (!current) return [typeof init === 'function' ? init() : init, () => {}]
      const store = current
      const i = store.index++
      if (!(i in store.hooks)) store.hooks[i] = typeof init === 'function' ? init() : init
      const set = (next) => {
        const value = typeof next === 'function' ? next(store.hooks[i]) : next
        if (Object.is(value, store.hooks[i])) return
        store.hooks[i] = value
        store.dirty = true
      }
      return [store.hooks[i], set]
    },
    useEffect(fn, deps) {
      if (!current) return undefined
      const store = current
      const i = store.index++
      const prev = store.slots[i]
      const same = prev && deps && prev.deps && deps.length === prev.deps.length
        && deps.every((d, k) => Object.is(d, prev.deps[k]))
      if (!same) store.pending.push({ i, fn, deps })
      return undefined
    },
    useCallback: (fn) => fn,
    useRef(value) {
      if (!current) return { current: value }
      const store = current
      const i = store.index++
      if (!(i in store.refs)) store.refs[i] = { current: value }
      return store.refs[i]
    },
  }

  let mod = null
  const sandbox = {
    window: {
      __ModuleLoader__: { load(m) { mod = m } },
      innerWidth: 1440, innerHeight: 900,
      addEventListener() {}, removeEventListener() {},
    },
    document: doc,
    fetch: (url, init) => fetchImpl(url, init),
    setInterval: (fn, ms) => { const id = ++timers.seq; timers.interval.push({ id, fn, ms }); return id },
    clearInterval: (id) => { timers.interval = timers.interval.filter((t) => t.id !== id) },
    setTimeout: (fn, ms) => { const id = ++timers.seq; timers.timeout.push({ id, fn, ms }); return id },
    clearTimeout: (id) => { timers.timeout = timers.timeout.filter((t) => t.id !== id) },
    console,
  }
  vm.createContext(sandbox)
  vm.runInContext(SOURCE, sandbox)
  if (!mod) throw new Error('client.js 没调用 __ModuleLoader__.load')

  const registrations = []
  const ctx = {
    effect: (fn) => fn(),
    slots: { inject: (_n, fn) => fn(), register(opts, Component) { registrations.push({ opts, Component }); return () => {} } },
  }
  mod.factory((name) => { if (name === 'react') return React; throw new Error('unexpected require: ' + name) }).apply(ctx)

  /** 挂载一个组件；返回 getTree / rerender / unmount / effects 计数。 */
  const mount = (Component, initialProps = {}) => {
    const store = { hooks: [], refs: [], slots: {}, index: 0, pending: [], dirty: false }
    let props = { ...initialProps }
    let tree = null
    let renders = 0
    const commits = []
    const render = () => {
      renders += 1
      store.index = 0
      store.pending = []
      current = store
      try { tree = Component(props) } finally { current = null }
      for (const item of store.pending) {
        const prev = store.slots[item.i]
        if (prev && typeof prev.cleanup === 'function') prev.cleanup()
        const cleanup = item.fn()
        store.slots[item.i] = { deps: item.deps, cleanup }
        commits.push({ hook: item.i, deps: item.deps })
      }
      store.dirty = false
      return tree
    }
    const rerender = async () => { for (let i = 0; i < 50 && (store.dirty || i === 0); i += 1) { render(); await flush(5) } return tree }
    const unmount = () => {
      for (const slot of Object.values(store.slots)) if (slot && typeof slot.cleanup === 'function') slot.cleanup()
      store.slots = {}
    }
    render()
    // 模拟「父组件重渲染」：props 换成新对象（onClose 是新的箭头函数 → 引用变了）
    const setProps = (next) => { props = { ...props, ...next } }
    return { get tree() { return tree }, get renders() { return renders }, commits, rerender, unmount, setProps, store }
  }

  return { mount, registrations, React, listeners }
}

/** 展开函数组件，收集整棵树（文本节点记为 #text）。 */
export function walk(node, out = []) {
  if (node === null || node === undefined || node === false) return out
  if (typeof node === 'string' || typeof node === 'number') { out.push({ type: '#text', text: String(node) }); return out }
  if (typeof node !== 'object') return out
  if (typeof node.type === 'function') return walk(node.type(node.props || {}), out)
  out.push(node)
  for (const child of node.props?.children || []) walk(child, out)
  return out
}

export const text = (tree) => walk(tree).filter((n) => n.type === '#text').map((n) => n.text).join(' ')

export function buttonByText(tree, label) {

}

export function runTimers(kind = 'timeout') {
  const list = timers[kind].slice()
  timers[kind] = timers[kind].filter((t) => !list.includes(t))
  for (const t of list) t.fn()
  return list.length
}

export function makeServer(initial) {
  let state = initial
  const log = []
  const gates = []
  let holdNext = 0
  const etagOf = (s) => '"' + JSON.stringify(s).length + '-' + JSON.stringify(s).slice(0, 20) + '"'
  const res = (status, body, headers = {}) => ({
    ok: status >= 200 && status < 300,
    status,
    headers: { get: (k) => headers[String(k).toLowerCase()] ?? null },
    text: async () => body,
  })
  const impl = async (url, init = {}) => {
    const u = String(url)
    const headers = (init && init.headers) || {}
    if (u.includes('/client-note') || u.includes('/client-error')) return res(204, '')
    if (u.includes('/update')) return res(200, JSON.stringify({ current: '0.9.200', latest: '0.9.200', hasUpdate: false }))
    if (u.includes('/state')) {
      const base = u.slice(0, u.indexOf('/state'))
      const snapshot = state
      const snapshotEtag = etagOf(state)
      log.push({ kind: 'state', base, inm: headers['if-none-match'] || headers['If-None-Match'] || null })
      if (holdNext > 0) {
        holdNext -= 1
        await new Promise((resolve) => gates.push(resolve))
      }
      if (base !== '/session-superagent') return res(200, JSON.stringify({ routeBase: base, serverVersion: '0.9.200' }))
      const inm = String(headers['if-none-match'] || headers['If-None-Match'] || '')
      if (inm && inm.split(',').map((v) => v.trim()).includes(snapshotEtag)) return res(304, '', { etag: snapshotEtag })
      return res(200, JSON.stringify(snapshot), { etag: snapshotEtag })
    }
    log.push({ kind: 'other', url: u, init })
    if (u.includes('/watch')) {
      impl.watchCount = (impl.watchCount || 0) + 1
      if (impl.failWatchWhen && impl.failWatchWhen(impl.watchCount)) return res(500, JSON.stringify({ error: 'boom' }))
      // 真的把 pause/resume 落到状态里（否则后续轮询看不出变化，场景 5 就不成立）
      try {
        const body = JSON.parse(init.body || '{}')
        const target = (state.watchers || []).find((x) => x.id === body.id)
        if (target) {
          if (body.action === 'pause') target.enabled = false
          if (body.action === 'resume') target.enabled = true
        }
      } catch {}
      return res(200, JSON.stringify({ ok: true }))
    }
    return res(200, JSON.stringify({}))
  }
  return {
    impl,
    log,
    setState(next) { state = next },
    get state() { return state },
    hold(n = 1) { holdNext += n },
    get gates() { return gates },
    release(i = 0) { const r = gates.splice(i, 1)[0]; if (r) r(); return gates.length },
  }
}
