# 架构

## 分层

```
lib/index.js   插件装配：注入 tools/agents，注册 7 个工具，管理定时器与状态文件
lib/watch.js   纯逻辑：什么算新闻、能不能唤醒、唤醒文本、水位推进
lib/redact.js  纯逻辑：凭证脱敏
```

`watch.js` 与 `redact.js` 不 import 任何 `@deepseek-ai/*`，因此可以被 `node --test` 直接测，不依赖宿主。

## 一次轮询

```
每 N 秒:
  gh api repos/<repo>/issues?sort=updated      ← 凭证在插件内部
  splitFresh(items, {seen, cursor})            ← 逐条水位，自己写的不算新闻
  若无 → 结束（零模型调用）
  若有 → decideWake(agent.status)
            running → 跳过，水位不动，下轮重试
            idle    → Agent.followup(消息)
                      成功 → advanceSeen + cursor 前移
                      失败 → 水位不动，记 lastError
```

## 为什么是 followup 而不是 inbox.append

`Inbox.append` 只把消息排进队列，空闲会话不会自己消费，客户端把它显示成“待发送草稿”。
`Agent.followup()` 会**启动驱动**，消息成为一条真正的用户轮次。

## 为什么只在 idle 时注入

在一轮进行中注入，消息会落进客户端的 pending-input 区；客户端下次同步可能把已发送输入当成草稿回填并重发。
等待 idle 最多多花一个轮询周期。
