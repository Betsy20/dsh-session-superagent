# 报告：空态 / 错误态 / 暂停态视觉核对（深色，0.9.184 → 0.9.185）

> **出图**：`shot-empty.png` / `shot-error.png` / `shot-paused.png`，均 1000×1000。
> **渲染源**：`node scripts/render-preview.mjs --only="空态（无守）|错误态（守失败）|暂停态（已停用）" --dark`，即真实 `client.js` 渲染出的 DOM + 移植 CSS，浅色页面里嵌一块 900px 宽的深色面板。
> **看图的动作**：三张 png 都用 `read_image` 逐张真看过（1000×1000），下面每条都写到「哪一行字、什么颜色、和谁挤在一起、坐标多少」。
> **量尺寸的做法**：不靠肉眼。无头 Edge `--dump-dom` + 注入 `getBoundingClientRect()` / `getComputedStyle()` 采样，原始数字见附录（4）。
> **只读约束**：`client.js` / `lib/**` / `test/**` 一行未动；本任务只改了 `scripts/render-preview.mjs`（场景），新增本报告与 3 张 png。

**读图须知（三条，先说清楚免得把工装缺陷记到面板头上）**

1. **三张图都是深色单主题**（`--dark`），浅色未出图；下面所有色值都是深色主题下的 `--dsw-alias-*`。预览页自带一句免责声明：兜底 token 只是近似值，真机以宿主注入的为准 —— 所以本报告只把「色值之间的关系」（同色/更亮/更灰）当结论，不把具体 hex 当设计规范。
2. **错误态整页比预览框高。** 页面实测 **875px**，预览框 `max-height:820px; overflow:auto`，底部 **55px 被框裁掉**（`按仓库` 里那条仓库行看不见）。这是 `--window-size=1000,1000` + 工装固定高度的限制，不是面板布局错误；第二节所有结论都取自 y<987 的可见区。
3. **三张图的「需要关注」竖条都是灰的**，不是红/琥珀 —— 这不是配色选择，是 `dt-danger` 这个类名没有对应规则（见 2.1、四·4）。
4. **出图时 `client.js` 的版本常量是 `0.9.184`**；本任务收尾时并行工作的另一个提交把它推到了 `0.9.185`（`git diff -- client.js` 只有这一行 `CLIENT_VERSION`）。版本常量不进面板 DOM，所以下面的坐标、色值和结论对当前树仍然逐字有效。

## 一、空态

**整页**：`FRAME 24,167 902x585`，`scrollH=583 = clientH=583` —— 全部可见，无裁切、无横向溢出。面板内容自上而下只有三块：统计条（y=374..398）→ 分区「主理鱼 0」（y=423）→ 引导卡（y=453..751）。

**结论先给**：空态**不是白屏**，它给了三步 + 主按钮 + 一条补白（y=714），「下一步做什么」是有的。问题都在层级：这一屏的每一块都在用同样的音量说话。

### 1.1 统计条四个 0 的单位和数字同色同号 —— 整条读成一句「0 条主理鱼 0 主理中 0 已暂停 0 异常」

- 图上位置：面板第一块内容，四个按钮横排在 y=374（x=64 / 158 / 238 / 318，相邻只隔 24px）。
- 实测：数值 `0` = **`#e6edf3` / 14px / 500**；单位 `条主理鱼` = **`#e6edf3` / 14px / 400**。**颜色完全一样，字号完全一样，只差一档字重。**
- 根因（CSS 级联）：`.dt-stat { color: var(--dsw-alias-label-caption); font-size: 12px }` 本意是「数值强、单位弱」，但紧跟其后的 `.dt-stat-btn { color: inherit; font: inherit }` 把它整条盖掉了 —— 四个统计都带 `onClick`（点了是筛选），所以四个单位全部回到 14px 白字。
- 同一组件的反证：`shot-error` / `shot-paused` 的「按仓库」里那颗**不带 onClick** 的 Stat（`0 / 12 本会话近一小时唤醒`，y=955）单位是 **12px `#7d8590`** —— 同一个 `Stat` 组件，同一页，两种排版。
- 为什么是问题：空态下这条 40px 的色带没有任何可扫读的锚点，四个 0 一样亮，读者必须逐字读完才知道「这是四个空」。

### 1.2 引导卡标题比它自己的步骤标题还「轻」（14px/400 对 13px/500）

- 图上位置：卡片标题「三步让这个会话开始盯办」（`x=72 y=474`，154×20）；下面三条步骤标题「填一个仓库」「选间隔」「点「添加到当前会话」」（`x=102`，y=510 / 562 / 614，13px/500）。
- 实测：卡片标题 **14px / 400 / `#e6edf3`**；步骤标题 **13px / 500 / `#e6edf3`**。标题只大 1px，字重反而更轻。
- 和谁挤在一起：它上方 29px 是分区标题「主理鱼」（14px/**600**，`x=55 y=423`）。空态这一屏的三级标题字重是 **600 → 400 → 500**，中间那个「卡片标题」是断点 —— 它比下一级的步骤标题还细。
- 为什么是问题：卡片标题是这一屏唯一的句子级标题，读者靠它决定「这块要不要读」；现在它和正文同重，卡片看着像没有标题。

### 1.3 第 2 步自相矛盾：「默认 60 秒；先设 300 秒」

- 图上位置：第 2 步说明行（`x=102 y=584`，214×18，12px `#8b949e`）。
- 一句话里两个互斥的数字（默认 60 秒 / 先设 300 秒），且第二个数字没有主语（设谁的 300 秒？间隔？）。空态的三步是「照做就行」的引导，这一步要读者先停下来做判断。
- 和谁挤在一起：它上方 18px 是步骤标题「选间隔」，下方 30px 是第 3 步；这一行是整页唯一一条自相矛盾的文案，而它恰好是「选间隔」这一步唯一的说明。

**这一态最该先修的一处：统计条（1.1）。**

为什么先修它：

1. 它是空态首屏第一块内容（y=374，占 40px 高），读者第一眼就撞上四个同样亮的 0；
2. 同一组件在「按仓库」里已经是正确排版（12px 灰单位），说明这是**级联覆盖**、不是设计取舍 —— 一行 CSS 就能让三张图同时变清楚；
3. 它和 1.2 的层级倒置是同一个病：空态没有「弱信息」，所有字都同样响。先让统计条把「数字强 / 单位弱」立住，1.2 的卡片标题才有一个可参照的层级。

## 二、错误态

**整页**：`FRAME 24,167 902x822`，`scrollH=875 > clientH=820` —— 底部 55px 被预览框裁掉（见读图须知 2）。可见区从上到下：统计条（y=414）→ 需要关注（y=463，2 条）→ 主理鱼（y=557，1 张卡）→ 按仓库（y=865 起）。

**结论先给**：这一屏有 4 处红（左栏 stage、行内 tag、错误行、横幅底），但**最该红的「需要关注」是白的**，而且同一句「跑 gh auth login」在 60px 内说了两遍。

### 2.1 「需要关注」的两条告警是白字 + 灰竖条 —— 全页最该红的区域一次红都没有

- 图上位置：y=493 与 y=521 两行（每行 810×20，左侧 12px 处一条 2px 竖线）：
  - `MYCF711/dsh-session-superagent 轮询失败：GitHub API 请求: 401 Unauthorized （gh 登录失效：跑 gh auth login，或在面板填 token）`
  - `未配置 token，正在复用已登录的 gh CLI（可用 panel 填 token 换成独立凭据）`
- 实测：两行文字都是 **`#e6edf3`（label-primary，纯白）**；左边竖条是 `currentColor` @ 0.45 透明度 = **浅灰**；`background: rgba(0, 0, 0, 0)`（透明）。
- 根因：JSX 里写的是 `<li className="dt-danger">`，但 PORTED_CSS 里**没有 `.dt-danger` 这条规则**（CSSOM 只枚举出 `.dt-banner.dt-danger` 和 `.dt-danger-zone`）。**这是个死类名** —— 想在「需要关注」里加的那抹红，从来没生效过。
- 和谁挤在一起：红色第一次出现要等到 y=601（左栏 `异常`）和 y=628（行内 `异常` 标签），比这两行低 **108px / 135px**。也就是说：读者先读到「轮询失败」这句最重要的结论，读的时候它和普通说明同级。

### 2.2 同一个「异常」在一行里出现两次，相距 124px

- 图上位置：y=601 的左栏状态列 `异常`（`x=65`，24×18，`#f85149`）；y=628 的标签行第一个胶囊 `异常`（`x=189`，38×19，`#f85149` on 10% 红底）。
- 两个红词之间只隔 106px 空白，说的是同一件事（这条守现在是异常）。行内已经有红色状态胶囊，左栏那 112px 宽的状态列就是在复读。
- 和谁挤在一起：同一行右边 10px 处就是 `退避 7200s`（`x=237`，70×19，`#d29922` on 12% 琥珀）—— 一行里两个状态色并排，红的是「现在坏了」，琥珀的是「还要等 7200 秒」，读者要先分辨哪个是结论。

### 2.3 同一句「跑 gh auth login」在 60px 内出现两次，「(28 分钟前前)」多了个「前」

- 图上位置：
  - y=728 红色横幅（676×36，2 行）：「凭证失效：跑 gh auth login 重新登录 —— 它不会自己恢复，在此之前这条守只会一直失败」；
  - y=768 红色错误行（`#f85149`）：「**(28 分钟前前)** GitHub API 请求: 401 Unauthorized」；
  - y=788 灰色括注（13px `#8b949e`）：「（gh 登录失效：跑 gh auth login，或在面板填 token）」。
- **同一句指令在这一屏出现三次**（算上「需要关注」那行是四次），最近两次只隔 **40px**。
- 「28 分钟前前」是叠字：`ageText()` 本身已经返回「28 分钟前」，调用处又拼了一个「前」（`'(' + errAge + '前) '`）。
- 和谁挤在一起：横幅（36px 高）底边到错误行顶边只有 **4px**（`.dt-ticket-body { gap: 4px }`），两段都在说凭证失效，视觉上会读成一段被切开的文字。

### 2.4 错误块 68px 里零间距堆了三样东西

- 图上位置：`y=768..836` 的 `.dt-ticket-note-error`：红字（20px）→ 灰括注（20px）→ `去填 token` 按钮（`x=189 y=808`，79×28），**行间 0px**。
- 实测：容器 676×68 = 20 + 20 + 28，`.dt-actions` 没有 margin；按钮左边缘与红字左边缘完全对齐（都是 x=189），看起来像第三行正文，而不是一个可点的动作。
- 为什么是问题：这一屏唯一需要用户动手的东西（去填 token）是全页最弱的元素（描边、12px、`#e6edf3` 同正文），还紧贴在两行字下面 0px 处。

**这一态最该先修的一处：「需要关注」的 `dt-danger` 死类（2.1）。**

为什么先修它：

1. 用户是自上而下读的，**第一处该红的地方就是「需要关注」**，而它现在是白字；
2. 红色要等到 135px 之后（卡片里）才出现，等于把「最严重」的结论放在了最不显眼的位置；
3. 修法是一行 CSS（`.dt-plain-list > li.dt-danger { color: var(--dsw-alias-state-error-primary) }`），不碰布局、不碰状态机，并且顺手把 2.2 里「红只在行内」的对比失衡扳回来。

## 三、暂停态

**整页**：`FRAME 24,167 902x737`，`scrollH=735 = clientH=735` —— 全部可见。可见：统计条（y=414）→ 需要关注（y=463，1 条）→ 主理鱼（y=529，1 张卡）→ 按仓库（y=725）。

**结论先给**：这一屏能看出「停了」（琥珀胶囊、琥珀左栏、`全部恢复`），但**看不出「为什么停」** —— 原因那行和「轮询 10 分钟前」同款。

### 3.1 暂停原因在卡片里是第 5 行，和「轮询 10 分钟前」同字号同颜色

- 图上位置：卡片内三行 note ——
  - y=627「联调会话 · 1e82afca · 每 60s · 轮询 10 分钟前」
  - y=652「唤醒 2 小时前」
  - y=676「**不在活跃时段（09:00-23:00 之外）：只攒条目，不唤醒**」
- 实测：三行都是 `.dt-ticket-note` → **14px / 20.3px / `#e6edf3` / w400**，三段完全同款，间隔 4px。
- 也就是说：「为什么不动」和「上次轮询是什么时候」在视觉上是同一级。唯一的暂停信号是 y=600 那个琥珀胶囊 `已暂停`（`x=189`，49×19，`#d29922` on 12% 琥珀）—— 它只说「停了」，不说「为什么」。
- 和谁挤在一起：这个原因上方 4px 是「唤醒 2 小时前」，再上方 4px 是「联调会话 · … · 轮询 10 分钟前」；三行等距等重，扫读时原因会被前三行吃掉。

### 3.2 「暂停唤醒：不在活跃时段（…）：只攒条目，不唤醒」—— 一句话两个冒号，且在 183px 内出现两次

- 图上位置：y=493「需要关注」第一行；y=676 卡片第 5 行。**两处逐字相同**。
- 两次都夹在冒号里：外面是 `暂停唤醒：`，里面是 `不在活跃时段（09:00-23:00 之外）：`，尾巴再跟一句 `只攒条目，不唤醒`。中文里连续两个冒号读起来像两段话被粘住。
- 且这一行在「需要关注」里是白字（同 2.1 的死类问题），在卡片里也是白字 —— 全页一条琥珀色正文都没有，琥珀只出现在两个胶囊里。

### 3.3 停用态的工具栏两颗按钮都亮着，其中「全部暂停」是空操作

- 图上位置：`全部暂停`（`x=732 y=308`，70×28）与 `全部恢复`（`x=810 y=308`，70×28），两颗同样是 0.5px 描边、`#a9b4bf` 的幽灵按钮，相距 8px。
- 这一页只有 1 条守，且 `enabled:false`：点「全部暂停」时 `actBulk('pause')` 会在 `if (action === 'pause' && !watcher.enabled) continue` 处直接跳过 —— **点了没有任何反馈、也没有任何变化**。
- 而 `全部恢复` 才是这一页唯一有意义的批量动作，两颗按钮却同权重并排，没有 disabled 态。

**这一态最该先修的一处：暂停原因那一行（3.1）。**

为什么先修它：

1. 暂停态的语义就是「为什么停」，这一行是全页的回答，现在却和「轮询 10 分钟前」同级；
2. 服务端已经给了 `deferReason: 'active-hours'`，客户端也有 `DEFER_LABELS` 映射，**只是没用在行内** —— 把它做成带 warning 色的独立行（或直接塞进 y=595 的标签行，紧跟 `时段 09:00-23:00`）成本极低；
3. 改完顺带消掉 3.2 的逐字重复：卡片里说清楚了，「需要关注」那一条就可以只留一行短摘要。

## 五、结论

**一句话**：三态都「能看懂是空的 / 坏的 / 停的」，但**「为什么」和「我该做什么」都被排在了第二屏**，而且三张图的头部（统计条 + 需要关注）都用同样的白字。

**修复顺序（按收益/成本排）**：

1. **错误态 2.1** —— `.dt-plain-list > li.dt-danger` 一行 CSS，让「需要关注」第一次真的变红。这是三态里唯一「用户会照着做」的区域，现在它连颜色都没有。
2. **暂停态 3.1** —— 把 `lastDeferred` 从第 5 行普通正文提成带 warning 色的独立行（或塞进标签行）。暂停态的全部信息就是「为什么停」。
3. **空态 1.1** —— 修 `.dt-stat-btn` 的 `color: inherit / font: inherit`，让单位回到 12px 灰；空态下统计条也可以整块隐藏（它和「主理鱼 0」重复）。这条三张图同时受益。
4. **错误态 2.3 / 2.4** —— 「跑 gh auth login」去重（横幅留、括注删），`去填 token` 按钮与上两行拉开 ≥8px；顺手修「28 分钟前前」的叠字。
5. **暂停态 3.3** —— 批量按钮补 disabled 态（`enabled` 全为 false 时「全部暂停」禁用）。

**不建议现在动的**：状态词重复（四·3）。左栏 stage 和行内 tag 是两套视觉语言（时间线列 vs 胶囊），去掉任一个都要重排版面，而它不影响理解。
