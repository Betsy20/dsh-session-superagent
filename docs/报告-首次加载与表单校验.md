# 首次状态加载与表单校验修复报告

## 结论

本任务只修改首次状态加载、读取错误展示和 watcher 表单校验提示：

- 主面板首次 `loading` / 首次 `/state` 失败时，不再用 `body={}` 渲染零统计、Onboarding 或任何业务 tabpanel；已有成功快照时仍显示旧数据和读取错误。
- Orbit 保持 `null=尚未读到`、`[]=成功读到空列表` 的区别。首次失败不再写成空数组；弹层用 `—` 代替伪造的 `0 / 0`，并显示读取错误。已有列表在刷新失败后保留。
- watcher 表单原生约束失败时调用 `reportValidity()`，查找第一个 `:invalid` 控件并显式 `focus()`；有效提交路径和 `/watch` POST 契约不变。

没有修改 `lib/`、`package*`、版本、preflight、派单表、轮询/ETag 或服务端 API，没有 push。

## 1. 根因与最小修复

| 缺陷 | 根因 | 修复位置与行为 |
|---|---|---|
| 主面板首载同时显示“正在读取/读不到”和零统计、Onboarding | `snap.body || {}` 派生空 watchers，四个业务页无条件挂载 | [`client.js:3305`](../client.js#L3305) 起，仅 `snap.body` 存在时挂载四个业务页；loading/error 自身保留 |
| Orbit 首次失败变成“还没有主理鱼” | `/state` catch 把 `watchers=null` 写成 `[]` | [`client.js:1585`](../client.js#L1585)：失败保留原 watchers，写入 `读取失败：…`；后续成功只清读取错误，不清写操作错误 |
| Orbit loading/error 显示 `0 / 0` 和空态 | 展示层把 `watchers || []` 当成功空列表 | [`client.js:1810`](../client.js#L1810)：未知状态显示 `— / 读取中或读取失败`；只有成功 `[]` 才显示真空指引；旧列表与读取错误可同时存在 |
| 必填空缺/数字越界点击后无 POST、无可见错误 | 保存 click 已 `preventDefault()`，`checkValidity=false` 后直接 return | [`client.js:1146`](../client.js#L1146)：补 `reportValidity()`、`:invalid` 查询和 `focus()`；有效路径仍进入原 `onSave(values)` |

Orbit 没有新增 `useState` 槽，避免位置化 hook 队列和现有 Orbit/Modal 契约漂移。首次 loading 的闭合触发器保留既有文案契约；本任务修正其弹层状态以及首次**失败**时的触发器摘要和 title。
