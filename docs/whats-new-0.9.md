# 0.9 已发布：你会感知到的变化（面向使用者，不是给开发者看的 CHANGELOG）

> 从 0.8.38 到 0.9.0 有六十多个版本。下面只挑**你打开面板、或收到唤醒时能感觉到**的变化。
> 逐版本的完整记录看 [CHANGELOG](../CHANGELOG.md)；每条背后的调研与取舍看 [docs/kb](kb/README.md)。

## 一、更省、更稳（你不用做什么，但会更少出问题）

| 以前 | 现在 |
|---|---|
| 每轮都整份拉 issue 列表 | **没变化时 GitHub 回 304，不计入速率限制**（[条件请求](kb/github-conditional-requests.md)） |
| 多条守同时到点，一起打 API | **首轮抖动错峰**，不再同一毫秒发车（[jitter](kb/polling-jitter.md)） |
| 额度快用完仍按间隔撞墙 | **剩余 < 500 时自动推迟到额度重置**，面板写明原因（[额度自适应](kb/rate-limit-adaptive.md)） |
| 被 GitHub 限流后继续重试 | **按 `Retry-After` 等**，不瞎猜（[secondary 限流](kb/rate-limit-secondary.md)） |
| 状态文件写坏 = 所有守消失 | **自动从 `.bak` 恢复**，坏的留证（[状态恢复](kb/state-crash-safety.md)） |
| 面板每 5 秒整份重拉 | 我们自己的接口也上了 **ETag/304**（[我们自己的接口](kb/etag-on-our-own-api.md)） |
| 不在活跃时段也照常打 GitHub | **时段判断移到拉数据之前**，夜里基本零请求（[时段前移](kb/active-hours-before-fetch.md)） |
| 被每小时上限挡住时只写"已攒 N 条" | 现在写**「约 43 分钟后可再唤醒」**（[等待可见](kb/wake-cap-wait-visibility.md)） |
| 隔离区只按天数回收，最多能堆几百个 | 再加**数量线：最多留 5 个**（[数量线](kb/worktree-count-cap.md)） |
| 报错是一行英文原始串 | 服务端 12/12 归类 + 面板把 `Failed to fetch` 也翻成人话（[错误人话](kb/humanize-errors.md)） |

## 二、唤醒消息更像"任务书"

以前只有一个条目列表。现在每条会带上：

- **最后是谁在说话**（并且能区分「我上一轮留的」—— 那不代表有人在处理）；
- **已有 PR #N（进行中·草稿·有冲突·等 review·CI 失败）** —— 避免重复劳动；
- **⚠ 被重新打开过** —— 说明之前判"不做"可能不对；
- **未认领** / **躺了 62 天** —— 积压一眼可见；
- **为什么是这几条**：本轮共 N 条变化、按什么取前 K 条、跳过了什么；
- **完成标准**：改了什么 / 怎么验证 / 回写到哪，三条可逐条核对。

## 三、面板上能看见的东西变多了

- **跳过原因累计 + 点开看明细**：回答"我加了标签，为什么一条都没叫醒"；
- **只读 / 已归档 / 无 Issues / fork / 私有** 徽章，且可点筛选；
- **隔离区占用**（几个、多大），保留天数可配；
- **分诊信号与取舍**表：哪些是事实、哪些是我们的判断、默认开不开；
- **设置 → 版本与更新 → 复制诊断信息**：一段脱敏文本，报障时贴给对方就够；
- **第一次打开有三步引导**；已经有守但没唤醒过时，会明确告诉你"在等"，并指向「立刻」。

## 四、安全

- Windows 上 `chmod 0600` 其实无效，**改用 ACL 只留当前用户**（[Windows 权限](kb/windows-secrets-perms.md)）；
- 面板显示 **token 的权限范围**，带 `delete:packages` 这类用不到的宽权限会提示换细粒度 token。

## 五、这次升级要注意的一件事

服务端改动**需要重启宿主**才生效。重启后核对：

```bash
curl -s http://127.0.0.1:65466/session-superagent/state | head -c 160
# 期望 "serverVersion":"0.9.0" 且响应头带 etag
```

如果 `serverVersion` 还是旧值，说明仍在跑老代码 —— 重启一次即可，不用重装。
