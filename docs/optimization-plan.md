# 优化计划（指标驱动，2026-11-02 起）

这份计划的作用：把「继续优化」变成**有数字、有目标、能验收**的清单，
每轮从里面挑一项做，做完更新数字。不靠"感觉更好了"。

```bash

node scripts/preflight.mjs       # 整体门禁（含 UI 体检、路由面、版本、包内容）
```

**已达成 7/7（100 分）**，但 100 分只说明"没有硬伤"，不说明"像原生"。下一批要补的：

- [ ] **组件替换**：把裸 `button`（8 处）换成宿主的 `Btn`/`Tag`，让 hover/active/focus 行为与原生一致；
- [ ] **间距节奏**：面板内边距/行距统一到 4/8/12/16/24 这套（现在端口 CSS 里是官方值，我们自造块里有 2px 的碎值）；
- [ ] **空态样式**：现在的空态是 `dt-hint` 文本，原生更像"图标 + 一行说明 + 一个动作"，考虑换成官方空态结构；
- [x] **深色/浅色双主题预览**：`node scripts/render-preview.mjs out.html` 现在一次出两套主题（9 个场景 × 2），
      兜底 token 用**真名**（旧版写的是 `border-default`/`success-500` 这些宿主上根本不存在的名字，所以预览一直是"没上色"的假象）；
- [ ] **真机双主题实拍**：预览只是近似，宿主机两套主题各截一次才算验完（需宿主，攒批）；
- [ ] **键盘走查**：Tab 顺序 → 弹层 Escape → 焦点回到触发元素（现在弹层只做了遮罩点击关闭）。

## 四、做法约定

1. **不需要宿主就能验的，绝不等到重载**：假 DOM + 假 fetch 能测客户端，`ui-audit` 能测源码级指标。
2. 只有"必须在真实宿主里证明"的事（双主题实拍、真实唤醒闭环）才攒批，一次说清。
3. 每轮汇报必须带**数字变化**（比如"裸 button 8 → 5"），否则视为没做完。
4. 指标不许造：新增指标时先写负例（故意违反一次，确认能抓到），再写正例。
