## 一、假阴性（必须修）

### FN-1 `scripts/audit-glossary.mjs` —— 脚本根本没有退出码，改坏了永远 exit 0

**它检查什么**：从 `client.js` 里抠出「主理鱼术语表」Modal 的 `['词', '解释']` 行，和 `render-panel-copy.mjs` 渲染出的面板文案做双向对照（术语表里的词必须在面板出现；面板里的技术词必须在术语表解释）。

**破坏了什么**：把 `client.js` 里术语表 Modal 的标题改名，让 `clientSource.indexOf("title: '主理鱼术语表'")` 找不到（术语表整块「消失」，解析出 0 条）。

```
术语表 0 条 / 面板文案 135 行
---
PASS 术语表的每个词都在面板里出现过
---
面板在用但术语表没解释（客户可能卡住）：
  上限
  限流
  轮询
  唤醒
  隔离
  副本
  过滤
  时段
  凭证
  ack
  goal
  盯办
EXIT=0
```

第二次破坏：从术语表里删掉「限流」这一行。

```
术语表 15 条 / 面板文案 135 行
---
PASS 术语表的每个词都在面板里出现过
---
面板在用但术语表没解释（客户可能卡住）：
  限流
EXIT=0
```

**为什么没发现**：
1. 脚本全文**没有任何** `process.exitCode` / `process.exit(` —— 两条检查都只 `console.log`。`grep -c "process.exitCode\|process.exit(" scripts/audit-glossary.mjs` 得 `0`。
2. 它打印的是「面板在用但术语表没解释」，**不含 `FAIL` 字样**，所以连专门抓「打印了 FAIL 却不返回非 0」的 `audit-exit-codes.mjs` 也看不见它（`grep -c FAIL scripts/audit-glossary.mjs` 同样是 `0`）。两条门禁同时失效。
3. 更糟：术语表被删空时，`deadTerms.length === 0` 成立 → 打印 **`PASS 术语表的每个词都在面板里出现过`**，这是空集上的假通过。一个「16 条术语全部消失」的重大回归，前半段输出是 PASS。
4. 唯一兜住它的是 `preflight.mjs` 里对**文本**的匹配（`out.includes('PASS 术语表的每个词') && out.includes('PASS 面板里的技术词')`）。任何只跑 `node scripts/audit-glossary.mjs` 再看 `$?` 的调用方（CI、hook、`&&` 链）都会被骗。

**建议怎么补**：
- 结尾加 `if (deadTerms.length > 0 || unexplained.length > 0) process.exitCode = 1`；
- 加一条下限断言：`if (terms.length === 0) { console.log('FAIL 术语表解析出 0 条 —— 选择器漂移了'); process.exitCode = 1 }`；
- 把「面板在用但术语表没解释」这行的前缀也改成 `FAIL `，让 `audit-exit-codes` 能看见。

### FN-2 `scripts/audit-test-skips.mjs` —— 跳过对象换行写、裸 return 带分号，都看不见

**它检查什么**：`test/*.test.mjs` 里 ① `{ skip: ... }` 必须带原因字符串（`? '原因' : false` 形式）；② 用例体内不许有裸 `if (...) return`。

**破坏了什么 A**：给 `test/meta.test.mjs` 追加一个「对象换行写」的无原因跳过。

```js
test('假阴性探针F2', {
  skip: true,
}, () => { assert.ok(true) })
```

```
扫描 22 个测试文件
---
PASS 所有 skip 都带原因
PASS 没有用例体内提前 return
EXIT=0
```

**破坏了什么 B**：用例体内写 `if (x) return;`（带分号）。

```
扫描 22 个测试文件
---
PASS 所有 skip 都带原因
PASS 没有用例体内提前 return
EXIT=0
```

**为什么没发现**：
- ① `line.match(/\{\s*skip:\s*(.+?)\s*\}/)` 是**逐行**匹配，且要求 `{` `skip:` `}` **在同一行**。对象一换行（Prettier 默认就会这么折），整块匹配不到，静默放过。
- ② 提前 return 的正则 `/^\s{2,}if \([^)]*\) return\s*$/` 要求 `return` 之后直接是行尾。`if (x) return;`（分号）、`if (x) return null`（返回值）、`if (a && b(c)) return`（嵌套括号）全都匹配不到。
- 对照：同一行写 `{ skip: true }` 是**能**抓到的（`meta.test.mjs:207  skip: true` → EXIT=1），所以问题只在「写法」上，不在判据上。

**建议怎么补**：
- 判据改成对**整份源码**做多行正则：`/\{\s*\n?\s*skip:\s*([^}]*?)\s*\}?/g` 配 `s` flag，或直接 `text.matchAll(/\bskip:\s*([^,\n}]+)/g)` 再看后面 3 行内有没有 `?` 和引号；
- 提前 return 改成 `/\bif\s*\(.*\)\s*return\b\s*;?\s*$/`（允许分号与返回值）；
- 更彻底：用 `node:vm` / `acorn` 解析 AST，拿 `CallExpression` 的第二参数。

### FN-3 `scripts/audit-doc-ordinals.mjs` —— 只扫 3 份根文档 + 只认「第 N 项」一种写法

**它检查什么**：文档里不许再写「preflight 第 N 项」这类序号引用（序号必然错位），要改成写检查名。

**破坏了什么**：

| # | 破坏 | 结果 |
|---|---|---|
| A | `HANDOFF.md` 末尾写 `这条规则对应 preflight 第 3 项。` | `PASS` EXIT=0 |
| B | `docs/01-架构.md` 写 `preflight 第三项`（中文数字） | `PASS` EXIT=0 |
| C | `docs/01-架构.md` 写 `preflight 第３项`（全角数字） | `PASS` EXIT=0 |
| D | `docs/01-架构.md` 写 `preflight 第 3 条` | `PASS` EXIT=0 |

A 的原始输出：

```
扫描 229 份 Markdown
---
PASS 文档里没有「第 N 项」这类序号引用（名字才稳定，序号插入即错位）
EXIT=0
```

**为什么没发现**：
- **扫描范围漏了根目录**：`files.push(join(ROOT, 'README.md'), join(ROOT, 'UPDATING.md'), join(ROOT, 'MAINTENANCE.md'))` 只补了这 3 份。`HANDOFF.md`、`AGENTS.md`、`CONTRIBUTING.md`、`SECURITY.md`、`CHECKLIST.md`、`CHANGELOG.md` **一份都没扫**。而 HANDOFF 恰恰是最常写「preflight 第 N 项」的交接文档。
- **判据只有一种写法**：`ORDINAL = /第\s*\d+\s*项/g`。`\d` 只匹配 ASCII 数字 → 中文数字（第三项）、全角数字（第３项）都不匹配；`项` 写死 → 「第 3 条」「第 3 步」不匹配（而「步」是流程描述、脚本自己也承认要放过，但「条」不是）。
- 对照：`docs/01-架构.md` 里写标准写法 `preflight 第 3 项` 是**能**抓到的（`docs/01-架构.md:70  第 3 项` → EXIT=1），所以问题在覆盖范围、不在逻辑。

**建议怎么补**：
- 根目录全量：`readdirSync(ROOT).filter(n => n.endsWith('.md'))` 全部纳入（`CHANGELOG.md` 是历史快照，可以像 `报告-` 一样单独排除，但要显式写清）；
- 正则可改 `/第\s*(?:\d+|[０-９]+|[一二三四五六七八九十百]+)\s*(?:项|条)/g`。

### FN-4 `scripts/check-docs.mjs` —— 只认内联链接 `［x］（y）`，另外两种 Markdown 链接形式完全失明

**它检查什么**：全仓库 Markdown 的相对链接必须能解析；`docs/kb/` 下每篇必须被 `docs/kb/README.md` 索引；索引里的「板块 → 篇数」和「共 N 篇」必须和实际一致。

**破坏了什么**：

| # | 破坏 | 结果 |
|---|---|---|
| A（有效） | `docs/01-架构.md` 里加一条内联链接，目标写不存在的 `不存在的文档-xyz.md` | FAIL EXIT=1 |
| B（假阴性） | `docs/kb/` 下新增一篇文档，只在索引**正文**里提一句文件名 | `PASS 知识库文档全部被索引` EXIT=0 |
| C（假阴性） | 文档里写自动链接 `<./不存在的文件-abc.md>` | `PASS 所有内部链接都能解析` EXIT=0 |
| D（假阴性） | 文档里写引用式链接 `[架构说明][ref-nope]` + `[ref-nope]: ./不存在的文件-def.md` | `PASS 所有内部链接都能解析` EXIT=0 |

C 的原始输出：

```
扫描 238 篇 Markdown，210 个内部链接目标
PASS 所有内部链接都能解析
PASS 知识库文档全部被索引
PASS 索引板块篇数与实际条目一致
PASS 索引总数与板块合计一致（182 篇）
PASS 索引有「第一次读」路径（3 篇，文件都存在）
EXIT=0
```

**为什么没发现**：
- **链接正则只覆盖一种语法**：`/\[[^\]]*\]\(([^)\s]+)(?:\s+"[^"]*")?\)/g`。
  - 自动链接 `<path>` —— 没有 `［...］（...）` 结构，匹配不到；
  - 引用式链接 `[label][ref]` + `[ref]: path` —— 同样匹配不到。
  两种都是 CommonMark 合法写法，VSCode/Typora 里点得开，但门禁当它们不存在。
- **孤儿检查判据太松**：`readdirSync(kbDir).filter(name => !index.includes(name))` —— 只要文件名**字符串**在索引里出现过（哪怕是在一句散文、一个代码块、一句「补充阅读：xxx.md」里）就算「已索引」。真正该看的是「有没有进 `| ［标题］（文件名） |` 这种索引行」。
- 对照：B/C/D 的同类破坏，只要写成内联链接（方括号 + 圆括号包路径）就能抓到（`FAIL 1 个链接指向不存在的文件： docs\01-架构.md → 不存在的文档-xyz.md` → EXIT=1），所以问题在语法覆盖、不在逻辑。

**建议怎么补**：
- 补两条正则：`/^\[[^\]]+\]:\s*(\S+)/gm`（引用式定义）和 `/<([^>\s]+\.md)>/g`（自动链接）；
- 孤儿检查改成 `new RegExp('^\\| \\[[^\\]]*\\]\\(' + escapeRegExp(name) + '\\)', 'm').test(index)`。

### FN-5 `scripts/audit-docs-all.mjs` —— 三处：版本跨段 / 路径前缀缺 `docs` / 8 份文档整份豁免

**它检查什么**：`README.md` + `MAINTENANCE.md` + `HANDOFF.md` + `docs/**/*.md` 里 ① `watch_*` 工具名必须存在；② `/session-superagent/*` 路由必须存在；③ 声称的版本不能高于当前；④ 提到的 `scripts|lib|test|src` 路径必须存在。

**破坏了什么**：

| # | 破坏 | 结果 |
|---|---|---|
| A（有效） | `docs/README.md` 写 `watch_` + `totally_fake_tool` | FAIL EXIT=1 |
| B（有效） | `docs/README.md` 写 `/session-superagent/` + `nonexistent-route` | FAIL EXIT=1 |
| C（有效） | `docs/README.md` 写 `０.９.９９９`（高于当前 0.9.217） | FAIL EXIT=1 |
| D（有效） | `docs/01-架构.md` 写 `scripts/` + `does-not-exist.mjs` | FAIL EXIT=1 |
| **E（假阴性）** | `docs/README.md` 写 `0.10.0`（同样高于当前） | **PASS** EXIT=0 |
| **F（假阴性）** | `docs/01-架构.md` 写 `docs/foo-bar-nonexistent.md` | **PASS** EXIT=0 |
| **G（假阴性）** | `HANDOFF.md` 写 `scripts/` + `does-not-exist.mjs` | **PASS** EXIT=0 |

E 的原始输出（注意当前版本就是 0.9.217，`0.10.0` 明显是未来稿）：

```
扫描 46 份文档（不含 docs/kb 与 CHANGELOG）
当前版本 0.9.217；代码里 6 个工具 / 9 条路由
---
PASS 工具名都对得上

PASS 文件路径都对得上

```

G 的原始输出（HANDOFF.md 里一个不存在的脚本路径，整条检查被跳过）：

```
扫描 46 份文档（不含 docs/kb 与 CHANGELOG）
当前版本 0.9.217；代码里 6 个工具 / 9 条路由
---
PASS 工具名都对得上
PASS 路由都对得上
PASS 版本号都对得上
PASS 文件路径都对得上
EXIT=0
```

**为什么没发现**：
- **E（版本）**：正则写死 `\b(0\.[89]\.\d+)\b` —— 只认 `0.8.x` / `0.9.x`。一旦进入 `0.10.x`（或者有人写 `1.0.0`），这条检查**整个失效**。注释说「避免把 Node 22.x 算进来」，但用「只认 0.8/0.9」来实现，等于给下一个次版本埋雷。
- **F（路径前缀）**：路径正则 `(?:^|[^\w/])((?:scripts|lib|test|src)\/...)` 只有 4 个前缀，**没有 `docs`**。而脚本自己的注释写的是「文件路径：全 docs/ 都要能解析」—— 名不副实。`assets/` 同样漏。
- **G（整份豁免）**：`const externalDoc = /官方|prototype|上游|upstream/.test(前15行)`，一旦命中就 `if (externalDoc) break` —— **整个文件跳出路径检查循环**。实测当前有 **8 份**文档被整份豁免：
  ```
  HANDOFF.md
  docs/competitive-analysis.md
  docs/deepseek-papers.md
  docs/design-system.md
  docs/official-gui-ia.md
  docs/README.md
  docs/ui-inventory.md
  docs/报告-测试覆盖缺口.md
  ```
  其中 `HANDOFF.md` 和 `docs/README.md` 是最常被改的两份，它们写的死路径**永远不会被发现**。豁免的本意是「描述别的仓库的文档不必做本仓库路径检查」，但实现成了「整份文档零检查」，而且判据是「开头 15 行出现过这四个词之一」——HANDOFF 只是提了一句「上游」，整份文档的路径就没体检了。

**建议怎么补**：
- E：版本改用「抓全部 `\d+\.\d+\.\d+` 再比大小」，只保留一条排除（`>=22` 的当 Node 版本）；或至少把正则改成 `\b(0\.\d+\.\d+)\b` 并把上界判据交给 `cmp`；
- F：前缀补 `docs|assets`；
- G：把 `if (externalDoc) break` 删掉，改成**行级**跳过（脚本里已经有一份行级 `if (/官方|prototype|上游|upstream/.test(line)) continue`，那条才是对的），或者把豁免判据收窄成「文档首行标题里带『外部仓库』」。

### FN-6 `scripts/audit-kb-claims.mjs` —— ✅ 和版本号必须同一行，换行写就查不到

**它检查什么**：`docs/kb/*.md` 里每条 `✅ … x.y.z` 的版本必须在 `CHANGELOG.md` 里有对应发布；每篇必须写「是否已落地」；提到的 `scripts|lib|test|src|docs` 路径必须存在。

**破坏了什么**：往 `docs/kb/audit-kb-claims.md` 追加一段把 ✅ 和版本号**分两行**写的伪造声明（版本 `０.９.９９９` 在 CHANGELOG 里不存在）。

```markdown
## 追加段落
- 是否已落地：✅
- 落地版本：０.９.９９９
```

```
知识库文档        182 篇
CHANGELOG 版本    347 个（最新 0.9.217）
✅ 声明            181 条
没写落地状态的     0 篇
---
PASS 所有 ✅ 的版本都能在 CHANGELOG 找到对应发布
INFO 这些 ✅ 的 CHANGELOG 用词与 KB 的标识符对不上（仅提示，可能是正常表述差异）：
提到的文件路径    67 个
PASS KB 提到的每个文件路径都真实存在
EXIT=0
```

注意 `✅ 声明 181 条` 一条都没多 —— 新写的两条声明**根本没被算进去**。

**为什么没发现**：提取正则 `/✅[^\n]*?(\d+\.\d+\.\d+)/g` 里的 `[^\n]*?` **明确排除换行**，所以「✅ 在第 1 行、版本号在第 2 行」这种写法一个 claim 都不产生。而「是否已落地：✅」又满足了 `statesStatus`（`text.includes('是否已落地')`），连 WARN 都不会有。等于说：**KB 作者只要把版本号另起一行，这条门禁就彻底失效**。

对照（有效）：同一段里把版本号写回 ✅ 同一行（`✅ ０.９.９９９`）就会红：

```
FAIL 这些 ✅ 宣称的版本在 CHANGELOG 里找不到：
  ０.９.９９９  ← docs/kb/audit-kb-claims.md
EXIT=1
```

**建议怎么补**：
- 先把文档按 `## ` 切成段落，段落里出现 `✅` 就取**该段**第一个 `\d+\.\d+\.\d+`；
- 或者退一步：`/✅[\s\S]{0,120}?(\d+\.\d+\.\d+)/g`（允许跨行，但限窗）。

### FN-7 `scripts/audit-line-length.mjs` —— 空输出 = 通过

**它检查什么**：跑 `scripts/first-run.mjs`，把输出按字符数（`[...text].length`，不是 `awk length` 的字节数）检查单行 ≤ 120。

**破坏了什么**：把 `scripts/first-run.mjs` 的 `console.log(rendered)` 改成 `if (false) console.log(rendered)` —— 整个「客户会读到的唤醒消息」一行都不输出。

```
--- first-run 实际输出行数 ---
0
--- 运行 node scripts/audit-line-length.mjs ---
检查 1 行（按字符数）
最长一行 0 字符：
上限 120 字符
---
PASS 所有行都在 120 字符以内
EXIT=0
```

**为什么没发现**：没有任何「输出至少该有 N 行」的下限。`''.split('\n')` 得到 `['']`，最长行 0 字符，`0 > 120` 为假 → PASS。渲染整体坏掉（文案为空、`formatWatchText` 抛错被吞、`say()` 全被注释掉）时，这条门禁给的结论是「所有行都在 120 字符以内」。

**建议怎么补**：
- 加下限：`if (lines.length < 20) { console.log('FAIL 渲染输出只有 ' + lines.length + ' 行，first-run 坏了'); process.exitCode = 1 }`；
- 或断言关键小节存在：`if (!out.includes('===== 3. 唤醒消息')) FAIL`。

### FN-8 `scripts/audit-pack.mjs` —— `REQUIRED` 漏了 `CHANGELOG.md`

**它检查什么**：`npm pack --dry-run` 的产物里 ① 必需文件齐全（`REQUIRED` 11 项）；② 不许泄漏 `test/`、`.tmp-`、`preview-panel.html`、`release/`、`node_modules/`、`*.tgz`。

<     "LICENSE",

### FN-14 `scripts/audit-exit-codes.mjs` —— 被 `audit-glossary.mjs` 绕过（覆盖盲区）

**它检查什么**：`scripts/*.mjs` 里凡是**打印了 `FAIL`** 的，必须同时设置非 0 退出码。

**破坏了什么**：这条不是「改坏某个文件」，而是一个**结构性盲区**：`audit-glossary.mjs` 既没有 `process.exitCode`，也**不含字符串 `FAIL`**。两个判据同时为空 → 它永远不会被列进 `bad`。

```
--- audit-glossary.mjs 里有 process.exitCode 吗 ---
0
--- 里面出现 'FAIL' 吗 ---
0
--- 运行 audit-exit-codes ---
PASS 退出码一致  打印 FAIL 的脚本都会返回非 0
EXIT=0
```

对照（有效）：同样「打印了问题却 exit 0」，只要用 `console.log('FAIL ...')` 写就会被抓到（`FAIL 这些脚本打印了 FAIL 却不返回失败： scripts/…silent-fail2.mjs` → EXIT=1）。

**为什么没发现**：判据是 `printsFail = /console\.(log|error)\(\s*['"`]FAIL/ || /['"`]FAIL /`。一个脚本只要不按这门「标准话术」输出失败（`audit-glossary.mjs` 输出的是「面板在用但术语表没解释」），它连被检查的资格都没有。于是「退出码一致性」这条元门禁，恰好放过了唯一一个真正永远 exit 0 的脚本。

**建议怎么补**：改成**白名单制** —— 所有 `scripts/audit-*.mjs` 必须显式声明 `process.exitCode`（静态 grep 得到）或文件头写 `// @gate-skip: <理由>`，两者都没有就报。这样新增检查脚本时，「忘了设退出码」在写完那一刻就红。
