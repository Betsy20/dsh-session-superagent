# 第一次被叫醒：照着走一遍

> 这是一份**教程**（跟着做），不是参考手册。每一步都写了「你应该看到什么」和「没看到时看哪里」。
> 参考手册在 [README](../README.md)，设计取舍在 [docs/kb](kb/README.md)。

总时长约 10 分钟，其中等待可能要 1–2 分钟。

---

## 第 1 步：确认插件真的挂上了

在主理鱼面板切到「设置 → 来源」，看两行：

| 应显示 | 没显示时 |
|---|---|
| `gh CLI`：`可用 · gh version 2.x` | gh 没装或没登录：`gh auth login` |
| `权限范围`：一串 scope 或「细粒度 token」 | 显示「正在探测…」超过 10 秒：点「刷新」；仍不行看「诊断」 |

> 为什么先看这个：后面所有失败里，最常见的就是"gh 没登录"。

---

## 第 2 步：加一条守

「触发」页：

1. 仓库填 `owner/name`（**别填网址**）；
2. 间隔先用 **300 秒**（第一次试，别把 API 打满）；
3. 勾上 **仅观察**（这一轮只记录"本会唤醒哪几条"，不会真的打扰你）。

点「添加到当前会话」。

| 应看到 | 说明 |
|---|---|
| 顶部提示「已添加，首轮立即开始轮询」 | 正常 |
| 提示「已添加，但注意：仓库 x/y 不存在…」 | 名字错了 —— 我们会在 404 后搜一次，给出「是不是想填 …」 |
| 提示里出现「只有读权限」 | 能看不能回写；要么换 token，要么把结论写在本地 |
| 提示里出现「已归档 / 关闭了 Issues / fork」 | 这条守注定收不到条目，换一个仓库 |

---

## 第 3 步：看它在轮询

回到「总览」。行内应出现：

- 会话标题与编号；
- 「每 300s · 轮询 刚刚 · 唤醒 —」；
- 如果这条仓库你只读，会有 `只读` 徽章；fork 会有 `fork · 上游 …` 徽章。

等 1–2 分钟，「轮询」那栏会变成 `X 分钟前`。

> 如果一直是「刚刚」不动，说明定时器没跑起来 —— 去「诊断」复制信息发出来。

---

## 第 4 步：制造一次"新动态"

两种办法，任选：

- **A（安全）**：在仓库里给一条 issue 加个评论；
- **B（最真）**：让同事/自己开一条新 issue。

因为有「仅观察」，此时**不会**唤醒你的会话，但会记录一条判定结果。

---

## 第 5 步：确认它被判定到了

切到「判定」页，应该看到：

```
【判定日志】
repo · 刚刚
仅观察（未唤醒）
#123 你的标题 · 会话标题 · session-xxxx
```

顶部还有一行 **跳过原因累计**（例如 `不在标签白名单: ai-fix × 0` 之类）。
点任意一个原因标签，就只看该类条目；再点取消。

| 没看到条目 | 可能原因 |
|---|---|
| 「跳过原因累计」里有数 | 被过滤器刷了 —— 点开看具体原因（标签白名单、机器人、草稿、已关闭） |
| 什么都没有 | 仓库确实没动静，或轮询间隔还没到 |

---

## 第 6 步：关掉仅观察，真的叫醒一次

回到「触发」→ 点行标题展开设置 → 取消「仅观察」→ 保存。
再制造一次动静（第 4 步）。

**这次会真的唤醒本会话**。你应该收到一条消息，长这样：

```
【主理鱼】owner/repo 有 1 条新动态：
#123 [open] 标题 — @作者 (issue) 标签: ai-fix 状态: open … 未认领
【为什么是这几条】本轮共 1 条变化；按「最近更新」取前 5 条
【完成标准】
1. 改了什么：…
2. 怎么验证的：…
3. 回写到哪：…
```

| 消息里出现什么 | 含义 |
|---|---|
| `最后评论: @某人` | 有人在说话 |
| `最后评论: 我（上一轮留的）` | 那是我们上次留的，**不代表有人在处理** |
| `已有 PR #20（进行中·草稿·有冲突·等 review·CI 失败）` | 已经有人在写，先看一眼再决定要不要接管 |
| `⚠ 这条被重新打开过` | 之前判"不做"被推翻了 |
| `躺了 62 天` | 积压 |
| `【权限提示】只有读权限` | 只能看，回写会 403 |

---

## 第 7 步：处理完，打上"已处理"

让会话（或你自己）对待办调 `watch_ack`，例如：

```
watch_ack({ repo: "owner/repo", numbers: "123" })
```

之后这一条会在 GitHub 上带 `主理鱼:已处理` 标签，**轮询直接跳过**。
这是幂等的关键：换机器、删状态文件都不会重报。

---

## 出问题时怎么报障

「设置 → 诊断 → 复制诊断信息」，把复制到的文本贴给对方。里面已经脱敏，含：
插件版本、宿主版本、挂载状态、每一条守的最近错误。

---

## 一页速查

| 现象 | 先看哪里 |
|---|---|
| 面板空白 / 工具不见了 | 重启宿主（服务端改动要重启才生效） |
| 一直没被叫醒 | 「判定」页的跳过原因累计 → 再看「总览」的「需要关注」 |
| 报错里有 EOF / 超时 | 客户网络问题；≥0.8.36 会显示成人话 |
| 想换只读仓库也能回写 | 换有写权限的 token，或把结论写在 PR 描述里 |
