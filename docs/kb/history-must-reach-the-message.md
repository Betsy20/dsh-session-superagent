# 记下来的历史，得进消息才算数

## 出处
- 这是"收集了数据但没闭环"的典型：可观测性里叫 **high-cardinality data without a consumer**
  ——数据在，但没有任何决策/输出用到它（参考 SRE 书里对"useful signals"的讨论：
  <https://sre.google/sre-book/monitoring-distributed-systems/>）。

## 现场
`entry.history` 一直记着"哪次叫醒处理了哪几条"，但**唤醒消息里完全没用**。
后果：同一个问题第二次被叫醒时，会话以为这是新问题，从头分析一遍 —— 白花上下文。

## 改法
发消息前把 `history` 压成 `{条目号: 最近一次叫醒时间}`，条目行尾追加：
```
#7 [open] 登录坏了 — @u (issue) https://x/7 未认领 ⏰ 之前叫醒过（2026-10-30）
```
只标日期，不占版面（单行仍 ≤ 120）。

## 判据
**每份记录都要有一个消费者。** 加字段时问：谁会读它？如果答案是"以后可能有用"，
那它现在就不该被存（或者至少要写进"未落地"清单）。

## 是否已落地
✅ 0.9.90。用例覆盖"标 / 不标 / 不传则不变"三种情况。

## 还没做的
- 「之前叫醒过但没处理」和「之前处理过、现在又坏了」现在看起来一样；
- 面板上看不到这个标记（只有消息里有）。
