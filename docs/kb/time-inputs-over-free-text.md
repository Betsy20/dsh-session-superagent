# 时间让用户选，别让他记格式

## 出处
MDN 对 `<input type="time">`：

> The value is always a 24-hour `HH:mm` (or `HH:mm:ss`) formatted time, **with leading zeros**,
> regardless of the UI's input format.

<https://developer.mozilla.org/en-US/docs/Web/HTML/Element/input/time>

## 现场
活跃时段原来是一个文本框，placeholder 写 `09:00-23:00，留空 = 全天`。客户要自己记住：

- 冒号、连字符、两位数；
- 打错（`9:00-23:00`、`09:00~23:00`、`9-23`）会**静默失效** —— 解析不了就当没设，
  于是"守明明配了时段却 24 小时都在唤醒"，而界面上没有任何提示。

## 改法
`HoursField`：两个原生 `<input type="time">` + 「→」+ 跨夜提示 + 「全天」按钮。

| 细节 | 为什么 |
|---|---|
| 原生控件 | 格式由浏览器保证，`HH:mm` 永远前导零 |
| 中止 <= 起始 显示「跨夜窗口」 | 22:00-06:00 是合法的，但要让人知道自己选的是跨夜 |
| 「全天」按钮 | 空值语义是"全天"，用一个按钮表达，比叫用户删空更明确 |
| 两个 `aria-label` | 屏幕阅读器分得清"起始/结束" |

回写仍是 `HH:mm-HH:mm`，服务端解析器一行没改。

## 判据
**凡是"有格式要求"的输入，先问浏览器能不能替你校验。**
日期、时间、颜色、数字区间都有原生控件；用文本框就是在把格式记忆的负担转给客户，
而客户打错时的表现通常是**静默失效**——最难查的一类。
