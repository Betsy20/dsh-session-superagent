# 时间线行：两行封顶，时间右对齐

## 出处
- 与 [弹层是摘要屏](popover-is-a-summary-screen.md) 同族：都是"信息该分几层"。
- 关于表格/列表里数字对齐（`font-variant-numeric: tabular-nums`）：
  <https://developer.mozilla.org/en-US/docs/Web/CSS/font-variant-numeric>

## 现场
判定页每条事件原来是三行：

```
MYCF711/dsh-session-superagent            10 分钟前
仅观察（未唤醒）
#11  README 收尾与发布 · s1
```

问题：**扫一眼看不出发生了什么**。而这一页恰恰是客户最常翻的（"为什么这轮没叫醒我"）。
第三行还重复了上方列表里已有的会话名与后缀。

## 改法
两行封顶：

```
MYCF711/dsh-session-superagent            10 分钟前
仅观察（未唤醒） · #11
```

- 第一行：主体（强）+ 时间（`margin-left: auto` 右对齐 + `tabular-nums`）；
- 第二行：结果 + `· #编号`；
- 会话信息不重复。

## 判据
**时间线的一行应该回答"谁、什么时候"，第二行回答"发生了什么"。**
超过两行，读者就要在行间做拼接 —— 而拼接是阅读成本的来源。

## 顺带
「追溯一条」的说明原本说了两遍（Section 的 hint 一句 + 下面又一句 Hint）—— 删重复那句，
把两句意思合并成一行。**同一屏里同一句话说两遍，读者会怀疑哪里不一样。**

## 后续（0.9.145）：按天分组
20 条事件平铺时，读者分不清哪条是刚才、哪条是两天前 —— 只有「26 小时前」这种相对时间，越往下越难换算。

改法：
1. 跨守合并后**按时间倒序**（此前逐守拼接，顺序并不是全局的）；
2. 按本地日期插入分组标题：`今天` / `昨天` / `M 月 D 日`；
3. 分组标题 12px caption 色，不抢事件注意力。

> 经验：**相对时间必须配绝对分界。** "3 小时前"在列表顶部够用，翻到第 10 条就失效了。

## 后续（0.9.146）：两个时间序列挨着放会互相削弱

判定页下面有两个都是时间序列的区块：

- 「判定日志（最近 5 次唤醒）」—— 每轮**判定结果**；
- 「时间线（最近 20 条）」—— 每次**轮询做了什么**（唤醒/攒着/限流/回收）。

名字相近、位置相邻，客户分不清该看哪个。

改法：第二个改名 **「运行时事件（最近 20 条）」**，并加一句 hint 说明两者差别：
`每次轮询做了什么：唤醒、攒着、限流、回收。上面那条只记判定结果。`

> 判据：**同一屏里两个同构区块，名字必须能一句话说清区别。**
> "时间线"和"判定日志"都是时间序列，等于没命名。

## 还没做的

- 分组标题的 sticky 在真机滚动时未肉眼验证（预览是静态截图）。
