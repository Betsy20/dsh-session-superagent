# 一排数字必须"加起来等于总数"，否则它们在骗人

## 出处
- 统计口径的基本原则：分类必须**互斥且穷尽**（MECE）。不满足时，数字看着对、实际错：
  <https://en.wikipedia.org/wiki/MECE_principle>

## 现场
面板顶部：`条主理鱼 / 主理中 / 已暂停 / 异常`。原来的算法各数各的：
```js
running = 状态==active 的条数
broken  = 状态==error  的条数
paused  = enabled===false 的条数      // ← 与前两项不互斥
```
于是：
- 一条**已暂停又有错误**的守 → 「已暂停」「异常」各数一次；
- 「**时段外**」根本不进任何一项。

5 条守（正常/暂停/出错/时段外/暂停且出错）：四项加出来是 5 —— **看起来对得上，其实是巧合**
（多算一条、少算一条刚好抵消）。

## 改法
四项都由同一个 `orbitStateOf()` 产出，天然互斥：
```js
const byState = { active: 0, paused: 0, error: 0, dormant: 0 }
for (const w of watchers) byState[orbitStateOf(w)] += 1
```

## 判据
**任何一组"分项数字"，都要有一条断言：sum === total。**
这条断言能同时抓住"重复计数"和"漏掉一类"。

## 是否已落地
✅ 0.9.104。用例：五种状态 → 分项之和 = 总数；把 dormant 写死为 0 会让它红。

## 还没做的
- 只有总览顶部那一组做了断言；面板其它统计（如"X 条守（启用 Y）"）没做同样检查；
- 计数口径没有写进术语表（客户不知道"时段外"算不算在跑）。
