# 统计数字本身就是筛选入口

## 出处
- 官方 rows 的做法：统计/计数是**可点**的入口，不是装饰。
- 与 [官方「统计」只用两种写法](official-stats-pattern.md) 配套：那条讲"长什么样"，这条讲"能干什么"。

## 现场
统计条一直是纯展示：

```
3 条主理鱼   1 主理中   1 已暂停   1 异常
```

客户看到「1 异常」，还得自己去列表里找是哪一条。

## 改法
- `Stat` 支持 `onClick`：有回调渲染成 `<button aria-pressed>`，没有仍是 `<span>`；
- 点「异常」只看异常，再点取消；「条主理鱼」= 全部；
- 状态筛选 `stateFilter` 放进 useState **末尾**（打乱已有下标会让测试桩与预览快照同时错位）。

## 两个坑（都靠出图发现）
1. `h('button', {…}, kids)` 把**数组**当一个子节点传 → 数字整段不渲染；要 `kids[0], kids[1]`；
2. 原生按钮默认样式把统计条变成一排灰盒子 → 必须 `border:0; background:none; padding` 归零，
   再用 `interactive-bg-hover` 做悬停/按下提示。

> 判据：**"这行数字看起来是静态的"是设计缺陷，不是事实。**
> 只要有"按某个维度分组"的计数，点击就该能筛到那一组。

## 是否已落地
✅ 0.9.157。新增 1 例：`stateFilter='error'` 时只剩异常那条且统计显示按下态。

- 弹层里的 `1 / 3 主理中` 还不可点（跨会话汇总，点了要开面板才合理）。
