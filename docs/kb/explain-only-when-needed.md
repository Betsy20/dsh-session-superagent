# 解释只在"需要解释"的时候出现

## 出处
- 信息设计的常识：**解释是成本，不是礼貌**。只有读者可能产生疑问时才需要解释，
  否则它就是噪音（NN/g 关于 progressive disclosure 与最小必要信息的讨论：
  <https://www.nngroup.com/articles/progressive-disclosure/>）。

## 现场
唤醒消息里有一段：
```
【为什么是这几条】本轮共 1 条变化；按「最近更新」取前 5 条
```
**只有一条变化时，这段解释是纯噪音** —— 本来就只有它，"取前 5 条"无从谈起。

## 改法
```js
const onlyOne = list.length <= 1 && changedTotal <= 1
if (!onlyOne) { …解释排序与总数… }
// 跳过信息不受影响：它不是排序解释，而是"我还看过别的"
```

## 边界（想清楚才改）
- 单条但**有跳过**时，仍要报「本轮跳过 2 条」—— 否则客户会以为我们没检查别的；
- 多条时解释必须保留，且要带总数（0.9.52 的教训：只报原因不报总数会误导）。

## 是否已落地
✅ 0.9.76。用例覆盖三种形态（单条 / 多条 / 单条+跳过）。

## 还没做的
- 消息里其它"固定说明"（如 ack 用法提示）是否也该按需出现，没有系统梳理。
