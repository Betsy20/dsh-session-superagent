# 视觉巡检清单：把"看一眼"变成有覆盖率的动作

## 出处
- 本仓库 0.9.134 起的技术手段：`scripts/render-preview.mjs`（真实 `client.js` 渲染 + 移植 CSS + 无头浏览器出图）。
- 与 [没有数据的截图会骗人](screenshots-without-data-lie.md)、[窄屏不是「缩小的宽屏」](narrow-screens-need-rhythm.md) 配套。

## 清单（每轮至少跑一遍，缺项要写"没验"）
| 维度 | 命令 | 覆盖 |
|---|---|---|
| 深色 1000px | `--only=<tab>` | 四个 tab 主布局 |
| 浅色 1000px | 同上（不带 `--dark`） | 对比度、卡片底色、分隔线 |
| 深色 600px | `--only=<tab> --dark --mobile` | 窄屏换行 |
| 浅色 600px | `--only=<tab> --mobile` | 窄屏 + 浅色（最容易漏的组合） |
| 弹层深色/浅色 | `--popover [--dark]` | 圆角、底色、比例条、行截断 |
| 空态 / 错误态 | `--only=读取失败` | 错误卡片 + 重试 |

## 这一轮（0.9.151）的结果
四个 tab × 浅色 × 600px 全部出图，**没有发现需要改的地方** ——
这是连续多轮里第一次"看了一圈但没找到缺陷"，说明前几轮的修改把这类问题收敛了。

## 判据
**"没发现问题"要能说得出来：哪几个格子看过了。**
说得出覆盖矩阵，才能区分"真的没问题"和"根本没看"。

## 顺带修掉一个会骗人的工具缺陷
`--measure` 之前 `querySelector('.dt-ticket-body')` 匹配到**最后一条**守，
量"改后行高"时数字其实是另一条守的高度。现在固定取第一条，并输出每个子块的高度 + 文本前缀。

> 工具默认值错了，比没工具更危险 —— 它会给你一个看起来很可信的错数字。

## 是否已落地
✅ 0.9.151。四个 tab × 浅色 × 600px 全部出图；`--measure` 取值修正。

## 后续（0.9.162）：预览要模拟"浮在内容之上"
预览一直是"孤零零一张卡片"，而真机里弹层**浮在聊天内容之上**。差别会导致两个误判：

1. 行底色（`bg-layer-2`）在纯色背景上看不出来 —— 有没有底色都一样；
2. 重叠感、边框清晰度在纯色背景上偏乐观。

改法（只动工装）：弹层容器加一层半透明内容层 + 一句说明；弹层行显式给 `bg-layer-2` 与行间分隔线，
让"透字"这类问题在预览里也能复现。

> 判据：**预览的背景要跟真机一样"脏"。** 纯色背景上的卡片永远比实际更好看。
