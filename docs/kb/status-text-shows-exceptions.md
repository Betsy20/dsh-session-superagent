# 状态文本：默认只写"是什么"，异常才写"为什么"

## 出处
- 与 dashboard 设计里的**"例外优先"**一致：正常运行的东西不该占版面，
  需要人注意的才是信息（Google SRE 书里对"哪些信号值得报警"的讨论：
  <https://sre.google/sre-book/monitoring-distributed-systems/>）。

## 现场
`watch_status` 原来每条守固定 8 个字段：
```
o/ok → s1 | every 60s | lastPoll=2026-11-02T… | lastWake=- | err=-
```
十条守 = 十行长日志，而 90% 的字段是 `-` 或 `null`。

## 改法
- 基础只写"是什么"：`o/ok → s1 | 每 60s`（正常 < 60 字符）；
- 需要注意时才追加：`暂停：cap-session` / `叫醒 3 次没回音` / `已 35 分钟没轮询` / `还没轮询过`；
- 固定字段（`lastPoll=` 等）从**文本**里退出，**JSON 里保留** —— 机器读的契约不变。

## 判据
- 文本给"人/agent 扫一眼"，JSON 给"程序解析"；两者的信息量可以不同，但**语义必须一致**；
- 一条守一行仍是底线：行数 = 守数，便于 diff 与心跳检查。

## 是否已落地
✅ 0.9.86。用例：正常行 < 60 字符且无暂停、异常行带原因、行数 = 守数。

## 还没做的

- 没有统计"正常行平均长度"作为指标。
