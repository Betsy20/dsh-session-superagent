# 同一套规则，两个读者：别让面板和消息各说一套

## 出处
- 这是"同一事实的单一口径"问题：面向不同受众的文案可以不同，
  但**规则本身**必须一致，否则用户会以为是两套机制
  （信息架构里的常见原则；NN/g 也把"术语与流程一致"列为可用性基础）。
  
- 我们的场景更具体：唤醒消息给**会话（agent）**看，面板给**人**看。

## 比对结果（本轮实测）
| 位置 | 说了什么 |
|---|---|
| 唤醒消息 | `接下来 1/2/3`：读 AGENTS.md → 修/回/待定 → 写回 + `watch_ack` |
| 面板（原来） | "守会在仓库出现新条目时叫醒这个会话。想先试一次点「立刻」；没动静看「需要关注」" |

**面板完全没说"叫醒之后会发生什么"** —— 客户只知道会被叫醒，不知道接下来三步是什么，
更不知道"不做也要 ack"这条（而这正是 0.9.11「叫醒了没回音」要治的病）。

## 改法
在面板的空态提示后补一句同一套规则（措辞按人的视角，规则不变）：
> 叫醒之后：会话先读仓库 AGENTS.md → 决定「修 / 回 / 待定」→ 做完写回并 `watch_ack` 打标签；
> 不做也要说明理由并 ack。

用例锁死三件事都在面板出现：`AGENTS.md`、`修 / 回 / 待定`、`watch_ack`。

## 为什么不是"把消息原文复制到面板"
消息是**任务书**（给 agent 的执行指令，含完成标准编号），面板是**解释**
（给人看的"会发生什么"）。内容对齐、语气不同 —— 一致的是规则，不是措辞。

## 是否已落地
✅ 0.9.39。面板空态提示补一句 + 一致性用例。

## 还没做的
- 面板其它位置（如「需要关注」里的各类提示）还没有逐条核对与消息的一致性；
- 没有把"两处文案"放进同一个快照做并排 diff（现在各有各的用例）。
