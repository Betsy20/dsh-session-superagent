# 引导里写的控件名，必须是页面上真的存在的那一个

## 出处
- 新手引导（onboarding）最常见的失效方式不是写错，而是**改名后忘了同步**：
  文案里还写着「点『添加到当前会话』」，按钮已经叫「加入盯办」。
  这是"引用型文案"的通病（与 [文档里的标识符会漂移](identifier-drift.md) 同源）。

## 现场
空态三步：
```
① 填一个仓库（owner/name）
② 选间隔（默认 60 秒）
③ 点「添加到当前会话」——之后仓库有动静，这个会话就会被叫醒
```
③ 里的名字是**引用**，不是描述。

## 做法
用例从引导文本抽出所有「…」里的名字，逐个要求它们在**「触发」页真实出现**：

```js
const quoted = [...overview.matchAll(/「([^」]{2,12})」/g)].map((m) => m[1])
for (const name of quoted) assert.ok(trigger.includes(name), '引导提到的「' + name + '」在「触发」页找不到')
```

## 两次假通过（判据问题）
1. 第一版写 `trigger.includes(name) || overview.includes(name)` —— 引导文本自己就含这个词，
   `overview` 永远为真 → **注入改名后仍 PASS**；
2. 收紧成只查「触发」页仍 PASS，因为测试桩没传 `sessionId`，按钮渲染成「先打开一个会话」。
   给渲染桩加 `props`、测试传 `{ sessionId: 's1' }` 之后，注入改名才**立刻变红**。

## 判据
- 引用型文案的检查，必须**在被引用的那个页面**里找；
- 渲染桩要能传 props，否则"有会话/无会话"两种文案只测到一种。

## 是否已落地
✅ 0.9.83。用例注入改名后失败、还原后通过（两次验证）。

## 还没做的
- 只覆盖被测的那一页；其它 tab 里的「…」引用还没系统性检查；
- 引用**图标**或**按钮样式**的稳定性没法用文案查。
