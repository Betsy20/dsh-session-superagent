# 「多久会叫醒我」要拆成五段，不能给一个数

## 出处
- 这是"延迟可解释性"的应用：把端到端时间拆成**可归因的组成**，
  用户才能判断"该调哪一头"。分布式系统里对 P99 归因分析用的就是这套思路
  （tail latency 分解，见 <https://research.google/pubs/the-tail-at-scale/>）。
- 对我们这里，五段分别是：轮询间隔 / 抖动 / 活跃时段 / 冷却期 / 每小时上限。

## 做了什么
`scripts/explain-latency.mjs`，用 `lib/watch.js` 的真实函数算出每段耗时并打印成表：

```
步骤                        本段耗时      累计        说明
① 提交                        0 秒           0 秒         客户动作，t = 0
② 下一次轮询看到它                  1 分 2 秒       1 分 2 秒     最多一个轮询周期（1 分 0 秒）+ 抖动 1794 毫秒
③ 冷却期门禁                     0 秒           1 分 2 秒     只吸收「自己刚碰过的条目」
④ 活跃时段门禁                    0 秒           1 分 2 秒     当前在 09:00-23:00 内，直接通过
⑤ 频率上限排队                    30 分 0 秒      31 分 2 秒    假设这一小时已用完 6 次
```

结论两句话：
- **最常见**：只有 ①②，约「一个轮询间隔 + 抖动」；
- **最坏**：五段叠加，可能到半小时级。

## 为什么这个脚本比文档更有用
1. 数字来自真实函数，不是手写示例 —— 改了默认值，输出会自动跟着变；
2. 它顺手纠正过我的理解：第 ② 段我一开始只写了"抖动 2 秒"，
   忘了**提交时刻相对下一次轮询是随机的**（最坏要等满一个周期）。跑出来一眼就发现"最常见 1 分 2 秒"和表里对不上。
3. 它明确区分了两件事：**唤醒延迟** vs **失败重试间隔（退避）** —— 后者指数增长到 16 分钟，客户最容易混淆。
