# 样式表要在"用到它的组件"里注入

## 出处
- 真机复现（2026-11-03）：重启后点状态栏圆环，弹层变成**一堆叠在一起的裸文字**。
- 与 [没有数据的截图会骗人](screenshots-without-data-lie.md) 相对：那条讲"预览骗人"，这条讲**预览太好了，掩盖了真机的缺失**。

## 现场
`PORTED_CSS + DOCK_CSS` 挂在同一张 `<style id="dsh-zhuli-ported-css">` 里，
而注入函数只在**「主理鱼」面板组件挂载时**调用：

```js
// 面板里：有
useEffect(() => { ensurePortedCss() }, [])
// StatusOrbit（状态栏圆环）里：没有
```

所以只要客户**没打开过面板**、直接点圆环，弹层就没有任何样式。

**为什么预览和单测都没抓到**：`render-preview.mjs` 自己会拼 CSS 进 HTML；
测试桩根本不做样式计算。两者都绕过了"谁负责注入"这一层。

## 改法
- 圆环组件挂载时也调一次（函数本身幂等，`getElementById` 已去重）；
- 补一条**静态断言**：`StatusOrbit` 源码里必须出现 `ensurePortedCss`。

## 判据
1. **样式表要跟着"用到它的组件"走，而不是跟着"最先想到它的组件"走。**
   共享样式表 + 单一注入点 = 只要那个组件没挂载，其他组件的样式全丢；
2. **预览越好，越要问"真机谁负责这一步"。**
   预览自己拼 CSS、测试桩不算样式 —— 这类"注入缺失"只能靠
   "把调用点写成断言"来防。

## 是否已落地
✅ 0.9.159。新增 1 例静态断言；`StatusOrbit` 挂载即注入。

## 后续（0.9.160）：把注入点提到模块入口
0.9.159 补的那次调用只是**第二个注入点** —— 下次再加一个槽位，同样的坑会再来一次。
把注入提到模块入口，一次搞定所有槽位：

```js
apply(ctx) {
  …
  try { ensurePortedCss() } catch {}
}
```

组件里的调用保留（幂等），作为宿主早期渲染顺序异常时的兜底。
静态断言现在有两道：**`apply()` 里必须调**、**`StatusOrbit` 里必须调**。

> 判据升级：**"补一次调用"是修症状；"把注入提到共同入口"才是修结构。**
> 每次发现"某个入口没调 X"，都要问一句：这个 X 是不是本该在更上层调一次。

## 还没做的
- 没有运行时自检（若 `<style>` 被宿主清掉，组件调用会重新注入，但只在渲染时才发生）；
- 新槽位的注册没有统一模板，仍然是"照着上一条抄"。
