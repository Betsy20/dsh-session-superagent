# 没有数据的截图会骗人

## 出处
- 与 [页面子块之间要有节奏](screens-need-vertical-rhythm.md) 同族：都在讲"怎么用出图核对界面"。
- 关于占位符参数的规范讨论（本轮未复核原文）：
  <https://www.nngroup.com/articles/error-message-guidelines/>

## 现场一：截图看着"空"，其实是快照缺字段
`--only=设置（诊断）` 出图，页面只有一个标题 + 一行提示，以下是当时的判断过程：

1. 先怀疑样式 —— 卡片只有 560px 宽、下面一大片空白；
2. 量了一下：`.dt-settings-body` 高度正常，**是里面真的没有内容**；
3. 回头查预览快照：`triageSignals` **根本没被写进快照**。

补上 5 条信号后，页面才是它本来的样子：

```
被重新打开  [事实] [默认开]  +100 分
state_reason=reopened
```

**教训：页面看着空，先确认"数据有没有喂给它"，再怀疑样式。**

## 现场二：客户能读到的「N」
| 位置 | 原文 |
|---|---|
| 优先级字段说明 | `优先级（一次只处理 N 条时先挑谁）` |
| 诊断页提示 | `一次只处理 N 条时，这些信号的加权决定先后。` |

「N」在**唤醒消息模板**里是合法占位（`有 N 条新动态` 本来就是给别人填的模板），
但在**固定说明文案**里就是没写完 —— 客户会以为漏了个设置项。

改法：`优先级（在「单次最多唤醒条数」内先挑谁）`、`一次只处理上限条数之内……`。

## 判据
1. **出图之前先喂全数据**（快照字段 = 页面用到的字段）；
2. **文案里的变量必须被填**：模板里可以有 `N`，说明文字里不行 —— 要么给数字，要么改成"上限条数"这种指代。

## 是否已落地
✅ 0.9.140。诊断页出图（含 5 条分诊信号）；两处 N 已改。

## 后续（0.9.141）：把它变成门禁
肉眼发现一次就够了，第二次要靠断言。新增 `test/preview-contract.test.mjs`：

1. **顶层**：`client.js` 里出现的每一个 `body.X`，快照里必须有同名键（当时 16 个，快照只有 6 个）；
2. **嵌套**：`isolation.roots[].{count,bytes}`、`isolation.totalBytes`、`sessionUsage.{used,cap,capped}`、
   `defaults.*`、`retryPolicy.*` 都必须在。

### 装门禁当天就抓到自己的错
我第一版快照写 `isolation.roots[].sizeBytes`，而服务端/客户端用的是 **`bytes` / `totalBytes`**，
出图显示「2 个 · **0 B**」。改正后：`2 个 · 256.0 KB（合计 256.0 KB）`。

**字段名错一位，界面就是一个错数字** —— 而且看起来"很正常"，不报错、不空态。
