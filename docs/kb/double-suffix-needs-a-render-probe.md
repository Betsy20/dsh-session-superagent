# 拼接出来的时间文案，要用真实数据渲染一次

## 出处
- 2026-11-04 真机：弹层副行显示 `76 秒前前 · 时段 09:00-23:00`。
- 与 [面板行也不能「一堵墙」](panel-row-density.md) 同族：都是"文案是拼出来的"引发的问题。

## 现场
```js
const ageText = (iso) => { … return s + ' 秒前' … }        // 已带「前」
parts.push(ageText(w.lastPoll) + '前')                     // 又加一次 → 秒前前
```

## 为什么预览和 264 个用例都没抓到
1. 预览快照的 `lastPoll` 是固定的 `iso(15000)`；
2. 所有断言都是 **"包含某段文字"**，没人逐字看过整段输出；
3. 这类错误**语法正确、逻辑半对**（时间是对的，只是多一个字）。

## 做法
用一个探针脚本，把**真实 `/state` 形状**的数据喂进渲染函数，打印出整段文本：

```js
const sub = nodes.filter((n) => n.props && n.props.className === 'sa-dock-sub')
                 .map((n) => (n.props.children || []).join(''))
console.log(JSON.stringify(sub))     // → ["… · 76 秒前前 · …"]
```

一眼就看到了。随后补一条回归用例：**副行不得出现「前前」**。

## 判据
1. **凡是"拼接"出来的用户可见文案，都要有一处把整段打印出来看一眼** ——
   "包含"式断言对重复词天然免疫；
2. **写函数时确认返回值形态**：`ageText` 返回的是"76 秒前"而不是"76 秒"。
   命名里带不带单位，要在函数名或注释里说清。
