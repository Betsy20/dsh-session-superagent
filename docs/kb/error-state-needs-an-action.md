# 错误态要带动作，不能只是一行红字

## 出处
- 与 [失败要带着「下一步」回到调用方](failures-must-carry-next-step.md) 同族：
  那条讲的是**接口/skill 的返回**，这条讲的是**界面上**的错误态。
- NN/g《Error Messages》四要素（本轮未复核原文）：
  <https://www.nngroup.com/articles/error-message-guidelines/>

## 现场
面板拉自己接口失败时，原来只有一行：

```
读取失败：Failed to fetch
```

客户能做的只有一件事：**关掉面板再打开**，或者去重启宿主 —— 全是猜的。

## 改法
错误态改成卡片：

```
┌ 读不到面板数据 ────────────────────────┐
│ 连不上宿主：DSH 可能正在重启，或插件刚被重载。 │
│ 稍等几秒会自动重试……                    │
│ [ 重试 ]                                │
└────────────────────────────────────────┘
```

- 标题说**发生了什么**（读不到面板数据），红色；
- 正文说**为什么 + 会自动重试**（人话，经 `humanizeError`）；
- 按钮给**下一步**（重试）。

## 判据
**错误态 = 现象 + 原因 + 动作，三样缺一不可。**
只有现象（"Failed to fetch"）是甩锅；只有原因（"宿主重启中"）是看戏；
有按钮才是把控制权还给客户。

## 顺带两处（同一轮出图发现）
1. 触发器表单满屏 900px，短数字输入框显得空 → `max-width: 480px`；
2. 弹层只能 Escape 关闭、**焦点进不去也回不来** → 打开时 `panel.focus()`（`tabIndex=-1`），
   关闭时焦点还给圆环按钮，与官方 Modal 的键盘行为对齐。

## 是否已落地
✅ 0.9.139。新增 1 例（弹层 `tabIndex=-1` + `aria-label`）；出图核对错误卡片与表单宽度。
