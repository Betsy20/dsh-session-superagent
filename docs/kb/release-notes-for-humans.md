# 四十个版本的 CHANGELOG ≠ 客户能读的东西

## 出处
- Keep a Changelog（我们一直遵循的格式）：<https://keepachangelog.com/en/1.1.0/>
  它的第一条原则就是 **"Changelogs are for humans, not machines."** ——
  但"人类"也分开发者与使用者，逐条罗列对使用者仍然不可读。

## 它怎么做的
按 **Added / Changed / Fixed / Removed** 分组，每个版本一段，面向"跟进这个项目的人"。

## 我们能怎么用
0.8.38 → 0.9 有四十多个版本。客户不会读四十段 CHANGELOG。
所以另写一页 `docs/whats-new-0.9.md`，规则是：

1. **只写"你会感觉到"的变化**（面板上看得见的、唤醒消息里出现的、省掉的问题）；
2. **每条都是"以前 → 现在"的对照**，不写内部实现名词；
3. 每条都能点进 `docs/kb/` 看背后的调研与取舍（想深入的人有路可走）；
4. 结尾必写**这次升级要注意什么**（我们的是"要重启宿主才生效"）——
   升级说明里漏掉这条，等于让用户以为装完就生效。

## 是否已落地
✅ 0.8.90（`docs/whats-new-0.9.md` + README 顶部入口）。

## 还没做的
- 没有为每个大版本都维护这样一页（现在是 0.9 专页）；
- 没有做"版本对照表"（哪个功能从哪版开始有）。
