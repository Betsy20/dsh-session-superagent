# 门禁也会"装死"：注入一次错误，看它到底红不红

## 出处
- 变异测试（mutation testing）的核心思想：**给代码注入缺陷，看测试能不能抓到**。
  抓不到的测试是"摆设"，抓不到的门禁也是。
  <https://en.wikipedia.org/wiki/Mutation_testing>
- 我们把它缩到门禁层面：每类检查挑一个安全可还原的注入点。

## 做法
`scripts/verify-gates.mjs`，四个注入（全部 try/finally 还原）：

| 注入 | 期望 |
|---|---|
| 把 README 的「N 项单测」改成 `9999 项单测` | `README 单测数` 变红 |
| 在 `docs/kb/` 临时写一条带已落地标记、但版本号是编的文档 | `知识库有据` 变红 |
| 在 `docs/` 临时写一个断链 | `文档链接` 变红 |
| 把面板文案里「全部暂停」改成「全部暂停（注入）」 | `面板文案快照` 变红 |

实测：
```
PASS README 单测数（注入错数字）
PASS 知识库有据（注入假版本号）
PASS 文档链接（注入断链）
PASS 面板文案快照（注入改字）
PASS 4/4 项注入都被检测到（门禁是活的）
```
约 10 秒，已接进 `preflight`（非 `--fast` 模式，第 25 项「门禁自检」）。

## 顺带修掉的另一个"假红"
`smoke:observe` 需要**真机宿主**（活的会话 + 已挂载插件 + gh 登录）。
在本机它一直红 9 项 —— 那不是产品问题，是**环境不满足**。
现在脚本自带宿主门禁：没有 `DSH_SMOKE_HOST=1` 就打印 `SKIP` 并退出 0，
preflight 认这个 `SKIP`。

> 假红和假绿一样有害：前者让人麻木，后者让人误以为安全。

## 是否已落地
✅ 0.9.65。`preflight` 25 项（`--fast` 时跳过「门禁自检」与冒烟）。

## 还没做的
- 只注入了 4 类检查（共 26 项），其余靠人工抽验；
- 注入点写死在脚本里，新增检查不会自动获得一个注入样例。

## 0.9.67 追加：覆盖率必须可见，否则等于没有
新增 3 个注入后（错误建议 / 全库文档一致 / 文案快照），`verify-gates` 结尾会打印：

```
注入覆盖：11/27 项检查有注入验证
未验证（不一定是问题，但要知道）：单测 node --test、临时目录收口、门禁自检、语法 node --check、…
```

`docs/验收清单.md` 也多了一列「注入验证」：`✅` = 有注入样例，`—` = 还没注入过（**不等于没检查**）。

**关键设计**：覆盖率不是"我想起来才看的数字"，而是每次跑 `preflight` 都会打印的一行。
没验过的项**主动列出来**，比一个漂亮的 100% 更诚实。

## 0.9.68 追加：变异测试当场抓到一条"疑似失明"的指标
给 `UI 体检` 加注入时，连续三种写法都没能改变「写死颜色」这个数字：

| 注入 | 期望 | 实际 |
|---|---|---|
| 在 JSX 里加 `style: { color: '#ff0000' }` | 数字 > 0 | **0** |
| 在自有样式块 `DOCK_CSS` 里加 `.x { color: #ff0000; }` | 数字 > 0 | **0** |
| 在文件第一行加 `// probe #ff0000` | 数字 > 0 | **0** |

而用**同一段表达式**在独立进程里算同一个文件，得到的是 **9**。
也就是说：`ui-audit.mjs` 打印的 0 与它自己的计算对不上 —— **指标疑似失明**。

我没有当场改掉它（改之前要先弄清原因），而是：
1. 把这条注入从覆盖清单里撤掉；
2. 在 `test/fixtures/gate-coverage.json` 里加 `suspect` 字段写明"注入后指标没动，需人工查"；
3. `verify-gates` 每次跑都会打印「疑似失明」清单，验收清单里显示 `⚠️`。

> **这次变异测试最大的产出不是覆盖率 +3，而是发现一条一直在骗人的指标。**
