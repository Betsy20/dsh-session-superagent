# 「在等」也是一种空态，别让它沉默

## 出处
- Nielsen Norman Group《Empty-State Interface Design》：
  <https://www.nngroup.com/articles/empty-state-interface-design/>
  要点：空态出现在"内容尚未存在"的场景里，**新手引导只是其中一种**；
  还有"内容被过滤掉""还没开始"等形态，各自需要不同的提示。

## 它怎么做的
把空态分类，而不是用一套"这里什么都没有"的占位图案糊过去。

## 我们能怎么用
我们的面板原来只有两种状态：
1. **一条守都没有** → 三步引导（0.8.48 补的）；
2. **有守** → 显示列表。

但真实使用里还有一种最常见的中间态：**已经有守，但一次都没被唤醒过**。
客户此时最想问的是"它到底在不在工作"。原来这里什么都没有 —— 一片安静，看起来像坏了。

改法：加一句明确的"在等"：
> 还没有唤醒过：守会在仓库出现新条目时叫醒这个会话。想先试一次，点行里的「立刻」；
> 如果一直没动静，看上面「需要关注」里有没有被过滤的记录。

三件事都指向**下一步动作**，而不是陈述状态。并且只在"全部守都没唤醒过"时出现 ——
一旦唤醒过就消失，不占版面。

## 是否已落地
✅ 0.8.89。用例：从未唤醒时必须出现「还没有唤醒过」+ 指向「立刻」；唤醒过之后不得再出现。

## 还没做的
- 没做"被过滤导致一直不唤醒"的专门引导（那是 `需要关注` 区在管，但可以更醒目）；
- 没做首次使用的时间提示（"已运行 3 分钟，尚未发现新条目"）。
