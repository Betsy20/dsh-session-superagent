# 对着全文做文案抽检：最长的那 10 条里有两处真问题

## 出处
- NN/g 的错误信息三原则：说清**发生了什么**、**为什么**、**下一步做什么**，
  并且**别让用户猜主语**（<https://www.nngroup.com/articles/error-message-guidelines/>）。
- 方法：从 `docs/面板文案.md`（0.9.56 生成的快照）里取最长的 10 条，
  每条问三件事：谁在说 / 需要我做什么 / 有没有更短更准的说法。


## 抓到两处
### ① 占位符没被填上（真 bug）
改之前第一条是：

> 你对 **这个仓库** 只有读权限：……

`accessNoteForPanel(access)` 只拿到权限对象、拿不到仓库名，于是 `access.repo` 为空时
退化成"这个仓库" —— 读起来像半成品。改成 `accessNoteForPanel(access, repo)`，
调用处传 `watcher.repo`，输出变成 `你对 acme/widgets 只有读权限：…`。
用例锁死：必须出现仓库名，且**不许出现**"你对 这个仓库"。

### ② 按钮已经在旁边，正文还在教一遍
> acme/widgets 已连续 2 次唤醒后没有回音（没看到 watch_ack）—— 检查这个仓库的 AGENTS.md 有没有给出处理规则

这一行的右侧本来就有「看建议规则」按钮 —— 正文再教一遍是重复，且 72 字偏长。
改成说清**后果**：`acme/widgets 连续 2 次被叫醒后没有回音（没看到 watch_ack）—— 会话可能没按规则处理`（55 字）。

## 判据（写死，下次照用）
1. **主语必须是具体的**（仓库名/会话名），不许出现"这个仓库""它"；
2. **旁边有按钮的，正文不再重复动作指引**，只说发生了什么、意味着什么；
3. 单条 ≤ 80 字符（超过就该拆或删）。
