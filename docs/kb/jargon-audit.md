# 面板上的行业词，客户不认识

## 出处
- 这是"curse of knowledge"的典型：写的人知道 `worktree`、`ack`、`回音` 指什么，客户不知道。
  NN/g 关于"说用户的语言"的老结论：
  <https://www.nngroup.com/articles/plain-language-experts/>

## 做法
从面板文案快照（`docs/面板文案.md`，129 行 / 104 条）里按词统计，看哪些"内部词"出现在了客户会读到的句子里：

```
ack × 1      acme/widgets 连续 2 次被叫醒后没有回音（没看到 watch_ack）
worktree × 1  隔离执行（每次唤醒开一次性 worktree；在副本里改，用完会自动回收）
回音 × 2      同上
上限 × 3      1 条守正因上限暂停
```

## 三处改动
| 原 | 现 | 为什么 |
|---|---|---|
| 隔离执行（…一次性 worktree…） | 隔离执行（…**一个临时副本**…） | `worktree` 是 git 术语，客户不需要知道实现 |
| 被叫醒后**没有回音** | 被叫醒后**没有动作**（没看到 `watch_ack` 标签） | "回音"是比喻；"没有动作"说的是可观察的事实 |
| 术语表缺「上限」 | 新增：两种上限（单守 6 / 会话 12）+ **和 GitHub 限流不是一回事** | "上限"在面板里指两种完全不同的东西，最容易误解 |

术语表同时补了「没有动作」「临时副本」两条，用例锁死这 5 个词必须在里面。

## 判据
1. 实现术语（worktree / cursor / deferReason）不进客户可见文案；
2. 比喻要在括号里给出**可观察的事实**（"没看到 watch_ack 标签"）；
3. 有歧义的词（上限）必须在术语表里一次说清两种含义。
