# 汇总行要么能点，要么就是装饰

## 出处
- 沿用上一篇的渐进披露（<https://www.nngroup.com/articles/progressive-disclosure/>）：
  概览层的作用是**导航**，不是"再显示一遍同样的信息"。
- 一个更朴素的判断：**如果一个元素看起来像可点的，它就必须可点**（否则用户会一直试点）。

## 问题
0.9.13 加了「按仓库」汇总，但仓库名是纯文本 —— 看起来像标题，点了没反应，
下面的明细还得自己去列表里找。

## 改法
仓库名改成按钮，点一下把 `search` 设成该仓库（再点取消），复用已有的搜索过滤：

- **零新增 state**（`search` 已在槽位里）—— 这点很重要，见下面；
- 类名用 `dt-textlink dt-row-name`，**不用 `dt-open`**：`dt-open` 是明细行的标题按钮，
  已有用例按"每行恰好 1 个 dt-open"断言，汇总行混用会让那条用例失去意义。

## 又一次踩到同一个坑
先给按钮用了 `dt-open`，结果「每行有编辑按钮」那条用例立刻红（2 !== 1）。
这类**共用类名导致语义混淆**的问题，用例能抓，但更该在设计时就想清楚：
`dt-open` 的语义是"展开这一行"，而"筛选列表"是另一件事。

## 是否已落地
✅ 0.9.14。用例：每个仓库一个可点名字（按 title 精确匹配），
搜索命中某仓库时明细只剩它。

## 还没做的
- 点汇总行不会自动滚动到明细区（现在要自己往下看）；
- 没有"只看有问题的那几个仓库"的快捷入口。
