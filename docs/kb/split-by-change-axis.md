# 拆分文件看「改动轴」，不看行数

## 出处
- 判断依据来自单一职责与"变化原因"的思路（GoF / Clean Architecture 里都强调：
  一个模块应当只有**一个变化的原因**）。
- 这次是**用脚本核对依赖**后才动手的，不是凭感觉拆。

## 怎么判断要不要拆
不看行数，看一个问题：**改一个功能，要不要同时读几块不相干的地方？**

实测 `lib/watch.js` 883 行、40 个导出，混着两类东西：
1. **调度与状态**：去重水位、抖动、退避、时段、合并写、水位推进；
2. **GitHub 交互与措辞**：错误归类、`Retry-After`、限流推迟、徽章、各类提示语、GraphQL 批量。

这两类的修改动机完全不同 ——
"唤醒消息多一行"不该让我读退避算法，"改退避曲线"也不该碰措辞。

## 怎么确认能安全拆
写了脚本统计两块之间的依赖：
```
tail 用到的 head 名字：（无）
head 用到的 tail 名字：assignmentNote, commentSummaryLine, linkedPrNote, stalenessNote, stateReasonNote
```
→ 尾部 422 行**对前半部分零依赖**，只被 `formatWatchText` 用到 5 个函数。
这种"单向、稀疏"的依赖才适合拆。

## 结果
| 文件 | 行数 | 职责 |
|---|---|---|
| `lib/watch.js` | 883 → **486** | 调度与状态 |
| `lib/gh-format.js` | **430**（新） | 解析 / 归类 / 措辞（不发请求、不碰状态） |

`watch.js` 转出 19 个名字，既有调用方（`index.js`、8 个测试文件）**一行都不用改**。

## 拆完必须同步的三处（漏了就出事）
1. `scripts/sync-profile.mjs` 的 `TARGETS`（否则新文件不进 profile → 插件整体挂不上，这个坑踩过）；
2. `scripts/preflight.mjs` 的语法检查文件列表；
3. `node scripts/contract.mjs --update`（形状没变，但跑一遍确认）。

## 是否已落地
✅ 0.8.95。测试 138 例全过、preflight 9 项全过（语法 6 个文件）。

## 还没做的
- `lib/index.js` 1795 行是下一个候选，但它按"工具/路由"天然分区，暂不动；
- 没有加"单文件行数上限"的门禁（怕逼出无意义的拆）。
