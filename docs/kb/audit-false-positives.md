# 审计器最怕的不是查不出，而是假警报

## 出处
- 静态分析工具的经典取舍：**误报（false positive）比漏报更伤信任** ——
  假警报一多，人就学会无视工具输出，门禁等于失效。
  （SonarQube / ESLint 的规则默认值讨论里反复出现这条：
  <https://eslint.org/docs/latest/use/configure/rules>）

## 本轮三次"我自己制造假警报"
| 我写的检查 | 假警报 | 真因 |
|---|---|---|
| 路由存在性 | `~/.dsh/state/session-superagent/watchers.json` 被当成路由 | 文件路径与路由长得一样，需要排除 `state/` 前缀与 `.json` 后缀 |
| 字段存在性 | `button` / `loading` / `glossary` 被判"lib 里没有" | 这些是**面板**的 React 概念，本来就不该在 `lib/` 里 —— 判据选错了层 |
| 文件路径存在性 | 官方仓库的 `client.js` 被判不存在 | 那份文档描述的是**外部仓库**的文件，不是我们的 |

三次都是在"检查器"这一侧出错，而不是被测对象。

## 最后的判据（留在脚本里）
- 路由：`(?<!state)\/session-superagent\/[a-z-]+(?![\w.])` —— 排除文件路径；
- 文件路径：**整份文档**若开头说明"描述的是外部仓库"，就跳过路径检查；
- 字段检查：**删掉**。它无法区分"面板组件名"与"服务端字段名"，
  假警报率太高 —— 宁可不要这条检查，也不让门禁变得不可信。

## 留下的四条硬检查
```
PASS 工具名都对得上
PASS 路由都对得上
PASS 版本号都对得上
PASS 文件路径都对得上
```
（17 份文档；不含 docs/kb 与 CHANGELOG —— 后者本来就该包含历史版本号。）

## 是否已落地
✅ 0.9.38。`preflight --fast` 对应检查：`PASS 全库文档一致　17 份文档的工具/路由/版本/路径都对得上`。

## 还没做的
- 没有检查文档里的**代码片段**能否运行（成本高，收益不明）；
- 版本号检查只报"高于当前版本"，不报"过旧"（过旧不一定是错，可能是历史记录）。

## 0.9.80 追加：想在"已落地"上加内容校验，但判据太松
想法很自然：KB 写着 ✅ 0.9.62，就该能证明**那条 CHANGELOG 真在讲这件事**。
做法：从 KB 里抽反引号标识符（`watch_doctor` / `format=json`），要求它也出现在那条 CHANGELOG 里。

实测：109 条 KB 里 **8 条**报"对不上"，逐条看全是正常差异 ——
CHANGELOG 写"兜底也要有下一步"，KB 写 `preflight`；CHANGELOG 写"文档分四种"，KB 写 `README.md`。

**结论：降级为 INFO，不进失败判定。** 数字照打（8/109），漂移可见，但不制造假警报。

> 判断一个检查该不该硬：如果**误报和真问题长得一样**，它就只能当提示。
