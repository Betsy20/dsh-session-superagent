# 同一个字段，在两个契约里就是两件事

## 出处
- API 设计里的"契约边界"：**同一个概念出现在两个接口里，它们的稳定性承诺是分开的**。
  OpenAPI 规范把每个 endpoint 的 response schema 单独定义，正是为了不让"内部字段"混进公开契约：
  <https://spec.openapis.org/oas/latest.html>

## 现场
给 `/state` 加 `otherSessions`（同仓库的其它会话）时，我顺手把它登记进了
`test/fixtures/contract-stability.json` 的 **`watch_status`** 条目 ——
结果稳定性用例立刻红：

```
结构化输出的每个字段都在稳定性清单里（新增字段必须登记）
```

因为那个清单管的是**工具输出**（`watch_status` 等 6 个工具的 JSON），
而 `otherSessions` 只存在于 `/state` 的 HTTP 响应里。**两个契约，不是一回事。**

## 教训
- 加字段前先问：这个字段走的是**工具**还是**HTTP**？（我们的对外契约有两套）
- 清单要按契约分开登记，否则"登记了"反而制造假红；
- 假红的价值：它逼我把边界想清楚，而不是让字段悄悄混进错误的契约。
