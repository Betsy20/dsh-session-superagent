# 文案长度门禁要分级：允许少数长句，但不许越来越多

## 出处
- 一刀切的行宽限制在真实文案里一定会误伤（有些话必须说全）。
  更实用的做法是**预算制**：给一个"允许的例外数量"，用超了才红。
  这与性能预算（performance budget）同一思路：<https://web.dev/articles/performance-budgets-101>

## 做法
`scripts/render-panel-copy.mjs --check` 除比对快照外，还统计：
- 最长一条多少字符；
- **超过 80 字符的有几条**，上限 **3**。

```
PASS 面板文案与当前实现一致（129 行；最长 77 字符；超过 80 字符的 0 条（上限 3））
```

## 为什么是"最多 3 条"而不是"都不许超过"
- 面板里确实有必须说全的长句（如只读权限那条要同时给出两个替代做法）；
- 但**趋势**才可怕：每次都想"再加一句解释"，一年后满屏长句；
- 预算制挡住趋势，又不逼着把话说半截。

## 验证（不是"应该有效"）
把阈值临时调到 `-1`：
```
$ node scripts/render-panel-copy.mjs --check --limit -1
FAIL 最长 77 字符；超过 80 字符的 0 条（上限 -1）
$ echo $?
1
```
恢复正常阈值 → exit 0。
