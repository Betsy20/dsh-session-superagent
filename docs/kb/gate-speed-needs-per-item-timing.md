# 门禁变慢时，先给每一项加耗时

## 出处
- 性能优化的第一步永远是 profiling：**不知道谁慢，就只能靠猜**。
  （Knuth/Amdahl 的老话，但工程上真正做的人很少：<https://en.wikipedia.org/wiki/Profiling_(computer_programming)>）

## 现场
全量 `preflight` 要 **83.7 秒**，但我以为是"检查太多" —— 加了每项耗时才发现：
```
PASS 门禁自检   21/21 项注入都被检测到  (56.6s)   ← 一项占了 68%
PASS 单测 node --test       215/215  (9.3s)
PASS 长跑体积    165.2 KB            (6.0s)
```

## 三处改法
1. **门禁自检里有两个注入在跑整套 `preflight --fast`**（22.1s + 13.8s）——
   它们只想验证「README 单测数」「语法」两条检查：
   - `scripts/audit-readme-tests.mjs`：真实用例数由调用方传进来（preflight 刚跑完 `node --test`，它知道），零成本；
   - `scripts/audit-syntax.mjs`：`node --check` 六个文件，0.5s。
2. **路由注入跑整个测试文件**（11.4s）→ `--test-name-pattern=路由面收敛`，只跑那一例（0.18s）。
3. 顺手发现第一次选的 pattern 抓不到问题：`注册了预期的工具与路由` 只检查"三条路由存在"，
   **不检查路径对不对**；换成钉住 9 条路径的那一例才真正红。

## 结果
| 阶段 | 耗时 |
|---|---|
| 改前 | **83.7s** |
| 改后 | **28.3s**（-66%） |
| 门禁自检本身 | 56.6s → **4.4s** |

## 判据
**每项检查都要打印自己的耗时**，并且结尾打「最慢三项」。
否则门禁会悄悄慢到没人愿意跑，而"没人跑的门禁"等于不存在。

## 是否已落地
✅ 0.9.107。`preflight` 每行带耗时 + 末尾「最慢：…」。
