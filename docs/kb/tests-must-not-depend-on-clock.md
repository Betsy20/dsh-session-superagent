# 用例不能依赖"现在几点"

## 出处
- 测试确定性（test determinism）：**任何依赖真实时钟的断言，都会在某一天自己变红**。
  通行做法是"时钟注入"（fake timers / clock injection）：
  <https://en.wikipedia.org/wiki/Test_double>
- 与 [门禁也会装死](gate-mutation-check.md) 互补：一个说的是"检查没生效"，这个说的是"检查自己会漂"。

## 现场（本轮真踩到）
`顶部四个计数必须加得上总数` 里把活跃时段写死成 `03:00-04:00`：

| 什么时候跑 | 结果 |
|---|---|
| 白天 | 该守在窗口外 → 计数里出现「时段外」→ **绿** |
| **凌晨 3 点** | 该守就在窗口内 → 「时段外」消失 → `value('时段外')` = `NaN` → **红** |

而这个用例在 0.9.104 写的时候是绿的 —— 它只是**在特定时刻**才暴露问题。
本轮 `node --test` 从 223/223 变成 221/223，根因就是这个。

## 改法
不算魔法时段，直接算一个"此刻一定在窗口外"的窗口：
```js
function outsideWindow() {
  const start = (new Date().getHours() + 6) % 24   // 6 小时后
  const pad = (n) => String(n).padStart(2, '0')
  return pad(start) + ':00-' + pad((start + 1) % 24) + ':00'
}
```

## 判据
**写用例时先问：它依赖"现在"吗？** 依赖就把"现在"变成参数或从当前值推导，
否则这条用例会在某个凌晨变成一颗定时炸弹 —— 而且它红的时候，你多半会先怀疑代码，而不是怀疑时间。

## 是否已落地
✅ 0.9.116。凌晨 3 点跑 `node --test` = 223/223。

## 还没做的
- 仓库里可能还有别的时段/日期相关断言（只修了这一处被踩到的）；
- 没有"伪时钟"基础设施（现在靠"从当前时间推导"，够用但脆弱）。
