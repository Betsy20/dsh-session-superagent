# 不可解释的门禁等于没有门禁

## 出处
- SRE 的告警原则同样适用于门禁：**每条规则都要能说清"它防的是什么"**，
  否则红了没人知道该不该急（<https://sre.google/sre-book/monitoring-distributed-systems/>）。
- 我们这里的形态更简单：preflight 的每一项配一行"防止什么 + 证据"。

## 做法
`scripts/render-acceptance.mjs` 生成 `docs/验收清单.md`：

```
| # | 检查 | 防止什么 | 证据 |
| 1 | 单测 node --test | 功能回归：纯函数、路由、面板渲染 | KB fake-pass.md |
| 2 | README 单测数 | 文档里的数字过期（曾写 136，实际 181） | KB prose-numbers-drift.md |
…
```

**每个 `record(...)` 都必须在 `WHY` 表里有解释**，否则脚本 `FAIL 这些检查没有解释：…`。
它自己也统计在内（第 23 项就是"验收清单"本身）。

## 一次有趣的自我指涉
刚把这条检查接进 preflight，它立刻红：`FAIL 这些检查没有解释：验收清单` ——
**新加的检查自己没写解释**。给它也补一行后变成 23 项全绿。
这正是判据在起作用：**任何门禁都不能例外，包括守门禁的那条**。

## 为什么值得
- 客户/未来的我能一眼看出"这项红了要不要慌"；
- 新增检查时被迫回答"它防的是什么"，避免堆一堆没人懂的门禁；
- 文档由代码生成，不会和实际检查项脱节（`--check` 守着）。

## 是否已落地
✅ 0.9.50。`preflight --fast` 20 → 21 项（新增「验收清单」）；`docs/验收清单.md` 23 行检查。

## 还没做的
- 解释是手写的（`WHY` 表），可能写空话 —— 没有机制检查"证据是否真的存在"；
- 没有把"最近一次红过哪些项"记下来（那需要历史数据）。
