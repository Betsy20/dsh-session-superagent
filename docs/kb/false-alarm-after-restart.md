# 自检要分清「刚重启」和「真故障」

## 出处
- 告警系统里最伤信任的是**假警报**（false positive）：Google SRE 书里专门讲"如果一个告警不能行动，
  它就不该响"（<https://sre.google/sre-book/monitoring-distributed-systems/>）。
- 进程重启后状态天然"陈旧"，这是**预期状态**，不是故障。

## 现场
上一版加的停滞检查（`age > max(3×interval, 5min)`）有一个假警报：
**宿主重启后** `lastPoll` 天然是几小时前的 → doctor 立刻报「定时器可能丢了」——
而客户只是刚重启。**假故障比没检查更糟**：客户会开始不信这个自检。

## 改法
- 记录 `PROCESS_STARTED_AT`，写进 `state.server.startedAt`；
- 停滞判断加前提：**进程 uptime 也超过停滞周期**才报故障；
- 否则如实说明：
  ```
  INFO acme/x 上次轮询是 120 分钟前，但进程才启动 1 分钟 —— 刚重启，等下一轮即可
  ```

## 判据
**任何"最后活动时间"的判断，都要和"进程活了多久"比一次。**
否则每次部署/重启都会制造一轮假警报，而假警报会训练人忽略真警报。

## 是否已落地
✅ 0.9.96。用例：刚重启 → 「刚重启」且无「定时器可能丢了」；进程跑够 3 小时 → 才报故障。

## 还没做的
- `startedAt` 只在 `state.server` 里，进程内另有 `PROCESS_STARTED_AT`，两处应当一致但没断言；
- 面板上没有"这台宿主上次重启是何时"的展示。
