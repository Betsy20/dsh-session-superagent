# 同一个毛病出现三次以上，说明缺的不是补丁而是检查

## 出处
- 这是"根因 vs 症状"的老问题：反复修的 bug 通常有一个**结构性原因**（缺少自动化护栏）。
  Google SRE 书在"postmortem culture"里强调：同类事故重复出现 = 上次的改进项没落地
  <https://sre.google/sre-book/postmortem-culture/>

## 统计（232 条 CHANGELOG）
| 主题 | 出现次数 |
|---|---|
| 门禁 / 检查 | 129 |
| 面板 UI | 116 |
| 错误提示 / 分类 | 88 |
| 文案 / 用词 | 60 |
| 消息内容 | 47 |

具体毛病词频：**`重复` 22 次**（最高）、`漏` 17、`兜底` 11、`漂移` 7。

## 结论
"重复"出现 22 次 = **至少 22 次是同一类疏漏**（改一处忘了另一处）。
第 23 次打补丁不如让工具去找它：

`scripts/audit-duplicate-copy.mjs` 扫 `client.js` / `lib/*.js`，
报告**同一句中文（≥16 字）出现两次**。首跑抓到 2 处：

1. `隔离执行（每次唤醒开一个临时副本；在副本里改，用完自动回收）` —— 触发页与设置页各一份；
2. `… 里都没有痕迹 —— 可能还没被轮询到，或者编号写错了。` —— 工具与 HTTP 两条路径各一份。

都抽成常量后 **0 处重复**，并接进 `preflight`。

## 判据
**词频统计是最便宜的根因分析**：不用读 232 条，只要数一数反复出现的是哪几个词。

## 顺带撞到的一次 TDZ
搬常量时替换脚本把常量自身的字面量也替换了 → `const ISOLATED_HINT = ISOLATED_HINT`，
用例立刻 `ReferenceError: Cannot access before initialization`。
**机械替换要排除"定义行本身"。**

## 是否已落地
✅ 0.9.103。`preflight` 第 32 项「整句文案不重复」。

## 还没做的
- 只扫整句单个引号字面量；模板字符串、双引号里的没覆盖；
- 阈值 16 字是拍的（短了噪音大），没有数据支撑。
