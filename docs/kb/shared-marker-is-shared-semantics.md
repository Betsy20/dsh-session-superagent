# 打在共享对象上的标记，语义也是共享的

## 出处
- 幂等标记放在**资源**上（issue 的 label），而不是**使用者**上（会话）时，
  语义天然是"资源级"的：所有使用者共享同一份结论。
  这是"作用域决定语义"的经典例子：<https://en.wikipedia.org/wiki/Scope_(computer_science)>

## 现场
`watch_ack` 把「主理鱼:已处理」打在 issue/PR 上 —— 那是**仓库级共享**的位置。于是：

- A 会话 ack 后，B 会话下一轮会把它当"已处理"跳过（判定日志记「已 ack」）；
- 这通常是**对的**（避免两边重复修同一个 bug），但客户必须知道；
- 想让两边各处理各的，就要**各用各的标签**。

## 改了什么
1. 面板在"还有 N 个会话也在守"后面补一句，直说共享语义与解法；
2. `watch_start` 新增 `ackLabel` 参数（此前只有面板能设）；
3. 顺手修了一个默认值缺失：`watch_start` 创建守时**没写** `ackLabel`（面板路径有），
   靠读取时兜底才没出事 —— 现在创建时就落盘默认值。

## 判据
**标记放在哪一层，语义就在哪一层。** 放在资源上 = 所有人共享；放在会话上 = 各自独立。
写功能前先明确"这个标记归谁"，能省掉后面所有解释。

## 是否已落地
✅ 0.9.106。用例覆盖"自定义标签落盘 / 不传用默认"。

## 还没做的
- 面板没有编辑 ackLabel 的输入框（只能靠工具或新建时带）；
- 两个会话用不同标签时，同一个 issue 会出现两个标签，没有任何清理机制。
