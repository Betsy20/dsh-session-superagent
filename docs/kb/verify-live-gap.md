# 版本差 54 个版本，界面上看不出来

## 出处
没有外部文献 —— 这是本机实测的教训，记下来因为**它会在任何"改了代码但没重启"的场景重演**。

## 实测
```
node scripts/verify-live.mjs
PASS /state 可达            HTTP 200，26ms
FAIL 版本对齐                 线上 0.8.38 ≠ 仓库 0.8.91
FAIL 响应带 ETag             没有 etag 头：这个版本早于 0.8.85
FAIL 条件请求可用（304）          跳过：没有 ETag
FAIL /diagnose 可用         HTTP 404
PASS /update 可用           current=0.8.38 latest=0.8.90
```

链路都通、页面都正常、`/state` 返回 200 —— **唯一对不上的就是版本**。
如果只看"页面能打开"，会以为一切正常。

## 为什么容易误判
1. 客户端热重载会生效（界面新功能看起来都在），让人以为整包都生效了；
2. `/state` 本身是老代码也能返回 200；
3. 老版本没有 `/diagnose`，但前端只是"请求失败"而不报错。

## 怎么做
把"线上跑的哪一版"变成一条命令，并且**把新特性是否存在也纳入判定**：
- 版本对齐；
- 响应头有 `etag`（0.8.85 起）；
- 条件请求能回 304；
- `/diagnose` 可达（0.8.47 起）。

四项任一 FAIL 就说明"线上还是老代码"，不需要再猜。
