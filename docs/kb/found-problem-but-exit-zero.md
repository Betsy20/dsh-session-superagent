# 检查发现了问题，却不返回失败

## 出处
- 与 [门禁也会装死](gate-mutation-check.md) 同源，但这是**第三种**形态：
  检查逻辑是对的、输出也对，**只有退出码是 0**。
  任何只看退出码的调用方（CI、脚本串联、注入验证）都会被骗。

## 现场
`audit-duplicate-copy.mjs` 发现重复文案时输出：

```
扫描 4 个文件，整句（≥16 汉字）重复 1 处
  x2  client.js  这是一个足够长的重复文案…
```

然后 **exit 0**（当时把它写成"INFO，仅供提示"）。
`preflight` 之所以还能红，是因为它碰巧用**文字匹配** `重复 0 处` 来判断 ——
一旦输出格式变了，这条检查也会跟着失效。

更有说服力的是：这轮做"反向用例"时，第 2 项怎么都红不了 ——
**用例自己把假通过抓了出来**。

## 改法
```js
console.log('FAIL 同一句文案出现两次 —— 抽成常量，或确认后改一处')
process.exitCode = 1
```
`preflight` 同步改成用 `res.status === 0` 判断，不再依赖文案。

## 三类"装死"汇总（现在是三条独立知识）
| 形态 | 例子 |
|---|---|
| 检查逻辑写错 | needle 写成固定字符串，永远匹配不到 |
| 判断条件没参与 | `leaky` 只放进提示文字，没进 `if` |
| **发现问题但 exit 0** | 本条 |

## 判据
**每条检查的唯一权威是退出码。** 文案是给人看的，退出码是给机器看的；
两者必须一致，否则迟早有人只信错的那个。
