# 可用性抽检：三条失败路径的"第一句话"

## 出处
- NN/g 的错误信息指南（已在 0.8.97 用过）：每条提示要**说明问题并给出建设性解决方案**。
  这一轮把它变成**可执行的自检**：不读代码，只看"客户会看到的第一句是什么"。
- 工具化：`node scripts/audit-ux-copy.mjs` 直接把这三处的现有文案打出来，避免凭记忆判断。

## 三条路径与抽检结果
| 路径 | 第一句话在哪 | 结果 |
|---|---|---|
| ① 仓库没写权限 | 行内徽章 `只读` + **（当时「需要关注」里没有）** | ❌ 只靠一个小徽章，客户不知道"回写会 403" |
| ② 会话没规则（叫醒了没回音） | 「需要关注」：`已连续 N 次唤醒后没有回音…检查 AGENTS.md` + 「看建议规则」 | ✅ 有原因 + 有动作 |
| ③ 一直没动静 | 判定页「时间线」+ 总览「还没有唤醒过…点「立刻」/ 看「需要关注」」 | ✅ 有原因 + 两个动作 |

## 改了什么
① 补上：`accessNoteForPanel()`（与服务端 `gh-format.js:accessNote` 同语义），
把"只有读权限"写进「需要关注」：

> 你对 owner/name 只有读权限：能看、能被叫醒，但没法回写评论或打标签 ——
> 要么换有写权限的 token，要么把结论写在本地/PR 描述里。

为什么客户端要独立一份：面板不跨包 import 服务端模块（避免把 cordis 依赖带进浏览器包），
两端各有一份同语义实现 —— 这已经是**第三个**这样的重复（`repoBadges` / `durationText` / 现在这个）。
知识库在这里记一笔：**重复是有意的，但每次都要有用例覆盖两端**。

## 是否已落地
✅ 0.9.16。用例：只读仓库必须在「需要关注」出现、必须给出"换 token"的下一步、
有写权限的仓库不得出现这条。
