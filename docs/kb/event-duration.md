# 合并了次数，还要能说出"持续了多久"

## 出处
- 与上一条同源（PagerDuty Alert Grouping）：合并之后，值班的人下一步要问的是
  **"这个问题持续多久了"** —— 只有次数没有时长，就无法判断严重程度。
  <https://support.pagerduty.com/docs/alert-grouping>
- 实现上就是给事件加两个时间：`since`（首次）与 `at`（最近）。

## 上一轮留下的缺口（我自己在 KB 里记的）
0.9.9 合并时把 `at` 更新成最新时间，**首次发生时间被覆盖** ——
于是只知道"最近一次是 X"，不知道"从什么时候开始"。20 条里的 `×10` 看不出是 10 分钟还是 10 小时。

## 改法
`pushEvent` 给每条事件加 `since`：

| 字段 | 含义 | 合并时 |
|---|---|---|
| `since` | 首次发生 | **不变** |
| `at` | 最近一次 | 更新 |
| `count` | 次数 | +1 |

（老数据没有 `since` 时，合并那一刻补一个，避免显示成"持续 0 分钟"。）

`durationText(since, until)` 输出人话：`不到 1 分钟` / `42 分钟` / `2 小时` / `2 小时 5 分`。
面板显示为 `cap-watcher ×10 · 持续 42 分钟`。

## 是否已落地
✅ 0.9.10。用例：`since` 不被覆盖、`at` 会更新、count 累加；
`42 分钟` / `2 小时 5 分` / `2 小时` / `不到 1 分钟`；缺输入与反向时间都给空。

## 还没做的
- 客户端为了不跨包 import，`durationText` 与服务端**各有一份实现**（同语义）。
  两份容易走偏 —— 目前靠同一条用例分别覆盖，但没有自动比对。
- 没有把"持续超过 1 小时"的事件在面板上额外标红（现在只靠 ×N 与时长文字）。
