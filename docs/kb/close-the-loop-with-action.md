# 提示之后要有下一步动作，但别替客户改仓库

## 出处
- AGENTS.md 是给 Agent 看的约定文件（"a README for agents"）：
  <https://agents.md> —— 它解决的问题正是"agent 不知道该按什么规则干活"。

## 上一轮留下的断头路
0.9.11 会提示「已连续 3 次唤醒后没有回音 —— 检查 AGENTS.md 有没有给出处理规则」。
但**提示之后没有下一步**：客户还得自己去想"规则该写什么"。

## 改法（克制版）
在「需要关注」那条提示上挂一个「看建议规则」按钮，打开弹层给出可直接粘贴的片段：

```md
## 主理鱼（dsh-session-superagent）处理规则
- 收到「【主理鱼】… 有 N 条新动态」时，先读完整条目再决定做不做。
- 做：按【完成标准】三件事写清，改完推分支开 PR。
- 不做：也要说明理由，然后照样 ack。
- 无论做还是不做，最后都要 watch_ack 打标签，否则下一轮会被再次唤醒。
```

**为什么不直接写进仓库文件**：那是客户的仓库，代写风险高（可能覆盖、可能和他们的规范冲突）。
给可复制的文本 + 说明，让人自己决定 —— 收益 90%，风险 0。

## 一个真实的实现坑（值得记）
弹层原本用**新加的 useState**，结果整套用例红了：
测试桩的 `useState` 是**按位置取队列**的（`hooks.queue[hooks.index]`），
在中间插一个新 state 会让后面所有 state 收到错位的值。
最后改成复用已有的 `glossary`（`false` 关 / `true` 术语表 / `'rules:owner/name'` 规则弹层），
零新增槽位，问题消失。

## 是否已落地
✅ 0.9.12。用例：未点开不得渲染规则文本（不该占版面）、点开后必须出现规则与 ack 要求、必须有复制动作。

## 还没做的
- 没有"检测 AGENTS.md 是否已含该段"（要读文件，且读完还得判断语义）；
- 没有做"复制后自动在 issue 里贴一份"（那属于代写，同上不做的理由）。
