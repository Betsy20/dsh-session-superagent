# 文案的"行"要按字符数算，别按字节

## 出处
- 中英混排下，**一个汉字 = 3 字节**（UTF-8），所以任何用字节数判断"这行多长"的工具
  在中文环境都会高估 2~3 倍。这是 i18n 里的经典坑（同一原因导致过不少截断 bug）。
- 定行宽上限的依据是"聊天窗口里一行读起来不费劲"，属于排版常识；
  120 字符是本次取的阈值，**写死在门禁里**。

## 第一次测量就掉进坑里
```
$ node scripts/first-run.mjs | awk '{ print length($0) }' | sort -rn | head -1
128
```
我以为某行有 128 字符，准备动手拆行。实际按**字符数**一量：

```
102 字符：#42 [open] 登录页在 Safari 上白屏 — @customer-a (issue) 标签: bug …
```

**awk 按字节算**（本机不是 UTF-8 感知的 awk）。如果没有复核，我会去"修"一个并不存在的问题。

## 做了什么
1. `scripts/audit-line-length.mjs`：用 `[...line].length` 算字符数，上限 120；
2. `formatWatchText` 加了一条**保护性**规则：单行超过 120 字符就把补充信息折到下一行
   （链接点哪都一样，折行几乎无损）；
3. 顺带把消息末尾那段 **260 字节的"墙"**（"接下来：1… 2… 3…"）改成分行编号 ——
   它本来就该分行，只是以前挤成了一段。

## 实测结果
```
检查 48 行（按字符数）
最长一行 102 字符
PASS 所有行都在 120 字符以内
```

## 是否已落地
✅ 0.9.37。`preflight --fast` 对应检查：`PASS 单行长度　最长 102 字符（上限 120）`；
文案快照同步刷新（44 → 47 行）。
