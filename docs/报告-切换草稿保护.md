## 1. 交付结果

折叠或切换 watcher 时，未保存草稿不再被静默重置：

- dirty 折叠：打开「放弃未保存的修改？」确认层，确认按钮为「放弃并收起」。
- dirty 切换：打开同一确认层，文案点出目标 watcher，确认按钮为「放弃并切换」。
- 取消、Escape、遮罩或关闭按钮：保留当前 dirty 表单、字段文案和 touched/dirty SaveBar。
- 只有确认放弃才重置草稿与 touched；切换后载入目标 watcher 的干净快照。
- 无 dirty 时维持原来的直接展开、折叠和切换行为。
- 复用现有 `ConfirmDialog → PanelModal → DSH Modal`，未引入浏览器 `window.confirm`，未新增样式或自制弹层。
- 确认、取消与确认连点均不发出 watcher POST。

核心实现见 [client.js:2130](../client.js#L2130) 和 [client.js:3427](../client.js#L3427)。

## 2. 状态与焦点设计

### 2.1 dirty 判定

以当前编辑快照为基线，同时检查：

1. `touchedRef.current.size > 0`；
2. 合并当前 draft 后，`watcherDirty(...)` 与打开快照存在差异。

因此取消不会重建或清空 touched，确认切回时则从目标 watcher 快照重新计算，旧草稿不会串到另一条 watcher。

### 2.2 折叠挂起与确认关闭

为保持既有行内编辑探针和 UI 行为一致，dirty 折叠在确认期间挂起 `editing` id，但通过 `displayedEditing` 继续挂载原表单；draft/touched 不动。取消时恢复原 `editing` id，确认时才调用统一的编辑器重置入口。

`watcherDraftConfirmedRef` 区分「确认后的关闭」与「取消/Escape 的关闭」，避免共享 `onClose` 在确认后又误恢复原编辑态。

### 2.3 Modal 与焦点

确认层直接复用共享 `ConfirmDialog`，沿用其 busy 防重入和 `PanelModal` 的焦点圈、Escape、关闭后焦点归还。真实 Chromium 验证：

- 打开后焦点位于当前 Modal 内，首个焦点为「关闭」按钮；
- Escape 后返回折叠触发按钮；
- 取消切换后返回被点击的目标 watcher 标题；
- 确认切换 / 折叠后也返回对应触发按钮。
