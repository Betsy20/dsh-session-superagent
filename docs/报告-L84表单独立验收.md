## 4. 明确未覆盖与保真度边界

### 4.1 touched-only 只覆盖同一 render 的请求体过滤

现有 harness 的 `useRef` 每次 render 都返回新对象（T38 §1.3 已确认），不能在“输入 → 重渲染 → 点新树保存”的链路中保留 `touchedRef`。因此第 8 项在第一次真实输入并重渲染得到 dirty 表单后，第二次输入采用同一 render 内回放，再点击该树保存。

它证明的是：**同一 render 内已经记录 touched 后，真实 `touchedRef → saveEdit → fetch` 链会严格过滤请求体。**

它没有证明：

- `useRef` 跨 render 持久化；若生产把 ref 错改为每次 render 新建对象（T38 M3），本用例仍可能通过；
- 跨 render 后的新 `draft/value/onSave` 闭包及 stale closure；
- 真实浏览器的 submit、constraint validation 与原生事件链。

没有手工复制或伪造 touched Set，也没有把这一项表述成跨 render 保真通过。

### 4.2 harness 不是浏览器或完整 React

- `useState` setter 只记录调用，本测试显式回放；React 自动重渲染、批处理及多次函数式更新的语义不在覆盖范围内。
- 原生 label 点击聚焦、浏览器 min/max 非法值拦截和原生表单提交未验；本测试验的是对应 DOM 关联、属性和直接控件处理器。
- `useEffect` 不执行，焦点恢复、effect 清理等不在本次范围。
- 未做真实布局测量，不能据此宣称窄屏无横向滚动。

### 4.3 本次未扩展的验收项

busy（fieldset 禁用、防重复提交）、error（保留输入、`role=alert`、重试）及窄屏/真机走查不在父任务本次明确要求新增的 8 项中，本报告不把它们写成已通过。后续可用 deferred fetch 配合 `stateCalls + applyCalls` 补 busy/error；窄屏需要浏览器或真机证据。
