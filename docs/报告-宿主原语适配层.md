# L84d 宿主原语适配层报告

## 交付边界

本次只修改独立适配模块、对应假对象测试和本报告；没有修改 `client.js`、`package.json`、`lib/`、其他测试、版本、派单表或 contract fixture，也没有 commit/publish。

适配层不接管业务确认、watcher 状态或 StatusOrbit，不实现自己的焦点圈、portal、定位、Toast timer 或第三套 Tooltip。

## exports 与调用面

`ui-host-primitives.js` 的 ESM 具名 exports：

- `createHostUi({ React, primitives })`
- `dismissToast(current, id)`：纯函数；仅 `current.id === id` 时返回 `null`，否则原样返回 `current`。

`createHostUi` 返回：

- `Modal({ open, title, description, footer, onClose, className, children })`
  - `open=false` 直接返回 `null`。
  - 打开时创建 `primitives.Modal`，透传上述参数并固定补 `closeLabel:'关闭'`。
  - 焦点、Escape、背板与 modal stack 全部留给宿主。
- `Toast({ item, onDone })`，其中 `item={ id, text, tone }`
  - 创建带 `key:item.id` 的 `primitives.Toast`，固定 `holdMs:3000`。
  - `onDone` 适配为只回传 `item.id`，不透传宿主事件或其他参数。
  - `success` 不传 `icon`，保留宿主内建勾；`error` 显式创建官方 `IconWarningOutlineMedium`。
  - 同时只保留最新一条仍由调用方负责；适配层没有队列或第二套 timer。
- `Tooltip({ text, icon, warn, children })`
  - 创建 `primitives.Tooltip`，映射 `label:text`，固定 `side:'top'`、`portal:true`、`openOnClick:true`、`gap:8`。
  - scroll-close 由这个宿主 React 包装组件适配：`useState` 保存 remount key，`useEffect(..., [])` 在 `window` 以 capture 注册 `scroll`，回调用函数式更新把 key 加一，并把该 key 传给 `primitives.Tooltip`。设计上由 key 变化卸载旧宿主 Tooltip、挂载新实例，从而清掉其内部 open/pinned 状态；capture 用于覆盖嵌套滚动容器。
  - 为避免 keyed remount 丢失 trigger 焦点，适配器用 `React.cloneElement(trigger, { ref })` 只补一个合并 ref：新 ref 同时维护内部 trigger DOM ref 与调用方原有的函数/object ref，原 element、props 和 handlers 不被改写。DSH Tooltip 随后再按真实 API 克隆该 trigger 并合并自己的 ref 与 hover/focus/click handlers。
  - scroll 回调在状态更新、旧 trigger 卸载**之前**读取 `document.activeElement`；仅当它是当前 trigger 或 `trigger.contains(activeElement)` 时置一次性的焦点恢复标记。`useEffect(..., [remountKey])` 在新 ref 附着后消费该标记，对仍连接的新 trigger 调用 `focus({ preventScroll:true })`，避免焦点归还再次触发滚动；标记无论能否聚焦都只消费一次，后续无关渲染不会补抢。滚动前焦点在 trigger 外时不调用 `focus`。
  - 这不是 DSH 原生受控关闭：没有传 `open/onOpenChange`，也没有假称宿主已有 scroll listener。effect 清理时用同一回调和 `capture:true` 对称解绑；无 `window` 时不注册，无 `document` 时不会标记焦点恢复。ref 卸载时对称收到 `null`，调用方原 ref 同样收到 `null`。
  - 除上述 ref 适配与 scroll 后重挂载外，不增加 DOM、不替换或包装 trigger 的 hover/focus/click handler；这些交互和 pinned 行为仍由 `primitives.Tooltip` 负责，原调用面和 props 不变。
  - `children` 若提供，必须是单个 React element；字符串、数组和 `null` 都显式抛错。
  - 省略 `children` 时保留原 InfoTip 的 `button.dt-info`、`warn` 对应的 `dt-info-warn`；默认 question、可选 info/warning 图标均来自 primitives，也接受调用方传入的 React icon element，不自绘 SVG。
  - 缺少 `primitives.Tooltip` 时显式抛出“不可用”，不会回退到本地弹层。
- `createToastState()`
  - 返回 `{ item, notify, dismiss }`。`notify(text,tone)` 替换当前 item，`dismiss(id)` 用函数式 state 更新执行 `dismissToast`。
  - 调用方可把 `dismiss` 直接传给适配 Toast 的 `onDone`；计时只由宿主 Toast 负责。
- 同名 `dismissToast` 引用，便于集成时只从 factory 返回值取用。

## 真实 API 调用证据

依据 [04-host-primitives-smoke.md](ui-decomp/04-host-primitives-smoke.md)：

1. 该记录通过安装版 web bundle 的真实 `__ModuleLoader__.create({ staticModules })` 捕获 primitives，并经主理鱼 factory 注入的 `require('@deepseek-ai/dsh-client-ui-primitives')` 取得同一对象：`sameIdentity:true`、`exportCount:290`、React `18.3.1`（文档 `:30-43`）。因此适配器只接收宿主注入对象，不做普通 Node 包解析。
2. `Modal` 的真实参数包括 `open,onClose,title,closeLabel,description,children,footer,className`（文档 `:147-164`）。
3. `Toast` 的真实参数为 `{ text, icon, tone, anchor, holdMs=3000, actions, onDone }`；源码直接调用无参 `onDone()`，success 才自带勾，error 需显式 icon（文档 `:183-196`）。
4. `Tooltip` 的真实参数为 `{ label, side='right', gap=8, portal=false, openOnClick=false, children, ... }`；children 必须可由宿主 `cloneElement`，`openOnClick=true` 才启用 pinned click 模式（文档 `:198-216`）。同段明确宿主没有 scroll listener，也没有受控 `open/onOpenChange`，所以本适配选择 remount，而不是虚构受控 API。
5. `IconWarningOutlineMedium`、`IconQuestionOutlineMedium`、`IconInfoOutlineMedium` 均在真实 290 exports 清单内（文档 `:88-140`）。
6. keyed Toast、按 id 清除、显式 error icon 与 `holdMs:3000` 的迁移约束见同文档 `:335-344`；Tooltip 参数建议见 `:315-320`。

本模块把这些真实参数连成可测试的薄调用面；没有把上述 smoke 改写为浏览器验收结论。

测试文件：`test/host-primitives-adapter.test.mjs`。使用假 React（包含与 React 18 一致把 `key/ref` 从 `props` 剥离、克隆时保留原 key/ref 的行为）、假 DOM 和假 primitives，验证：

- Modal 的 props 透传、中文 `closeLabel` 与关闭不渲染；
- Toast 的真实元素 `key`、`holdMs`、success/error 图标分支、无参宿主完成回调到 `onDone(id)` 的转换；
- Tooltip 的 `label/side/portal/openOnClick/gap`、单 element 约束、默认 trigger 样式及缺少原语时显式报错；
- 自定义 trigger 经 `cloneElement` 只增加合并 ref：原 element 不被修改，type/children/class/props 与 hover/focus/click handlers 保持，调用方 object ref 在附着和清理时分别收到 DOM node 与 `null`；
- scroll-close 的 effect `deps=[]`、假 `window` 上精确的 `('scroll', listener, true)` 注册参数、函数式 key 更新与重渲染后 key 从 0 到 1、cleanup 用同一 listener 和 capture 参数对称解绑；
- 模拟 keyed commit 的旧 ref `null` 清理、新 ref 附着和 passive effect 顺序：滚动前焦点在 trigger 或其内部时，新 trigger 收到一次 `focus({preventScroll:true})` 且 key 递增；焦点在别处时新 trigger 的 `focus` 调用次数为零，外部焦点保持不变；首次 mount 不聚焦，原 props/handlers 不回归；
- `dismissToast` 的 id guard 与 `createToastState` 的替换/函数式清除。

这些测试没有 mount 真实 React 或真实 DSH Tooltip；假 effect、ref detach/attach 和 scroll listener 都是手动执行，`document.activeElement`、`contains` 与 `focus` 也是假 DOM。因此它们只证明适配策略、事件注册参数、state updater、key、ref 链和清理，不证明真实 React reconciliation 已卸载旧 Tooltip，不证明 DSH 的真实 ref 合并顺序或浏览器 `document.activeElement` 已恢复，也不证明真实 DOM capture 传播、bubble 已关闭，**不宣称真实 DOM/浏览器行为已验证**。

以下仍待宿主/真实浏览器验收：Modal 焦点圈与焦点归还、Escape/背板、轮询不抢焦点；Toast 的 3+1 秒生命周期、fade、连续通知重挂载与 `role=alert` 读屏；Tooltip 的 hover/focus/touch/click pinned、Escape/Tab、外点、portal 叠放、边缘定位，以及 window/嵌套容器 scroll 后旧 bubble 是否关闭、新实例是否保持关闭。焦点专项还必须实验：DSH 二次 `cloneElement` 后适配 ref 与原 ref 是否都附着到新 DOM、keyed remount 的 passive effect 时序、`focus({preventScroll:true})` 是否避免二次滚动、程序聚焦是否经宿主 focus handler 重新打开 bubble，以及焦点在 trigger 外时是否始终不抢。

本次只交付独立适配模块的 scroll-close 与焦点恢复策略。编写报告时，并行工作树的 `client.js` 已出现另一份内联 Tooltip 焦点恢复改动及对应新测试；那不是本任务写入的内容，其旧断言冲突和最终复跑由集成方单独处理。无论两处实现是否相同，都不能仅凭本模块假 DOM 测试通过就宣称实际 InfoTip 路径的焦点问题已验收。真实 DSH Toast 根语义为 `role=alert`，不是旧实现的 `role=status/aria-live=polite`。
