# 唤醒消息示例（由 scripts/first-run.mjs 生成，不要手改）

```text
===== 1. 轮询：从 3 条动态里挑出该唤醒的 =====
仓库里最近有 3 条动态；其中 3 条是「新」的，0 条被冷却期吸收（是我自己刚操作过的）

===== 2. 一次只叫醒 N 条 =====
批大小 2 → 这次唤醒带 2 条，剩余 1 条下一轮再说
本轮选中：#42 登录页在 Safari 上白屏 / #77 修复表头错位

===== 3. 唤醒消息（客户会读到的原文）=====
【主理鱼】acme/widgets 有 2 条新动态：
#42 [open] 登录页在 Safari 上白屏 — @customer-a (issue) 标签: bug https://github.com/acme/widgets/issues/42 未认领
#77 [open] 修复表头错位 — @contributor (PR) https://github.com/acme/widgets/pull/77 未认领
【为什么是这几条】本轮共 3 条变化；按优先级取前 2 条
（另有 1 条：#43，处理完这批再看）
本条目主理目标：让客户的问题当天有回应
【完成标准】
1. 改了什么：文件清单 + 一句话为什么
2. 怎么验证的：跑过的测试/命令 + 结果
3. 回写到哪：在 issue 里留言 + watch_ack 打标签

接下来：先读仓库 AGENTS.md 定「修 / 回 / 待定」；没有测试结果不算完成；做完一条就写回 GitHub + watch_ack 打标签，不要扩大范围。

===== 3b. 有跳过时的同一条消息 =====
【为什么是这几条】本轮共 7 条变化；按优先级取前 2 条；本轮跳过 4 条（已关闭 × 2、机器人 × 1、已 ack × 1）

===== 4. 面板会看到什么 =====
按仓库：acme/widgets（1 条守）
徽章：（无）

===== 5. 这些情况下产品会怎么说 =====
· 仓库已归档：acme/widgets 已归档：GitHub 上归档仓库是只读的，评论和打标签都会失败 —— 守它只能看、不能回写。
· 关闭了 Issues：acme/widgets 关闭了 Issues —— 主理鱼只认 issue / PR，这里不会有任何条目可接。
· 只有读权限：你对 acme/widgets 只有读权限：能看、能被叫醒，但没法回写评论或打标签 —— 要么换有写权限的 token，要么把结论写在本地/PR 描述里。
· 仓库名联想（输入 acme/wid 时）: （无）
· 已打 ack 标签的条目会被跳过：true

===== 5b. 失败与不唤醒时长什么样（客户最常问：为什么没动静）=====
· Get "https://api.github.com/repos/a/b/issues?p…
    kind=network　面板显示：GitHub API 请求: EOF　建议：（网络抖动：这一轮没连上 GitHub，已按退避自动重试，不需要手动处理）
· HTTP 403: API rate limit exceeded for user ID …
    kind=ratelimit　面板显示：HTTP 403: API rate limit exceeded for user ID 1　建议：（被 GitHub 限流：等几分钟，或换成带 token 的凭证）
· HTTP 404: Not Found…
    kind=notfound　面板显示：HTTP 404: Not Found　建议：（不存在或没权限 —— 私有仓库也回 404：检查 owner/name 与 token）

· 会话正忙（不在 idle）→ 不唤醒，记下原因：{"ok":false,"reason":"agent busy (running)"}
· 会话空闲 → 允许唤醒：{"ok":true}
    面板上会显示「暂停唤醒：agent busy (running)」，下一轮空闲时自动补上。
```
