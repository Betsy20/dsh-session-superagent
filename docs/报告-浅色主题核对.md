## 1. 怎么量的

### 1.1 数据来源

不是截图肉眼取色，也不是读源码猜 token，而是**浏览器自己算出来的值**：

1. `scripts/render-preview.mjs` 把真实 `client.js` 的组件树 + 移植的 `PORTED_CSS`/`DOCK_CSS` 渲染成静态 HTML；
2. 往这份 HTML 末尾注入一段测量脚本，用 `msedge --headless=new --dump-dom` 在真浏览器里跑；
3. 脚本对 `.preview-frame` 内每个「有直接文字节点」的元素：
   - `getComputedStyle(el).color` 取前景；
   - 从元素自身向上逐层 `getComputedStyle(node).backgroundColor` 收集，遇到 `alpha = 1` 的层停；
   - 把这一叠颜色**从底往上画到 1×1 canvas 上**，读 `getImageData` 得到合成后的真实背景；
   - `opacity`（含祖先）乘进前景的 alpha，前景再叠加到背景上；
   - 用 WCAG 相对亮度公式算比值。
4. 非文字面（胶囊底、输入框底、统计条）按「自身填充 vs 父层合成色」算，用来查 1.4.11 的 3:1。

### 1.2 踩过的两个坑（写下来，免得下个人重踩）

- **`color-mix()` 不能用正则解析**。`getComputedStyle` 对 `color-mix(in srgb, #9a6700 12%, transparent)`
  返回的是 `color(srgb 0.603922 0.403922 0 / 0.12)`，不是 `rgba(...)`。第一版用 `/^rgba?\(/` 解析，
  结果**所有胶囊底色都被当成「透明」→ 背景算成纯白 → 比值虚高**（琥珀算成 4.87，实际 4.17）。
  改成交给 canvas（`fillStyle` + `getImageData`）后才是真值。
- **解析和合成不能共用一块 canvas**。解析颜色本身要 `fillRect`，会把已经合成好的背景**覆盖成纯色**
  （第二版把琥珀底算成了 `#966900`，比值 1.00，看着像「白底白字」的大新闻，其实是工装 bug）。
  现在解析用一块画布、合成用另一块。

### 1.3 这套测量的边界（别拿它当真机结论）

- `lightTokens` 是预览工装里**手写的近似值**，真机以宿主注入的 `--dsw-alias-*` 为准。
  本报告量的是「**面板 CSS 与这套 token 组合出来的结果**」，不是宿主真实色板。
  但结论对「**面板自己写死的颜色 / 面板 CSS 对某个 token 档的依赖**」完全成立 —— 那部分与宿主无关。
- 只量静态渲染，不量 `:hover` / `:focus-visible` / 动画中途。悬停态在 `PORTED_CSS` 里都是
  `--dsw-alias-interactive-bg-hover`（`#f3f4f6`），本身与白底只差 1.03，属「弱提示」设计，未列入不达标。
- 预览工装的兜底 `body` 是 `#eef1f4`，不在 `.preview-frame` 内，未计入面板。

| `PORTED_CSS` 第 190 行 | `#000` ×2 | `.dt-page .dt-tabs[data-more='both'] { mask-image: linear-gradient(to right, transparent, #000 40px, #000 calc(100% - 40px), transparent) }` |

**判定：可以留。** `mask-image` 吃的是**亮度通道**不是颜色，`#000`/`transparent` 在这里表示
「遮住 / 露出」，与主题无关；换成 token 反而错。这 3 条选择器要求 `[data-more]` 属性，
本次 4 个页面都没出现（tab 条未溢出），所以扫不到属正常。

另有 2 处**颜色关键字兜底**（不是 hex/rgb，但同属写死）：

```css
.dt-pre ins { background: color-mix(in srgb, var(--dsw-alias-state-success-primary, green) 18%, transparent); }
.dt-pre del { background: color-mix(in srgb, var(--dsw-alias-state-error-primary) 18%, transparent); }
```

`ins` 那行的 `green` 是 token 缺失时的兜底值。**只有 `.dt-pre ins` 会用到**（diff 视图的插入行），
本次 4 张图都没有 diff 视图，未触发。**判定：低危，但既然是兜底就应该和 `del` 一样不写** ——
`del` 那行没有兜底，两个写得不一致。

### 4.3 结论

**没有「浅色主题下出现写死颜色」的问题。** 面板颜色 100% 来自 `--dsw-alias-*`，
浅色下的浅是**token 值本身**（`--dsw-alias-label-caption: #818b98`）造成的，不是写死色。

## 5. 工装自身的问题（只报告，**本次没改 `scripts/**`**）

### 5.1 `render-preview.mjs` 把 `aria-*=true` 渲染成**裸属性**，导致所有 `[aria-selected='true']` 样式不生效

`scripts/render-preview.mjs` 的 `attr()`：

```js
function attr(name, value) {
  if (value === undefined || value === null || value === false || value === true) {
    return value === true ? ' ' + name : ''      // ← 这里
  }
  return ' ' + name + '="' + escapeHtml(value) + '"'
}
```

`value === true` 时输出的是裸 `aria-selected`（无值），而 CSS 写的是
`.dt-tab[aria-selected='true']`。**属性存在但值不是 `'true'`，选择器不命中。**

实测（修之前）：`grep -o 'aria-selected[^ >]*' preview-light-source.html` →

```
      1 aria-selected
      5 aria-selected='true']
```

真机 React 渲染 `aria-selected={true}` 得到的是 `aria-selected="true"`。所以：

- **影响面**：所有依赖 `[aria-selected='true']` / `[aria-checked='true']` / `[aria-pressed='true']` /
  `[aria-current='true']` 的样式。本仓里至少包括选中 tab（`--label-primary` + 下划线）、
  开关 `dt-switch[aria-checked='true']`（变蓝）、分段控件 `dt-segment[aria-selected='true']`。
- **影响历史**：**此前所有深色主题出图核对都带着这个失真**。它们看到的选中 tab 是「未选中」的颜色。
  那几份报告的「选中态」结论需要打折看。
- 本次处理：只在**临时副本**里把 `true` 改成 `name="true"`（仅 `aria-*` / `data-*`），
  让出图和测量都对齐真机。`scripts/**` 一个字没动。

### 5.2 预览 token 是手写近似值

`scripts/render-preview.mjs` 里 `lightTokens` / `darkTokens` 是硬编码的兜底色板。
真机的 `--dsw-alias-*` 由宿主注入，可能与这里的值不同。**凡是「刚好擦边」的结论（4.43 / 4.54 / 4.55）
都要在真机上复核一次**，因为宿主只差一点点就会翻到另一边。

## 结论

### 最该先修的三处

#### ① `--dsw-alias-label-caption` 这一档在浅色白底上整体不够（3.14–3.45）

- **证据**：`#818b98` on `#ffffff` = **3.45**，on `#f6f8fa` = **3.24**，on `#f3f4f6` = **3.14**。
  深色下同一档是 `#7d8590` on `#0d1117` = **5.07** / `#161b22` = **4.64** / `#1c2128` = **4.34** —— 深色全部过线。
- **受影响**：`span.dt-stat-unit`（统计条四个单位，3.14/3.24/3.45）、`span.dt-count`（分组计数 3.45）、
  `span.dt-row-meta.dt-signal-meta`（+100 分… 3.45）、仓库行副标题（3.45）。
  共 **11 个组合 / 22 个文字节点**，覆盖**错误态、暂停态、分诊信号页**三个页面。
- **为什么它排第一**：不是单个元素的问题，而是**一整个语义档位**（「次要说明」）在浅色下集体失效。
  而且它踩的正是这次要查的那个坑 —— 深色下过、浅色下不过，光看深色永远发现不了。
  受影响的人是**所有用浅色主题看统计条/分诊权重/仓库副标题的人**，也就是「想快速判断哪条守出事」的那一眼。
- **修法方向**（不在本任务范围，交 Lead）：把浅色的 `label-caption` 压深到 `#6e7781`（= tertiary，4.55）
  或 `#636d78`（≈4.9）；或者把 `dt-stat-unit` / `dt-count` / `dt-signal-meta` 三处从 `caption` 升到 `tertiary`。

#### ② 琥珀 / 绿胶囊的「12% / 10% 同色底」把文字对比度吃掉（4.17 / 4.43）

- **证据**：`warning` 胶囊 `#9a6700` on `#f3ede0` = **4.17**（纯白底时是 4.87，**同色底扣了 0.7**）；
  `success` 胶囊 `#1a7f37` on `#e8f2eb` = **4.43**。
  深色下同一胶囊是 **6.34 / 6.51**，都很宽裕。
- **受影响**：「判断」（琥珀）、「已暂停」（琥珀）、「退避 7200s」（琥珀）、「事实」（绿，×4）。
  也就是**暂停态和分诊信号页的状态识别**。红胶囊 `danger` 是 4.54、擦边通过，但余量只有 0.04。
- **为什么它排第二**：这三颗胶囊是面板里**唯一承载「这条守现在什么状态」的颜色**。
  淡到读不出色差，用户就只剩文字可读；而 11px 的字本身也小。
  和 ① 不同，这个修起来很便宜：把同色底的混色比例从 10–12% 降到 6–8%，
  或者直接用 `label-primary` 当胶囊文字、让颜色只留在描边上。

#### ③ 浅色下「表面」几乎全部同色：输入框 1.00、设置内容区 1.00、统计数字选中态 1.03

- **证据**：`span.dt-input` 填充 `#ffffff` on `#ffffff` = **1.00**、边框 `#c6cdd5` = **1.60**；
  `div.dt-settings-body` 填充 `#ffffff` on `#ffffff` = **1.00**、边框 `#d8dee4` = **1.36**；
  `button.dt-stat-btn[aria-pressed="true"]` 选中底 `#f3f4f6` on `#f6f8fa` = **1.03**。
  三者都低于 WCAG **1.4.11** 要求的 3:1。
- **受影响**：**浅色主题下所有用户**，具体是两件功能事：
  ① 搜索框没有边界 —— 看不出哪里能打字；
  ② **点了统计数字在按它筛选，浅色下没有任何视觉反馈**（1.03，肉眼等同没变）。
- **为什么它排第三**：它不是「读不清字」，而是「看不出这是个控件」。
  文字对比度全部合格（搜索框文字 15.80、统计数字 14.84），所以不影响阅读；
  但 1.4.11 是硬指标，而且这是**纯浅色问题**：`bg-layer-1` 和 `bg-base` 在浅色下都是 `#ffffff`，
  在深色下好歹是 `#141a21` vs `#0d1117`。修法很简单（浅色给 `bg-layer-1` 一点灰度，
  比如 `#fbfcfd`，或把边框提到 `border-l3` 以上），但**不能只改边框**——
  统计选中态那个 1.03 是「hover 底色 vs 模块底」，得单独给它一个可见的选中样式。

### 没发现问题的部分（明确写下来）

- **没有「白底白字」**：最低的文字比值 1.82 是 `[disabled]` 按钮，WCAG 1.4.3 明确豁免；
  除它之外，**全部文字 ≥ 3.14**，且 15 个不达标组合（30 个节点）全部落在 3.14–4.43 这段「偏淡」区间，不是不可读。
- **红色在浅色下没翻车**：`--dsw-alias-state-error-primary` `#cf222e` 当正文用是 **5.36**（阶段字 / 错误行 /
  `dt-error-text`），完全够。危险只在**带 10% 红底的横条**（4.54）—— 任务担心的「浅色下红色最危险」
  在纯文字上不成立。
- **面板 0 处写死颜色**：四份渲染结果扫 `#rrggbb|rgb()|hsl()` 全部为 0，
  颜色 100% 走 `--dsw-alias-*`。源码里仅 3 处 `#000` 在 `mask-image`（亮度通道，主题无关）+
  1 处 `green` 兜底关键字（本次未触发）。
- **选中 tab / 选中导航 / 选中胶囊的文字都过线**：15.80 / 14.84 / 5.74。

### 不在本任务范围、但必须让 Lead 知道的两件事

1. **`scripts/render-preview.mjs` 的 `attr()` 把 `aria-*=true` 渲染成裸属性**，
   导致所有 `[aria-selected='true']` / `[aria-checked='true']` 样式在预览里**从不生效**。
   **此前所有深色出图核对都带着这个失真**（选中 tab 显示的是未选中色）。
   本次为了量准，只在临时副本里改了，`scripts/**` 未动 —— 这个工装 bug 需要单独派单修。
2. **预览 token 是手写近似值**。§3 里所有「擦边」结论（4.43 / 4.54 / 4.55 / 1.60）
   都建议在真机上复核一次再动手改，因为宿主只差一点就翻面。
