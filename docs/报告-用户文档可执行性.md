## 一、必须修

### M1. `README.md:66` 与 `README.md:72` —— 安装节的第一条命令直接跑不起来（两层问题）

原文：

```bash
# 默认 profile
dsh plugin install dsh-session-superagent
...
# 本地开发：直接装这个目录（会以 file: 硬链接方式挂进 profile）
dsh plugin install /path/to/dsh-session-superagent
```

**照着做会发生什么**（两层，分别实测）：

① 在装了 DSH Desktop 的本机上，`dsh` 根本不在 PATH：

```console
$ dsh plugin install dsh-session-superagent
/usr/bin/bash: line 1: dsh: command not found
[exit=127]
```

```console
$ where dsh
信息: 用提供的模式无法找到文件。
```

② 就算拿到了 DSH Desktop 自带的那个 CLI（`(resources/runtime/cli/bin/dsh.cmd)` 指向的
`app.asar/dsh/node_modules/@deepseek-ai/dsh-desktop-host/lib/cli.js`），`install` 也不是它的子命令写法，
而且 `--profile` 是**必填**：

```console
$ ELECTRON_RUN_AS_NODE=1 "…/DeepSeek Harness.exe" --expose-internals "…/dsh-desktop-host/lib/cli.js" \
    plugin install dsh-session-superagent
error: required option '--profile <name>' not specified
[exit=1]
```

依据：`cli.js`（`@deepseek-ai/dsh/lib/bin.js`）里写的是
`plugin … .requiredOption("--profile <name>", …)`，且帮助示例只有一种形态：

```text
dsh plugin --profile tui add <package>    install a plugin into the tui profile
```

DSH 界面自己的文案也说「包名就是 README 里 `dsh plugin add` 后面的那一段」——是 `add`，不是 `install`。
`plugin install` 这个串只在一条恢复提示里出现过（`run 'dsh plugin install'`），不是子命令表。

**建议改成**（三条一起改，否则第一条永远是最容易点的坑）：

1. `环境要求`（`README.md:54` 那节）补一行：**`dsh` CLI 从哪来** ——
   DSH Desktop 用户用 `(安装目录)\resources\runtime\cli\bin\dsh.cmd`，或把它所在目录加进 PATH；
2. 把 `dsh plugin install …` 统一改成有 `--profile` 的形态：
   `dsh plugin --profile <profile> add dsh-session-superagent`；
3. 明确 `<profile>` 是哪来的（`$DSH_HOME/profiles/` 下的目录名；本机实际有 `desktop`、`web` 等），
   不要让客户猜一个占位符 —— 现在 `README.md:66` 写「默认 profile」，
   但 CLI 没有默认 profile 这回事。

### M3. `docs/真机验证清单.md:11` —— 默认端口写死 64349，开箱即 FAIL
