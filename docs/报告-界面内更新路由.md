## 1. 交付结果

- 原 `GET /session-superagent/update` 的只读版本检查保持不变。
- 同一路由新增 `POST`，先过现有 `guardWrite`，再读取严格 JSON body。
- body 只允许 `{}` 或 `{ "version": "<strict semver>" }`；额外字段、畸形 JSON、数组、`latest`、`v1.2.3`、范围、前导零、非法预发布与命令文本均在 runner 之前拒绝。
- 省略 `version` 时复用 `checkUpdate(false)` 的 `latest`。`latest` 缺失或不是严格 semver 时返回 503，不会退化为执行 `@latest`。
- 生产 runner 使用 `child_process.spawn` 的 argv 数组，`shell:false`，固定执行：

```text
dsh plugin --profile <profile> add dsh-session-superagent@<version>
```

-  runner 通过 `apply(ctx, { updateRunner })` 注入；测试中的路由 runner 与生产 spawn 均为 mock，未真实安装。

## 2. profile 与 CLI 解析

### profile

按以下顺序读取第一个非空值：

1. `DSH_PROFILE`
2. `DSH_PROFILE_NAME`
3. `DSH_ACTIVE_PROFILE`

没有值时返回 `profile_unavailable`，没有 `desktop` 兜底。profile 必须是 1–64 位的字母、数字、点、下划线或连字符，并以字母或数字开头，防止把额外 CLI 选项塞进参数位。

### CLI

按以下顺序查找，第一个存在且可执行的候选获胜：

1. `DSH_CLI_PATH`
2. `PATH` 各目录中的 `dsh`（Windows 同时检查 `dsh.exe` / `dsh.cmd`）
3. DSH 安装布局：`process.resourcesPath/runtime/cli/bin/dsh[.cmd]`，以及 `dirname(process.execPath)/resources/runtime/cli/bin/dsh[.cmd]`

`DSH_CLI_PATH` 可指向可执行文件或 `.js` / `.mjs` / `.cjs` CLI 入口。JS 入口使用当前 runtime 加独立 argv 执行。

Windows 标准 `resources/runtime/cli/bin/dsh.cmd` 不会经 shell 启动：runner 将其转换为独立 `DeepSeek Harness.exe` 子进程，设置 `ELECTRON_RUN_AS_NODE=1`，并传入 `--expose-internals` 与 asar 内的 `dsh-desktop-host/lib/cli.js`。非标准 `.cmd` / `.bat` 不猜测、不拼 shell 字符串，返回可读的 `cli_unsupported`。全部候选都找不到时返回 `cli_not_found`，不假装成功。

## 3. 并发、超时与输出

| 项目 | 行为 |
|---|---|
| 并发 | `Symbol.for('dsh-session-superagent.pluginUpdateInFlight')` 跨模块实例共享；第二个请求得到 409 `update_in_flight` |
| 默认超时 | 120,000ms；生产 runner 超时只终止自己启动的 CLI 子进程 |
| 注入 runner 超时 | 外层计时器返回 504；锁保留到迟到 runner 真正结算，避免重叠安装 |
| 迟到拒绝 | 成功与失败两种迟到结果都有处理器，不产生未处理 Promise rejection |
| stdout / stderr | 每路最多保留 16KiB；响应带 `stdoutTruncated` / `stderrTruncated` |
| 退出码 | `0` 才为成功；非零保留真实 `code` / `exitCode` 并返回 500；spawn 失败不会映射成成功 |
| 输出安全 | HTTP 回传前经过现有 `redact()`，并有第二次 16KiB 上限 |

特别处理了 runner 自身以 `code="timeout"` 拒绝的情况：它与外层计时器错误按对象身份区分，两种情况都会释放或最终释放锁，不会永久挡住后续更新。

## 4. HTTP 契约

### 成功

以下为 mock 示例；`installedVersion` 是命令结束后重新读取的磁盘版本，`runningVersion` 始终是当前进程已加载的 `SERVER_VERSION`，不会把安装成功写成运行中代码已更新：

```json
{
  "ok": true,
  "code": 0,
  "exitCode": 0,
  "version": "0.9.272",
  "profile": "work-profile",
  "installedVersion": "0.9.272",
  "runningVersion": "0.9.271",
  "needsReload": true,
  "stdout": "",
  "stderr": "",
  "stdoutTruncated": false,
  "stderrTruncated": false
}
```

`needsReload` 在磁盘版本与运行版本不同，或成功请求的目标版本与运行版本不同，时为 `true`。实现不包含重启、关闭 DSH 或修改 `cordis.patch.yml` 的代码。

### 失败

| HTTP | `code` / 场景 |
|---:|---|
| 400 | `invalid_body` / `invalid_version` |
| 403 | `guardWrite` 拒绝跨源写请求 |
| 405 | 非 GET / POST |
| 409 | `update_in_flight` |
| 500 | 非零退出码、`spawn_error` 或其它执行失败 |
| 503 | `cli_not_found` / `cli_unsupported` / `profile_unavailable` / `invalid_profile` / `latest_unavailable` |
| 504 | `timeout` |
| 413 | 沿用现有 body 64KiB 上限 |

失败响应同样携带 `installedVersion` / `runningVersion` / `needsReload`，不声称安装或加载成功。
