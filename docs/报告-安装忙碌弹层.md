# 安装忙碌弹层修复报告

日期：2026-11-06  
工作区：`D:\主工作区\projects\dsh-session-superagent-update-busy`

## 结论

更新安装确认层现在只在 `preventDismissOnBusy: true` 时启用忙碌防关闭：POST 进行中，取消按钮禁用，取消处理器与 Modal `onClose`（遮罩、Escape、右上关闭）都被同步 guard，连点不会重复发请求；弹层持续显示“安装进行中，完成后才能关闭”，确认按钮保留 `aria-busy="true"`。成功后仍只关闭一次并展示安装回执；失败后解除 busy，取消与 `onClose` 恢复可用。

watcher 删除等其它确认没有传入该开关，默认 `preventDismissOnBusy = false`，保留原行为。

## 根因

`ConfirmDialog` 原先用 `busyRef` 只锁住确认按钮，取消按钮和 Modal `onClose` 仍直接调用 `onClose`。因此安装 POST 尚未完成时，用户仍能关闭弹层；请求继续在后台执行，但界面失去进行中状态和最终结果入口。

## 改动

### `client.js`

- `ConfirmDialog` / `ConfirmButton` 新增默认关闭的 `preventDismissOnBusy` 参数，仅更新安装调用点传入 `true`。
- 新增 `dismiss()`：开关启用且 `busy` 或 `busyRef.current` 为真时返回 `false`，不调用原 `onClose`；否则维持原关闭路径。
- busy 时取消按钮 `disabled`，取消处理器和 Modal `onClose` 统一走 `dismiss()`。
- 成功路径继续直接调用一次原 `onClose()`，不经过 busy guard，避免成功后被误挡。
- busy 正文复用现有 `Hint`，显示“安装进行中，完成后才能关闭”；按钮复用现有 `ButtonComponent`，Modal 复用现有 `PanelModal`/本地 fallback，没有新增样式。

### `test/update-ui.test.mjs`

- 成功用例改为 deferred POST：pending 时验证取消、遮罩/Escape/关闭共用的 `onClose`、确认连点均不关闭且 POST 总数保持 1；同时验证取消 disabled、确认 `aria-busy` 和进行中 Hint。
- resolve 后验证只关闭一次、强制刷新一次、回执写入并展示 `installedVersion` / `runningVersion` / 等待重载状态。
- 失败用例改为 deferred POST：resolve 为 HTTP 500 后验证不伪造成功、不刷新、不写安装回执，busy 解除，取消与 `onClose` 均可关闭，原错误 Section/Toast 和命令回退仍保留。
