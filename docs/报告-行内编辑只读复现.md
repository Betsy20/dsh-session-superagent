# T55 · 行内编辑「只能看到数据，不能修改」根因复现

日期：2026-11-05  
范围：只读分析 + 测试；本任务没有修改 `client.js` 或其他生产文件，没有 commit。  
可写交付物：本报告与 `test/edit-interaction-probe.mjs`。

## 0. 结论先行

**真实根因是标题按钮的透明伪元素点击层覆盖了整个已展开行，抢走了表单控件的鼠标点击。**

旧结构同时满足三条：

1. `.dt-row { position: relative }`，使 watcher 的 `li.dt-row.dt-ticket` 成为定位包含块；
2. 仓库标题是 `button.dt-open`，其 `::after` 为 `position:absolute; inset:0`，因此铺满整个 `li`，不只是标题文字区域；
3. 展开的 `WatcherForm` 也挂在这同一个 `li` 内，旧 CSS 没有给表单独立的叠层保护。

于是鼠标点 input 时，实际命中的是标题按钮。生产标题 `onClick` 在展开态执行 `setEditing(null)`，编辑器随即卸载。用户看到的就是：**字段和值都能看见，但一点就像只读，无法进入修改。**

这不是 `disabled/readOnly`，不是 React 受控输入失效，也不是轮询把 draft 重置。

并行任务已经在 **0.9.267 / commit `c4be34e`** 加入最小修复：

```css
.dt-ticket-body .dt-form { position: relative; z-index: 1; }
```

当前 `client.js:186` 已包含该规则；本任务只在浏览器内做删除/恢复这一条规则的 A/B，没有改生产源码。

## 2. 决定性 Chromium A/B

### 2.1 方法

探针复用现有 `scripts/render-preview.mjs` 生成当前「行内编辑」静态预览，但拦截最后一次 `writeFileSync`，HTML 只保存在内存。随后在同一个 Chromium 页面做两组实验：

- A：仅从内存 HTML 删除 `.dt-ticket-body .dt-form { position: relative; z-index: 1; }`；
- B：把同一条规则恢复；
- 其他 DOM、CSS、输入位置完全相同；
- 不伪造生产 React 点击回调，只给标题添加 click 计数器，观察真实指针命中和焦点。

可复跑入口已保存在 `test/edit-interaction-probe.mjs` 的 `captureStaticPreview()` 与 `runBrowserAbProbe(page, html)`。

### 2.2 A：删除保护规则，复现成功

目标：「目标/规则」input 的中心点，坐标 `(527, 464.625)`。

```text
input.disabled = false
input.readOnly = false
li.dt-ticket position = relative
form position/z-index = static/auto
::after position/inset = absolute/0px

elementFromPoint(input 中心) = button#probe-row-opener
elementsFromPoint 前两项 = button#probe-row-opener, input#probe-goal-input
```

真实鼠标点击该点：

```text
document.activeElement = button#probe-row-opener
openerClicks = 1
input.value = 原始值（未改变）
```

这直接排除了「只是看起来不能改，实际 input 能聚焦」的可能：失败分支的焦点确实没有进入 input。

### 2.3 B：恢复一条保护规则，输入成功

```css
.dt-ticket-body .dt-form { position: relative; z-index: 1; }
```

同一个输入点：

```text
elementFromPoint(input 中心) = input#probe-goal-input
form position/z-index = relative/1
document.activeElement = input#probe-goal-input
openerClicks = 1（保持 A 的次数，没有新增）
键盘插入 X 后 input.value = 原始值 + X
```

因此最小修复点就是这个表单叠层，而不是给 input 加 `readonly=false`、重写 onChange、关闭轮询或给行容器补另一个 onClick。

### 2.4 为什么现有动作按钮一直能点

现有 `.dt-ticket-actions` 已有 `position:relative; z-index:1`，所以「立刻/暂停/删除」能避开标题伪元素；旧 WatcherForm 没有同等保护。这也解释了为什么 bug 只在展开后的编辑控件上出现，而不是整行所有按钮都失效。

## 3. panel-harness 状态与结构复现

`node test/edit-interaction-probe.mjs` 已实测：

1. 调真实仓库标题 `onClick` 打开目标编辑器；
2. 「目标/规则」input 有 `value` 和 `onChange`，没有 `readOnly`，非 busy 时 input/fieldset 不禁用；
3. 调生产 input `onChange` 后，正确的 draft 槽位更新；
4. 仅替换 snap，模拟新 `/state` 到达，draft 仍为新输入，标题仍 `aria-expanded=true`；
5. 再调展开态标题 `onClick`，`editing` 变为 `null`，补齐「误点标题 → 收起」的最后一环；
6. ticket/body/form/fieldset 无 onClick，ticket 内只有一份 form；
7. 无 Toast/Modal 时无对应覆盖 DOM，无 inert，form 无 `pointer-events:none`；
8. 当前 CSS 已能检测到表单叠层保护。

### 3.1 旧 opening 是否会覆盖 draft

当前渲染顺序是：

```js
const opening = editSnapshotRef.current?.key === key
  ? editSnapshotRef.current.values
  : watcherValuesFrom(watcher)
const editorValue = { ...opening, ...draft }
```

`draft` 最后展开，优先级高于 opening。`opening` 只在标题打开/关闭、保存成功时显式重设；普通 `load()` 不写它。故「服务端轮询返回旧 watcher， opening 把正在输入的 draft 覆盖」不符合当前代码路径。

需要保留的边界：panel-harness 的 `useRef` 跨 render 会重建，不能用它证明真 React 的 ref 持久性；这里对轮询的结论来自**生产 setter 调用面审查 + draft 优先级 + 独立真实 React 探针**，不是单靠桩。

## 4. React 18.3.1 受控 input / onChange / onInput

为排除「只是假 React 能更新」，另在真实 Chromium 挂载了同版本官方包：

- [React 18.3.1 UMD](https://unpkg.com/react@18.3.1/umd/react.production.min.js)
- [ReactDOM 18.3.1 UMD](https://unpkg.com/react-dom@18.3.1/umd/react-dom.production.min.js)

受控组件将 `draft.goal` 作为 input.value，在 `onChange` 中 `setDraft({...draft, goal:event.target.value})`，并另设独立 snap 状态。结果：

```text
React.version = 18.3.1
输入后 onInput.nativeEvent.type = input
输入后 onChange.nativeEvent.type = input
onChange 读到 event.target.value = React 草稿
input.value = React 草稿
document.activeElement = controlled

只更新 snap：tick 0 → 1
input.value 仍为 React 草稿
焦点仍为 controlled

显式 setDraft('显式重置') 后
input.value = 显式重置
```

结论：**受控值只有随 draft 改变才重置；父级其他状态重渲染本身不会清掉 draft。** 生产 `WatcherForm` 文本/数字控件只登记 `onChange`，没有第二个 `onInput` 写入器，事件链没有竞争。

此探针证明同版本 React 的浏览器语义，不声称已经挂载到需认证的 DSH Web GUI。

## 5. 点击、label、form/fieldset、CSS 与 Modal/Toast 排查

### 5.1 行级和高级折叠点击

- watcher 行没有整行 `onClick`；标题自己才是 button。
- 真正覆盖 input 的是标题的 `::after`，不是 input 的事件冒泡到父容器。
- 高级设置 `DisclosureRow` 的触发行有 onClick；高级输入位于其后的 `.dt-disclosure-body`，不是触发行后代，不会仅因冒泡触发折叠。
- 「只看已指派/仅观察/隔离执行」等 switch 都在同一个 WatcherForm 内，表单叠层修复同时覆盖它们。

### 5.2 label 与 form 嵌套

- `Field` 使用 `div.dt-field`，标题为 `label[htmlFor=fieldId]`，input 使用对应 id。
- InfoTip 与 label 是兄弟节点，不再把 button 嵌进 label。
- HoursField 的起止 input 有各自 aria-label；起始 input 与 Field label 关联。
- ticket 内只有一份 WatcherForm form，没有 form 套 form。
- fieldset 只在 busy/disabled 时禁用；截图对应的普通展开态不满足该条件。

### 5.3 pointer-events / inert / 覆盖层

- `.dt-ticket-actions/.dt-row-buttons/.dt-row-actions` 的 pointer-events 规则不匹配 `.dt-form`。
- 编辑树没有 inert 属性。
- 真正的覆盖层是 `.dt-open::after`，透明不代表不参与命中测试。
- 本次失败 A/B 已在同页证明：不需要假设任何额外第三方覆盖层，单这一条伪元素就足以完整复现。

### 5.4 Modal / Toast 新改动

源码与定向测试能支持的结论：

- fallback Modal 在 `open=false` 时返回 null；其 effect 依赖 `[open]`，轮询重渲染不会仅因 inline `onClose` 重建焦点 effect。
- DSH HostModal 同样在 `open=false` 时返回 null；打开后才交给宿主 portal。
- `useToast` 只维护 Toast item/timer，不调用 `setDraft` 或 `setEditing`；无 item 时没有 Toast 覆盖层。
- fallback `.dt-toast` 本身是 `pointer-events:none`。
- 表单与 Modal/Toast 的定向测试 38/38 通过。

边界：这些结果排除了「未打开 Modal/Toast 时它们导致本次静态只读」；不代替真实 DSH 宿主对 portal、焦点圈和 inert 的验收。

### 6.2 应保留/补充的回归测试

1. **真实命中测试（最高优先级）**：用当前静态预览或宿主 DOM，对「目标/规则」和「间隔（秒）」中心点断言 `elementFromPoint` 是 input；真实鼠标点击后 `document.activeElement` 是 input，标题 click 次数不增加，`aria-expanded` 保持 true。
2. **A/B 反向用例**：只在测试 DOM 删除保护规则，必须复现 input 点击命中标题；恢复后可输入。防止测试只会验证“现在能跑”而从未见过原始失败。
3. **控件覆盖矩阵**：text、number、switch、高级 Disclosure 内 input、HoursField 起止时间、SaveBar 保存/放弃都各点一次；确认不触发标题，也不意外折叠高级区。
4. **轮询保持**：输入后连续推进至少两次新 snap，另覆盖 304 早退；断言 draft、editing、焦点保持。真实 React 的 ref 持久性要在真 mount 中验，不能只靠 panel-harness。
5. **React 事件**：真实 React 18.3.1 下用键盘输入，断言 onChange 的 nativeEvent 为 input、draft 逐字更新；另补 IME composition，避免中文输入中受控值回跳。
6. **label/折叠语义**：点击 label 聚焦对应控件；点击高级输入不改变 advancedOpen；ticket 内仍只有一份 form。
7. **保存链路**：修改后点击 SaveBar，确认只发 touched 字段、只发一次；保存失败保留草稿和编辑器，放弃恢复 opening。
8. **认证宿主验收**：在真实 DSH GUI 重复上述指针路径，等待实际 5 秒轮询，另开/关 Modal、触发 Toast，核对遮罩、焦点归还与表单命中。此项本次未做。
