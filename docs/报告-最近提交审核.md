**怎么确认的（实验，不碰仓库，全部在 /tmp）**：

```bash
cd /tmp
cat > sigtest2.mjs <<'EOF'

writeFileSync(mark + '.started', 'yes')
process.on('SIGTERM', () => { writeFileSync(mark + '.sigterm', 'handler-ran'); process.exit(0) })
process.on('SIGINT',  () => { writeFileSync(mark + '.sigint',  'handler-ran'); process.exit(0) })
process.on('exit',    () => { writeFileSync(mark + '.exit',    'exit-hook-ran') })
setInterval(() => {}, 1000)
EOF
cat > sigparent.mjs <<'EOF'
import { spawnSync } from 'node:child_process'
const res = spawnSync(process.execPath, ['sigtest2.mjs', 'mark2'], { cwd: process.cwd(), timeout: 2000, encoding: 'utf8' })
console.log('spawnSync status =', res.status, '| error =', res.error && res.error.code, '| signal =', res.signal)

```

真实输出：

```

```

只有 `.started`（被杀之前写的）。`.sigterm`、`.sigint`、`.exit` **一个都没有**。
也就是说 `bail()` 在 Windows 上一次都不会被调用。真机上 `node --version` = v24.20.0。

**修法方向**（不在本次改动范围）：Windows 上靠信号兜不住，得改成「子进程写前先落一份 journal，
下次启动时先检查 `.gate-lock` + 快照目录并自动还原」，或者让 `restoreAll` 在**每个用例开始前**先跑一遍
（现在的快照机制已经具备这个能力，只是没在启动时用）。

## 二、值得改

### W1. `scripts/preflight.mjs:133` 给 audit-pack 的 120s 超时 < 它自己等锁的 180s —— `SKIP 不假红` 这条分支**不可达**

```js
133:   const res = tryRun('node', ['scripts/audit-pack.mjs'], { timeout: 120000 })
```
对照 `scripts/audit-pack.mjs:24` 的 `acquireGate('mutate', { timeoutMs: 180000 })`：
`spawnSync` 会在第 120 秒把子进程杀掉（`status = null`），而 audit-pack 要等到第 180 秒才打印
`SKIP npm pack 内容  另一个门禁正在跑…` 并 `process.exit(0)`。也就是说**在 preflight 里这条优雅跳过永远走不到**，
