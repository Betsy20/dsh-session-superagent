# 重启之后：三条命令 + 三个动作

> 服务端改动只有**重启宿主**才生效。重启完照这个清单走一遍，5 分钟。
> 现在线上是 0.8.38，仓库已到 0.8.92 —— 也就是说下面这些"新特性"**一次都还没在真机跑过**。

## 一、三条命令

### 1. 一条命令看全貌

```bash
node scripts/verify-live.mjs            # 默认 http://127.0.0.1:64349
node scripts/verify-live.mjs http://127.0.0.1:<其它端口>
```

会逐项打印 PASS/FAIL。**重启前**在本机实测的输出是：

```
PASS /state 可达          HTTP 200，26ms
FAIL 版本对齐               线上 0.8.38 ≠ 仓库 0.8.91 —— 需要重启宿主（不是重装）
FAIL 响应带 ETag           没有 etag 头：这个版本早于 0.8.85
FAIL 条件请求可用（304）        跳过：没有 ETag
FAIL /diagnose 可用       HTTP 404
PASS /update 可用         current=0.8.38 latest=0.8.90
PASS 守的投影完整             1 条，其中隔离执行 1 条
```

**重启后预期**：7 项全 PASS，其中「版本对齐」「ETag」「304」「/diagnose」四项会翻绿。

### 2. 手工看重定向是否安全（可选）

```bash
curl -s -o /dev/null -w "%{http_code}\n" http://127.0.0.1:64349/session-superagent/state
# 期望 200
```

### 3. 确认没有编译/挂载级别的问题

```bash
node scripts/preflight.mjs
# 期望 9 项全 PASS（含「离线挂载冒烟」与「契约快照」）
```

## 二、三个界面动作

| 动作 | 期望 |
|---|---|
| 打开主理鱼面板 → 设置 → **诊断** → 复制诊断信息 | 剪贴板里出现「主理鱼诊断 · 时间 / 插件版本 0.8.9x / 挂载: routes=8 failed=0」 |
| 面板 → 设置 → **来源** → 看「权限范围」 | 显示 token 的 scope 列表（不是一直「正在探测…」） |
| 「总览」里找一条守 → 点行标题展开 → 看有没有「**隔离区保留天数**」 | 有输入框；保存后刷新仍在 |

## 三、如果哪一项没翻绿

| 症状 | 原因 | 处理 |
|---|---|---|
| 版本对齐仍是旧值 | 宿主没真重启（只是关窗口） | 用托盘退出再启动；不是重装 |
| `/diagnose` 404 | 同上（旧代码） | 同上 |
| ETag 缺失 | 同上 | 同上 |
| preflight 的「离线挂载冒烟」红 | 新增文件没同步进 profile | `node scripts/sync-profile.mjs --repair` 后重启 |
| preflight 的「契约快照」红 | 有人改了工具/路由形状 | 确认是有意改动后 `node scripts/contract.mjs --update` |

## 四、验证完请回填（一行就够）

```
重启后核对：0.8.92 / routes=8 / etag=有 / diagnose=有 —— 通过 or 哪项没过
```
