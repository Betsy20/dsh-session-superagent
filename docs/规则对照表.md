# 规则对照表：消息里说了什么，面板/文档里在哪说

> 用途：改文案或改协议时，照这张表逐条核对 —— 同一条规则不能只在一边存在。
> 判据来自知识库 [同一套规则，两个读者](kb/two-audiences-one-contract.md)。

## 唤醒消息里的硬规则

| # | 规则 | 消息（`lib/watch.js`） | 面板（`client.js`） | 文档 |
|---|---|---|---|---|
| 1 | 先读仓库 AGENTS.md 再决定做法 | `接下来 1.` | 空态提示「叫醒之后…」 | README「一次真实运行长什么样」第 4 步 |
| 2 | 只有「修 / 回 / 待定」三种处理方式 | `接下来 1.` | 同上 | — |
| 3 | 没有测试结果不算完成 | `【完成标准】2.` + `接下来 2.` | 同上（隐含在"做完写回"） | KB `dry-run-first-use.md` |
| 4 | 做完要写回 GitHub（留言/PR） | `【完成标准】3.` | 同上 | README 第 5 步 |
| 5 | 必须 `watch_ack` 打标签 | `【完成标准】3.` + `接下来 3.` | 空态提示 + 「叫醒了没回音」提示 | README 安全边界 |
| 6 | 不做也要说明理由并 ack | `接下来 3.`（隐含） | 空态提示 | KB `wake-without-ack.md` |
| 7 | **不要扩大范围**（只处理列出的条目） | `接下来 3.` | 空态提示（0.9.40 补） | 本文 |
| 8 | 隔离模式下只在副本里改、用完 `git worktree remove` | `【隔离工作区】` | 「隔离执行」开关说明 + 保留天数/数量说明 | README 已知限制 |
| 9 | 一次处理 N 条（批量上限） | 消息头「有 N 条新动态」 | 面板「每次最多唤醒几条」设置项 | KB `coalesce-bursts.md` |
| 10 | 频繁/积压时不要硬叫醒 | — （由服务端拦截） | 「需要关注」「暂停原因」Pill | README 三层频率限制 |

## 核对结论（0.9.40）
- 1–5、8–10 两边都有；
- **6、7 原来只在消息里**（客户看面板不知道"不做也要 ack""不会扩大范围"）→ 已在面板补齐；
- 第 8 条面板只说"每次唤醒开一次性 worktree"，没说**用完会回收** → 已补。

## 怎么用这张表
1. 改唤醒消息里的规则措辞 → 回来核对第 2 列，并检查第 3、4 列是否还一致；
2. 新增一条硬规则 → 先在表里加一行，再决定它需要在面板/文档哪里出现；
3. 删掉一条规则 → 同样回来删行，避免面板还留着"已不存在的规则"。
