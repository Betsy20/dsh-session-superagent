## 官方结构依据

直接核对官方 superagent 原型源码：

- `src/client/widgets.tsx:75-89`：`ConfirmButton` 使用独立触发按钮、同一个 `Modal`、取消/确认 footer、异步 busy，成功后关闭。
- `src/client/controls.tsx:171-214`：`Modal` 的 Escape、Tab 焦点陷阱、背板关闭、焦点恢复；`onClose` 通过 ref 保持稳定，effect 只依赖 `open`。
- `src/client/rows.tsx:78-102`：`DecisionLine` 使用 `li.dt-row.dt-link.dt-ticket`，内部为 `dt-ticket-stage`、`dt-ticket-body`、标题、摘要和 meta。

没有新增第三套弹层，也没有引入 `window.confirm`。

## 实现结果

### 1. ConfirmButton + Modal

- 原 `ConfirmBtn` 的 armed 二段按钮已移除，统一为 `ConfirmButton`。
- 第一次点击「删除」只执行 `setOpen(true)`，不调用删除 action。
- 主面板与卫星环使用同一个 `ConfirmButton`、同一个 `Modal`；两处触发按钮统一为 `sm / ghost / trash`，测试直接比较两处按钮与 Modal 的 DOM 形状。
- Modal 使用官方 `description` 与 `footer` 结构，footer 为「取消 / 确认删除」。
- 取消、关闭按钮、Escape、背板只走 `onClose`，不调用 action。
- 确认期间设置 `busy`，确认按钮 `disabled + aria-busy + dt-btn-busy`；另有同步 `busyRef`，防止状态尚未重渲染时连点造成重复 POST。
- 两处现有 action 返回真实成功/失败布尔值：成功才关闭 Modal，失败保持打开；卫星环「删除成功但刷新失败」仍按动作成功关闭，并保留错误提示。
- `Modal` 最小修补：`onClose` 放入 `close` ref，effect 依赖从 `[open, onClose]` 改为 `[open]`，避免后台轮询重渲染反复清理/重建 effect、覆盖触发元素并抢走焦点；关闭清理仍执行 `back.focus()`。

### 2. 判定日志 DecisionLine

- 判定日志不再使用 `ol.dt-timeline > li.dt-event`。
- 每条记录改为 `ul.dt-list > li.dt-row.dt-link.dt-ticket`，包含：
  - 结果 StageMark：已唤醒 / 仅观察 / 跳过；
  - 仓库；
  - 编号（包括 Gitee 字符串编号，空编号显示「无编号」）；
  - 原因或「判定通过」；
  - `time[dateTime]` 与可读相对时间。
- 保留每守最近记录的截取与跨守时间倒序。
- 日期分组保留「今天 / 昨天 / 具体日期」，每天独立 `Section + ul.dt-list`；日期标题为 Section 标题内的 `span.dt-timeline-day`，不再与事件混作 `li`。
- 为既有主题与旧测试保留标题内部兼容节点 `dt-event-head`，但判定行主体语义与外层列表均为 DecisionLine。

### 3. 时间线回归边界

- `TraceTimeline` 保持 `ol.dt-timeline`，仍是一条标题及每个事件各自一个 `li.dt-event`。
- 运行时事件保持 `ol.dt-timeline`、倒序和一事件一 `li.dt-event`。
- 新测试同时断言 DecisionLine 不会混入上述两条时间线。
