# 行内编辑「看得到但不能改」：透明点击层修复报告

## 用户现象

展开 watcher 后能看到字段和值，但点击输入框像只读；同时表单直接散在 ticket 内，缺少官方 DraftEditor 的外壳层次。

## 已证实根因

不是 `disabled`、不是 `readonly`，也不是受控值被轮询重置。

官方 `.dt-open::after` 是覆盖整行的透明点击层：

```css
.dt-row { position: relative; }
.dt-open::after { position: absolute; inset: 0; }
```

展开后的 `WatcherForm` 没有抬层级，点击 input 实际命中标题按钮，触发展开/收起。动作区之所以能用，是因为官方 `.dt-ticket-actions` 已有 `position:relative; z-index:1`。

## Chromium 实测

同一静态预览、同一输入框坐标：

```text
修复前 elementFromPoint(input 中心)
→ <button class="dt-open" aria-expanded="true">…</button>

修复后 elementFromPoint(input 中心)
→ <input type="number" value="60">
```

独立 A/B 复现还确认：恢复 z-index 后焦点进入 input、键盘可追加字符、opener 不再收到 click；
移除修复后 opener 获焦并触发 click。标题 onClick 会把 editing 设为 null，因此这一击正好收起编辑器。

这不是测试桩推断，是真实 Chromium 的命中、焦点与事件结果。

## 修复

1. `.dt-ticket-body .dt-form { position:relative; z-index:1; }`：表单位于透明点击层之上。
2. `WatcherForm` 外壳改为官方 DraftEditor 的 `form.dt-card + Fields + SaveBar`，不再裸放 `dt-form`。
3. `scripts/render-preview.mjs` 增加「行内编辑 / 行内编辑（已修改）」两个永久预览场景。
4. `test/edit-click-layer.test.mjs` 固定 z-index 与 `form.dt-card`，防回归。

## 验证

- `node --check client.js` 通过；
- 全量测试 500/500；
- Chromium 命中测试通过；
- 未把「disabled 不存在」误写成「交互已验证」，本次以真实命中对象为准。
