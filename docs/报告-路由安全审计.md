### 2. `id=__proto__` 原型污染：一次跨站请求就把 `Object.prototype.enabled` 写成 `false`，进程内所有「缺省启用」的守一起变暂停

**代码**：`applyWatcherAction` 用未校验的 `id` 直接索引普通对象，命中的是 `Object.prototype`，随后往它上面赋值。

`lib/watch.js:453-463`

```js
export function applyWatcherAction(state, { action, id } = {}) {
  const watchers = (state && state.watchers) || {}
  const entry = watchers[id]
  if (!entry) return { ok: false, error: `unknown watcher: ${id || '(missing id)'}` }
  if (action === 'delete') {
    delete watchers[id]
    return { ok: true, action, id, deleted: true }
  }
  if (action === 'pause') {
    entry.enabled = false
    return { ok: true, action, id, enabled: false }
  }
```

`id` 的来源（只 `String()` 一下，无白名单）：`lib/index.js:1833-1834`

```js
            const action = String(body.action)
            const id = String(body.id || '')
```

`state.watchers` 是 `JSON.parse` 出来的普通对象，`watchers['__proto__']` 返回 `Object.prototype`（truthy，所以连 `if (!entry)` 都过），`entry.enabled = false` 就落在 `Object.prototype` 上——**污染的是整个宿主进程，不是这份状态文件**。

**触发条件**：任意网页发一条 `{"action":"pause","id":"__proto__"}`（`text/plain`，无预检，无凭证）。

**真跑输出**：

```
=== B. 污染前的 /state ===
  acme/widgets#session-A enabled=true workdir=null
  acme/other#session-B enabled=true workdir=C:\Windows\System32

=== C. 一次跨站请求：POST {action:pause, id:__proto__} ===
  HTTP 200 {"ok":true,"action":"pause","id":"__proto__","enabled":false}
  ({ }).enabled = false
  Object.prototype.hasOwnProperty("enabled") = true
  process 里任何缺省对象现在都「被暂停」：({ }).enabled === false → true

=== D. 污染后的 /state（同一个守，同一条数据）===
  acme/widgets#session-A enabled=false
  acme/other#session-B enabled=true
  注意：状态文件里 enabled 字段一个都没变 → 变的只是进程里 Object.prototype
  盘上 widgets 条目有没有 own enabled 字段 = false
  但同一条数据「读出来」的 enabled = false（继承自被污染的 Object.prototype）
  即：一个缺省启用的守在盘上仍启用，进程里却判成已暂停
```

**连带影响**（同一进程内所有读 `.enabled` 的代码，包括其它 DSH 插件）：`Object.prototype` 是进程级单例；`isEnabled()` 的语义是「`enabled === undefined` 即启用」（`lib/index.js:170-177`），污染后所有没显式写 `enabled` 的守一律判成暂停；反过来 `{"action":"resume","id":"__proto__"}` 会把它们全拉起来。这不是「面板显示错」，是**行为被改**。

**修法**：`applyWatcherAction` 开头用 `Object.hasOwn(watchers, id)` 判存在（一行），或 `const watchers = Object.create(null)` / 用 `Map`。同时 `event` 里的 `state.deleted`、`client-note` 的 `state.client` 等按外部键写入的地方都该过一遍 `Object.hasOwn`。

**顺带发现（同一根因，轻）**：`{"action":"delete","id":"__proto__"}`（以及 `constructor` / `toString`）会**谎报成功**，实际什么都没删：

```
  delete id="__proto__" → HTTP 200 {"ok":true,"action":"delete","id":"__proto__","deleted":true}
  delete id="constructor" → HTTP 200 {"ok":true,"action":"delete","id":"constructor","deleted":true}
  delete id="toString" → HTTP 200 {"ok":true,"action":"delete","id":"toString","deleted":true}
```

### 3. 请求体与守数量都**没有**上限：64KB 只是「读完之后截断」，48MB body 实测把服务端 RSS 顶高 229MB；守数量可以无上限灌

**代码**：`readBody` 先把**所有** chunk 收进数组，全部到齐后才 `truncateUtf8(..., 64 * 1024)`。也就是说 64KB 不是上限，只是「解析前砍掉尾巴」，内存已经花掉了。

`lib/index.js:1803-1814`

```js
      const readBody = (req) => new Promise((resolve) => {
        const chunks = []
        req.on('data', (chunk) => chunks.push(chunk))
        req.on('end', () => {
          try {
            // 按字符边界截断：直接 subarray 会切开汉字，剩下的半截被 decodeBody 当成 GBK 整段重解（T16）
            const raw = decodeBody(truncateUtf8(Buffer.concat(chunks), 64 * 1024))
            resolve(JSON.parse(raw || '{}'))
          } catch { resolve({}) }
        })
        req.on('error', () => resolve({}))
      })
```

**没有任何** `content-length` 检查、`413`、请求体大小熔断、单 IP 速率限制（`grep -n "content-length\|413\|415" lib/index.js` → 无输出）。宿主层也没有（`dsh-host-webserver` 只管路由，另有一个可选的 gzip 中间件）。

**触发条件**：`fetch(url, {method:'POST', mode:'no-cors', headers:{'content-type':'text/plain'}, body: 'x'.repeat(48<<20)})`。

**真跑输出**：

```
──────── 6.1 请求体上限（声称 64KB） ────────
  发送 8.0 MB body → HTTP 400 用时 17ms  → {"error":"repo 不能为空"}

──────── 6.3 超大 body 的内存（服务端 RSS） ────────
  发送 48 MB → HTTP 400 用时 102ms
  服务端 RSS: 105 MB → 333 MB (Δ 229 MB)
```

8MB 返回 `400 repo 不能为空` 正是「截断在 64KB → JSON 断了 → 解析失败 → `{}`」的实证：请求体被静默截断，客户端拿到的是与体积无关的报错，服务端先把 8MB 收进了内存。

**守数量也没有上限**（`/watch` 新建不看已有条数）：100 次跨站 POST → 100 条守，每条都带自己的定时器与 `gh` 轮询：

```
  100 次跨站 POST 新建 → 200 的 100 条，用时 1651ms，状态文件 99 KB
```

40 条并发的另一组实测同样全部 200：

```
  并发 40 个「新建守」→ 状态码 [200]，最终 watchers 条数 = 46
```

`intervalSec` 被夹到 ≥30s（`lib/index.js:1879`），但 100 条守 × 用户自己的 GitHub token = 每分钟数百次 API 调用，属于「借用户凭证打 GitHub 限额」的放大面。

**修法**：`readBody` 里在 `data` 回调中累加长度，超过 64KB 立刻 `req.destroy()` 并回 `413`；`/watch` 新建前检查 watcher 总数上限（例如 50，面板里给提示）；写路由加最简速率限制（例如同进程 10 次/分钟）。

### 4. `repo` 白名单放行 `.` / `..`：`../../etc/passwd` 被接受成 `repo: "../.."`

**代码**：`lib/watch.js:1136-1142`

```js
  const parts = rest.split('/').filter(Boolean)
  if (parts.length < 2) return { ok: false, error: '要写成 owner/name' }
  const [owner, name] = parts
  if (!/^[A-Za-z0-9_.-]+$/.test(owner) || !/^[A-Za-z0-9_.-]+$/.test(name)) {
    return { ok: false, error: 'owner/name 只能包含字母、数字、下划线、点、短横线' }
  }
  return { ok: true, provider, repo: owner + '/' + name, spec: provider === 'github' ? owner + '/' + name : 'gitee:' + owner + '/' + name }
```

字符类 `[A-Za-z0-9_.-]` 允许 `.` 与 `..` 单独成段，于是 `'../../etc/passwd'` 取前两段 = `owner='..'`, `name='..'`，通过校验。

**真跑输出**：

```
  repo="../../etc/passwd" → HTTP 200 {"ok":true,"id":"../..#session-A","repo":"../..","intervalSec":60,"enabled":true,"warnings":[]}
  repo="C:\\Windows" → HTTP 400 {"error":"要写成 owner/name"}
  repo="a/b/../../../etc" → HTTP 200 {"ok":true,"id":"a/b#session-A","repo":"a/b","intervalSec":60,"enabled":true,"warnings":[]}
```

**为什么不是「必须修」**：`repo` 不进任何文件路径（见第 15 条），最终只是拼进 `gh api repos/<repo>/issues` 这类参数，`spawn(..., {shell:false})` 不开 shell，所以既不能穿越目录也不能注入命令。但脏值会进状态文件、面板、`gh` 参数与 `gh` 的错误信息。**修法**：对 `owner`/`name` 再加一条 `!/^\.+$/` 且禁止以 `.` 开头的段，或直接要求符合 GitHub 的 `^[A-Za-z0-9][A-Za-z0-9-]{0,38}$`。

## 三、确认没问题

审过并实测为「没问题」的点（逐条给了判据）：

1. **没有任何 CORS 放开**：`grep -rn "Origin\|origin" lib/*.js` → 无命中；`grep -n "Access-Control" lib/index.js` → 无命中；实测所有响应 `ACAO=(none)`，`Object.keys(headers).filter(k=>k.startsWith('access-control'))` → `[]`；真机 `GET /state` 响应头也没有 `Access-Control-*`。**跨站读不到响应体**（写仍然成功，见第 1 条）。
2. **`GET /state` 不回凭证**：`secretsSummary()` 只回 `configured`/`none`，且 `tokenHint`/`sshKeyHint`/`ghConfigDirHint` 恒为 `null`（`lib/index.js:286-300`）。实测：种一份运行时拼接的 token 后，`/state` 全文 `includes(token) = false`，`giteeToken` 同理；`/state.credentials` 只有 `{"token":"none"/"configured"}` 这类枚举值。
3. **`/diagnose` 不回凭证**：返回前过 `redact()`（`lib/index.js:2034-2035`），实测 `含 token？ false 含 gitee？ false`。
4. **错误信息不回显输入**：`POST /credentials {token:'not-a-real-shape-1234567890'}` → `{"error":"token shape not recognized (ghp_… or github_pat_…)"}`（固定文案）；`workdir` 报错回显的是**路径**（`workdir does not exist: …`），不是凭证，且该路径本来就是调用方自己传的。
5. **`/update` 出站不带任何凭证**：只 `fetch('https://registry.npmjs.org/…/latest', { headers: { accept: 'application/json' } })`，没有 `Authorization`，也没有把 token 拼进 URL（`lib/index.js:1616-1619`）。
6. **没有把用户输入拼进文件路径**：状态目录只由 `DSH_SUPERAGENT_STATE` 决定（`lib/index.js:75-79`，`STATE_DIR`/`SECRETS_FILE`/`STATE_FILE` 三个常量），实测写盘只有 `secrets.json`、`watchers.json`、`watchers.json.bak`；`repo`/`sessionId`/`id` 都不参与路径拼接。
7. **`sessionId` 不参与路径**：`sessionTitle()` 用它作 `Map` 的键从索引里查（`lib/index.js:347`），不做 `join()`；`GET /state?sessionId=../../../../etc/passwd` → `title=null`。
8. **`worktreePlan` 对 `repo`/`sessionTag` 做字符白名单**（`lib/watch.js:505-515`：`replace(/[^A-Za-z0-9._-]+/g,'-')`、`slice(0,8)`），`..` 会被拼进更长的 `id` 里，形不成独立路径段。
9. **`/trace` 的 `repo` 只做相等比较**：`GET /trace?repo=../../../../etc/passwd` → 只是把该字符串回显进文本（`{"ok":true,"text":"#1 在../../../../etc/passwd 里都没有痕迹 …"}`），不读文件、不拼路径。**不构成 XSS**：面板用 `h()` 生成文本节点，`client.js` 里 `innerHTML` 零命中。
10. **`filters` 不会被原型污染**：`mergeFilters` 逐键白名单（`lib/watch.js:625-637`）。实测 `{"filters":{"__proto__":{"labels":["pwned"]}}}` → `({}).labels` 仍是 `undefined`。
11. **`client-note` 有键白名单**：`CLIENT_NOTE_KEYS`（`lib/index.js:82`），未知键直接丢弃。实测 `key=__proto__` → `HTTP 204`，状态里没有 `note:__proto__`。
12. **无正则爆炸**：`/credentials` 的 token 正则是线性的，60KB 输入 37ms；`parseRepoSpec` 的正则只在 60KB 字符串上做一次 `match`，10ms。没有嵌套量词、没有回溯放大点。
13. **状态文件损坏可恢复**：`readState()` 主文件坏了退回 `.bak`，`.bak` 也坏才留 `.corrupt-<时间戳>` 并从空状态起（`lib/index.js:121-151`）；写盘走「先备份再原子 rename」（`213-251`）。这是可用性而不是安全问题，但和 DoS 相关，一并记下。
14. **宿主只绑回环**：`netstat -ano | grep LISTENING | grep 65466` → `TCP 127.0.0.1:65466 0.0.0.0:0 LISTENING 10096`；`0.0.0.0:65466` 计数为 0。公网不可达——这是当前唯一实质性的缓解，也是第 1 条为什么暂时只算「本机攻击面」而不是「远程接管」。
15. **面板请求带了 `content-type: application/json`**（`client.js:63`），所以面板自己的调用天然走预检；问题只在于服务端同时接受 `text/plain`，把这条防线让掉了。
16. **`DELETE`/`PUT` 等其它方法**：所有写路由都显式 `if (req.method !== 'POST')` 拒掉（`1828`、`1968`、`2088`），实测 `OPTIONS /watch` → `405`。

## 附录 A：怎么复跑

审计用的是「真实 `node:http` 服务 + 真实 `fetch`」，与宿主派发一致（`/tmp` 脚本已删，下面是它的骨架）：

```js
import { createServer } from 'node:http'
import { mkdtempSync, writeFileSync } from 'node:fs'
import { tmpdir } from 'node:os'
import { join } from 'node:path'
import { pathToFileURL } from 'node:url'

const DIR = mkdtempSync(join(tmpdir(), 'zhuli-audit-'))
process.env.DSH_SUPERAGENT_STATE = DIR      // 不碰真状态目录
process.env.DSH_SUPERAGENT_NO_POLL = '1'    // 不真的轮询 GitHub
process.env.DSH_SUPERAGENT_OFFLINE = '1'
writeFileSync(join(DIR, 'watchers.json'), JSON.stringify({ watchers: {
  'acme/widgets#session-A': { id: 'acme/widgets#session-A', repo: 'acme/widgets', provider: 'github', sessionId: 'session-A', intervalSec: 60 },
} }))

const routes = new Map()
const agents = { currentInitiator: () => ({ id: 'session-A' }), get: () => null }
const { apply } = await import(pathToFileURL('D:/主工作区/projects/dsh-session-superagent/lib/index.js').href)
apply({ tools: { register: () => {} }, webServer: { register: (r) => (routes.set(r.path, r), () => {}) },
        agents, get: (n) => (n === 'agents' ? agents : undefined), inject: () => {}, effect: (f) => f(), on: () => {} })

const server = createServer(async (req, res) => {           // 与宿主同构：pathname → handler
  const { pathname } = new URL(req.url ?? '/', 'http://x')
  const r = routes.get(pathname)
  if (!r) { res.writeHead(404); res.end(); return }
  await r.handler(req, res)
})
await new Promise((r) => server.listen(0, '127.0.0.1', r))  // 只绑回环

await fetch('http://127.0.0.1:' + server.address().port + '/session-superagent/watch', {
  method: 'POST', mode: 'no-cors',
  headers: { Origin: 'https://evil.example', 'Content-Type': 'text/plain' },
  body: JSON.stringify({ action: 'pause', id: 'acme/widgets#session-A' }),
})
server.close()
```
