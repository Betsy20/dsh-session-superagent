# 对比：官方 `dsh-superagent-prototype`

> 对象：[`deepseek-ai/dsh-superagent-prototype`](https://github.com/deepseek-ai/dsh-superagent-prototype)
> （TypeScript，`src/` 92 个 `.ts` / 12,390 行，v0.1.0，MIT）。
> 结论写在 [为什么做这个产品.md](为什么做这个产品.md) —— 本文只列事实。

## 它是什么

> A proactive agent for one GitHub repository, as a DSH bundle: it listens to GitHub and
> optionally Feishu, evaluates requests under a Policy, turns authorized ones into Tickets,
> and executes each in its own DSH Session.

核心链路：**Source → Trigger → Thread → Policy → Eval → Ticket → Assignment → Executor → Delivery**。

## 它有、我们没有

### 一、事件源

| 官方 | 我们 |
|---|---|
| 飞书渠道（群消息、图片 `feishu-image`、循环检测 `feishu-loops`、机器人身份） | 无。只有 GitHub + Gitee |
| `Source` 抽象：`kind` 可扩展，官方的 `008-cookbook.md` 教怎么加新来源 | 写死在 `parseRepoSpec` |
| 每个 Source 持自己的读位与机器人身份 | `cursor`/`seen` 挂在 watcher 上 |
| `Subscription`：Thread ↔ Ticket 多对多，后续讨论**自动**到达执行体 | 无。每条新动态都要重新唤醒 |

### 二、授权

| 官方 | 我们 |
|---|---|
| `Policy` 层：按 Source 维护「谁可以派活」，名单外的请求直接丢弃 | **已部分补上**（0.9.252 `allowAuthors`），但只在 GitHub/Gitee 单源、无版本化 |
| Policy 版本化，变更要影响在跑的 Ticket | 无 |
| `Mandate`：记录「为什么可以干、能干多远」 | 无 |

### 三、执行

| 官方 | 我们 |
|---|---|
| `Ticket` 状态机：`open → ended`，人的消息可 resume | 无 Ticket；只有水位线 |
| `Executor` / `Assignment`：Ticket ↔ 执行实例，支持多实例 | 无 |
| 每个 Ticket 独立 agent 会话 + 独立工作目录 | 有隔离 worktree，但仍在**本会话**执行 |
| `Eval` 两层（gate + assessment），输入含 Thread 快照与全部历史 | 单层过滤 + 优先级权重 |
| `Delivery`：结果回写原对话（PR / 评论 / 飞书回复） | 只打 ack 标签，回写靠会话自己 |
| 多角色提示词：orchestrator / worker / handoff | 无 |

### 四、面板

官方 `src/app/views/` + `src/client/`：`overview` / `records` / `settings` / `sources` /
`threads` / `tickets` / `execution` / `deployment` / `eval` / `draft`。

| 官方 | 我们 |
|---|---|
| Ticket 记录页（谁提的、按哪条规则、执行了几次） | 有「追溯一条」，但只到「为什么没叫醒」 |
| 草稿视图（面板里起草回复） | 无 |
| 执行视图（正在跑什么、卡在哪） | 一行状态 |
| 部署视图（升级/配置/排障） | 无 |
| 多语言 `locale/en.json` + `zh.json` | 中文硬编码 |

### 五、安装与运维

| 官方 | 我们 |
|---|---|
| 交互式安装向导 `SETUP.md`：一次一问、先收齐再执行、永不在聊天里索要密钥 | 一条命令 + README |
| `migration.ts`：版本间数据结构迁移 | 靠 `readState()` 兜底 |
| 健康检查 / 重试健康度 / outbox | `/diagnose` + `watch_doctor` |
| 打包的 skills（`dsh-superagent-github` / `-feishu`） | 无 |
| 提示词可配置（`prompt-config` + 面板 prompts 页） | 唤醒消息模板写死在代码里 |

## 我们有、它没有

| 我们 | 官方 |
|---|---|
| **Gitee 支持**（字符串编号、标签、429 处理，真机联调过） | 只有 GitHub |
| **分诊信号表**（躺多久 / 有 PR / 草稿 PR / CI 红绿 / 认领状态，带权重与开关） | 有 assessment，但没有这套可配置清单 |
| **唤醒消息即任务书**（完成标准 + 下一步 + 权限提示） | 侧重 Ticket，不侧重「叫醒之后怎么干」 |
| **自检命令** `dsh-zhuli`（不依赖宿主加载） | 靠模型工具自查 |
| **凭证不进模型**（`redact()` 统一出口） | 未见同等机制 |

## 判断

**该抄**：Policy 白名单（已抄最小版）、Ticket 状态机 + resume、Delivery 回写、多语言。

**不该抄**：飞书/多 Source、Executor 多实例、orchestrator/worker/handoff ——
那是「一个 agent 服务整个团队」的形态，会把「1 个人 5 分钟装好」变成「一支队伍一下午配好」。

**该警惕**：它的 Ticket 状态机 vs 我们的水位线。水位线表达不了「这条还在进行中」，
这是我们未来最可能撞墙的地方。
