# 报告：设置页三个分区的视觉核对（深色，0.9.179）

> **出图**：`shot-set-source.png` / `shot-set-diag.png` / `shot-set-update.png`，均 1000×1000。
> **渲染源**：`node scripts/render-preview.mjs --only=设置（来源|诊断|版本与更新） --dark`，即真实 `client.js` + 移植 CSS，浅色页面里嵌一块 900px 的深色面板。
> **量尺寸的做法**：不靠肉眼。无头 Edge `--dump-dom` + 注入的 `getBoundingClientRect()` / `Range.getBoundingClientRect()` 采样，数字见各节「实测」。
> **只读约束**：`client.js` / `lib/**` / `scripts/**` 一行未动；本报告之外只新增了 3 张 png。

**读图须知（很关键）**

1. 三张图**没有一处文字被真正截断**。逐个文本节点实测 `scrollWidth == clientWidth`、行高整除，全页 0 次横向溢出。下面每节第一条给的是「最接近切边的那一行」的余量数字，其余是能指着图说清楚的层级/对齐问题。
2. 任务书里 `--window-size=760,900` 的截图参数会**切掉预览框右侧 164px**（预览框固定 900px 宽、左起 x=24，760 处切断）。我实跑过：`仓库` 的值只剩到 `someone/b…`；工具栏 `全部暂停`（x=727..795）被切断、`全部恢复`（x=803..871）整块在画面外，图上最后只剩半个字。那是**截图切边、不是 UI 截断**，所以最终三张图用 `1000×1000` 出，整块面板完整可见。
3. 预览里工具栏 `术语` / `刷新` 两个按钮的图标是坏的（按钮高 28px、内容实测 89px）。原因在工装：`render-preview.mjs` 的 `render()` 属性白名单里没有 `width` / `height` / `viewBox`，`<svg>` 拿不到尺寸。**这不是面板缺陷**，我看图时已排除；要修得改 `scripts/`，本任务只读。

## 一、来源

**整卡**：`x=228 w=643 h=188`，内边距 16（内容 609）；标签列 `x=245 w=52`，值列 `x=313 w=541`，行距 26px（20 行高 + 6 gap）。五行标签左边缘完全对齐、五行的值左边缘也完全对齐 —— **这一节的列对齐是对的**，问题在信息层级。

### 1.1 `仓库` 一行是全卡最挤的一行（余量 23px）

- 图上位置：卡片第 1 行，`仓库` 右边那串 `MYCF711/dsh-session-superagent, MYCF711/dsh-GOkifu-compact, someone/broken-repo`。
- 实测：文字宽 **518px**，值列可用 **541px**，余 **23px** —— 是三张图里横向余量最小的一行。第二长的行（`隔离占用`）只有 188px，**相差 2.75 倍**。
- 问题：三个仓库靠 `", "` 两个字符（约 8px）粘成一条 518px 的长行，没有「共 3 个」的计数、没有换行分组。扫读时第三个 `someone/broken-repo` 和前面两个分不开 —— 而它恰好是三个里唯一一个不属于 `MYCF711` 的仓库（示例数据里就是它 404），最需要被看见。
- 边界行为（实测）：宽屏下不切、刚好一行；收到 600px 时这一行折成 **2 行**（`h: 20 → 40`），折行点是 `overflow-wrap: anywhere`，会在 `owner/name` 中间劈开，不会在逗号处干净断行。

### 1.2 `凭证` 与左栏「凭证」同词不同义，且与 `gh CLI` 的互斥关系没写出来

- 图上位置：左栏第 2 项是 `凭证`（分区导航）；右侧卡片第 3 行标签也是 `凭证`（值是 `使用面板配置的 token`）。
- 同一个词在同一屏出现两次、指两样东西：一个是「点进去能填 token 的分区」，一个是「当前认证凭据」这一条事实。点左栏「凭证」进来看到的是三个输入框，和这一行的含义不是一回事。
- 同时 `gh CLI`（`可用 · gh version 2.101.0`）与 `凭证`（`使用面板配置的 token`）在业务上是**二选一**关系（配了 token 就不走 gh 登录态），图上却是两行等权的事实，读者无法判断哪一条在生效。

### 1.3 `隔离占用` 的值把同一个数字写了两遍，且「2 个」没有说是什么的个数

- 图上位置：卡片第 5 行 —— `2 个 · 256.0 KB（合计 256.0 KB）`。
- 实测文字宽 188px，其中 `256.0 KB` 出现两次。只有一个隔离根时「合计」必然等于前一个数，括号里的内容恒等于前面的数（本图就是这种情况）。
- 「2 个」缺量词：没说清是隔离根目录还是工作树；读者要读到括号里才明白后面那个 KB 是体积。
- 补：这一节是五条只读事实，**通篇没有一句说明**（对比：`诊断` 有一句 13px hint、`版本与更新` 有两句），首次打开的人不知道这一页能做什么、要去哪改。

## 二、诊断

**整卡**：`x=228 w=643 h=439`；标题 `分诊信号与取舍`（105×20）；说明句 `494 / 609 px`；五行信号，每行 `65 / 65 / 65 / 64 / 64` px。图上五行都完整可见，没有被截断。

### 2.1 分值 `+N 分` 是这一页的排序依据，却是全页最不齐的一列（左右各抖 28~40px）

- 图上位置：五行行尾的 `+100 分` / `+10 分` / `+5 分` / `+3 分` / `+2 分`。
- 实测左边缘：`436 / 422 / 408 / 420 / 434` —— **跨度 28px**；右边缘：`478 / 457 / 438 / 450 / 464` —— **跨度 40px**。原因是行标题是 `display:flex; align-items:center; gap:8px` 的左打包，每个 chip 紧跟上一个，前一个宽度变一点，后面全跟着漂。
- 同一现象也发生在 `事实` / `判断`（`331 / 317 / 303 / 317 / 331`）和 `默认开` / `默认关`（`377 / 363 / 349 / 363 / 377`）这两列上。
- 而右侧**空着 368px**（行标题区 `x=253..846`，第一行内容只用到 `478`）。有空位却不给这三列定列宽 —— 一眼看不出「谁权重高」，只能逐行读数字。
- 图上看点：五行行尾的数字块连不成一条竖线 —— `带标签` 那一行的 `+5 分` 比第一行的 `+100 分` 左移 28px（约两个字符宽），比上一行 `+10 分` 也左移 14px。

### 2.2 `默认关` 和 `默认开` 是两种不同形态，`关` 那一档更轻

- 图上位置：`被重新打开/有人评论/带标签` 三行是 `默认开`，`无人认领/长期没动静` 两行是 `默认关`。
- 实测：`默认开` = **51×21，border 1px `#3d444d`**（描边胶囊）；`默认关` = **49×19，border 0px**（纯灰字）。两档高度差 2px，`关` 没有边框圈住。
- 问题：同一列里「开/关」是一个二元状态，却用了「胶囊」和「裸字」两种形态，视觉上 `默认关` 像一条注解而不是状态值。读者会以为关的那两行少了点什么（而它们恰恰是「默认不开」的信号，信息量不比上面小）。

### 2.3 导航写「诊断」，卡片标题写「分诊信号与取舍」

- 图上位置：左栏第 4 项 `诊断`（图上高亮项），右侧卡片第一行大字 `分诊信号与取舍`。
- 五个分区里，4 个的卡片标题与导航项逐字相同，只有这一项不同 —— 点「诊断」进来先看到一个大标题叫别的名字。
- 更麻烦的是「诊断」这个词在本插件里另有指代：`版本与更新` 页底部那颗 `复制诊断信息` 按钮复制的才是「诊断」。同一份面板里，`诊断` 既是分区名、又是另一个分区的产物名，而真正在这里的信号权重表跟「诊断」没关系。

## 三、版本与更新

**整卡**：`x=228 w=643 h=320`；卡片上方还有一条横幅 `x=64 w=807 h=46`。这一页是三张图里唯一有「动作」的分区。

### 3.1 命令、`复制命令`、`重新检查` 三个东西视觉权重完全一样，且上下只隔 8px

- 图上位置：卡片下半部，从上到下依次是 `dsh plugin add dsh-session-superagent@0.9.0`（一行等宽字）、`复制命令`、`重新检查`。
- 实测：命令 `.dt-code` = **266×12，12px 等宽，背景 `#161b22`**（一行内联色块，既不是块级也不占满宽）；`复制命令` = **68×28，color `#e6edf3`、background `rgba(0,0,0,0)`、border `0px`**；`重新检查` = **68×28，同上**。两个按钮都是**无边框、无底色、与正文同色的白字**。
- 后果：这一页唯一的产出物（命令）最弱，复制它的按钮和「重新检查」长得一模一样、还紧贴在它下面 8px（`y=604` 与 `y=640`，两按钮之间只有 8px）。三个元素读起来像一个控件组。
- 而它们干的活完全不同：`复制命令` 写剪贴板（且**没有任何 toast 反馈**），`重新检查` 会发一次 `/update?refresh=1` 并把上方三行 kv 改掉。点错一次的观感是「我点复制，怎么上面的数字变了」。

### 3.2 同一组事实说了两遍：全宽横幅 + 卡内三行 kv

- 图上位置：卡片**上方**那条橄榄色横幅 `有新版本 0.9.0（当前 0.8.45）`；卡片**内部**三行 `当前版本 0.8.45` / `npm 最新 0.9.0` / `状态 有新版本，可以升级`。
- 实测横幅：宽 **807px**，文字只占 **257px（31.8%）**，右侧 550px 是空的 —— 一条横贯整个面板的色带只装了 12 个字，而它复述的三件事（0.9.0 / 0.8.45 / 有新版本）在下方 109px 处逐条又写了一遍。
- 层级后果：横幅是页面上最抢眼的东西（带底色），却只是「入口」；真正要读的版本号和状态在卡片里，视觉权重反而低。用户扫一眼只记住横幅，不会去读卡片。

### 3.3 文案承诺「下面这份诊断」，版面里只有一颗按钮

- 图上位置：卡片偏下第二段灰字 —— `反馈问题时把下面这份诊断贴给对方：里面有版本、挂载状态和每条守的最近错误（凭证已脱敏）。`，它下面 8px 是 `复制诊断信息` 按钮（`94×28`，三颗按钮里唯一有描边的）。
- 「下面这份诊断」指向的是一份可读的诊断正文，但版面里没有任何正文 —— 内容只在剪贴板里。读者按字面往下找，只找到一颗按钮。
- 顺带：两条 hint 之间只有 8px（`y=676` 与 `y=704`，各 555 / 572px 宽单行），1127px 的文字压在按钮区下面，`复制诊断信息` 被推到 `y=732`，是整卡最靠下的元素。

## 五、结论

**最该先修的一处：`版本与更新` 页的「命令 + 复制命令 + 重新检查」区。**

理由，按重要性排：

1. **这是三个分区里唯一有任务的一页。** 来源和诊断都是只读事实（改不改都不影响能不能用），更新页的存在意义就是「把 `dsh plugin add …` 这条命令复制走」。而现在这一页最弱的元素恰恰是命令本身（266×12 的内联色块），最抢眼的却是上方横幅和两颗与正文同色的白字按钮 —— 三个显眼的东西，没有一个指向「复制命令」。
2. **错一次有代价，而且代价被藏起来了。** `复制命令` 与 `重新检查` 实测同尺寸（68×28）、同颜色（`#e6edf3`）、同无边框、上下仅隔 8px；点前者只写剪贴板（无任何反馈），点后者会发一次网络请求并改写上方三行 kv。用户点错之后看到「数值变了」，会归因到复制失败或版本被改，而不是「我点到隔壁了」。
3. **改法最小、风险最低。** 命令包成块级（`.dt-code` 改 block + 8/10 padding + 圆角 + 允许换行），`复制命令` 贴到命令块同一行右侧并给 `variant='outline'`（和 `复制诊断信息` 对齐形态），`重新检查` 降级成 `dt-textlink` 并移到三行 kv 下方、与复制区间隔 ≥16px。只动三处 JSX/一条 CSS，不碰状态机。
4. **改完顺带修掉 3.2 的重复**：横幅保留（它是跨分区的入口），把卡内 `状态：有新版本，可以升级` 换成它没有的信息（例如「需要重载宿主才生效」），横幅与卡片就不再互为复读。

**第二优先**：诊断页的分值列（2.1）。右端抖 40px、右侧空 368px，只要给行标题加 `flex-wrap:nowrap` + 把 `+N 分` 用 `margin-left:auto` 顶到右边，五行立刻成列，成本一行 CSS，收益是这张表的排序依据第一次可扫读。

**不建议现在动的**：`来源` 的五条事实（1.2 / 1.3）。它们是文案与信息取舍问题，牵涉「凭证/gh CLI 到底谁生效」的产品口径，单改排版治不了；而且这一页没有功能性错误，修它的收益排在最后。

**没验的**：浅色主题（本任务只出深色三张）；真机宿主的实际面板宽度（预览固定 900px，600px 只是脚本 `--mobile` 的模拟）；hover / focus 态（静态出图看不到）。
