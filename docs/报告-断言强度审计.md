## 一、必须加强

### 1. `test/routes.test.mjs:1077-1083` —— 断言在算测试自己的算术，生产代码一行没参与

```js
// 间隔下限：min(配置, GitHub 要求) 取大者 —— 用纯函数验证逻辑本身
const { nextDelayMs } = await import('../lib/watch.js')
const entry = { consecutiveFailures: 1, minIntervalSec: 90 }
const base = 60000
const floor = Math.max(base, entry.minIntervalSec * 1000)
assert.equal(floor, 90000, '下限应当是 90 秒')
assert.ok(nextDelayMs(entry, floor) >= floor, '退避只在更大的方向上生效')
```

- **它现在测不出什么**：`floor` 是测试自己用两个字面量算出来的，`Math.max(60000, 90 * 1000)` 恒等于 90000；真正的实现 `effectiveIntervalMs()`（`lib/index.js:481-484`）一次都没被调用。把 `Math.max` 改成 `Math.min`、或让 `minIntervalSec` 彻底失效，这两条照样绿 —— 而标题声称守的正是「尊重 x-poll-interval」。
- **建议**：把 `effectiveIntervalMs` 挂进 `__test`（`lib/index.js:76`）后打真值：

```js
assert.equal(__test.effectiveIntervalMs({ minIntervalSec: 90 }, 60000), 90000, 'GitHub 要求更慢就照它等')
assert.equal(__test.effectiveIntervalMs({ minIntervalSec: null }, 60000), 60000)
assert.equal(__test.effectiveIntervalMs({ minIntervalSec: 30 }, 60000), 60000, '更短的要求不能把间隔压小')
```

  退而求其次，至少用 spy 断言 `nextDelayMs` 收到的第二个实参就是 `90000`。

### 2. `test/client.test.mjs:1171-1177` —— 标题说「默认值从 /state 的 defaults 读」，断言只看了「有内容」


- **它现在测不出什么**：两条断言只证明「渲染出了字」和「没有 undefined」。把面板里的默认值写死成 `12/3/6` —— 正是这条用例声称要防的回归 —— 照样全绿。`dflt` 算出来以后从没被使用。
  实测证据：把 defaults 传成 `{ sessionMaxWakes: 30, maxWakesPerHour: 4, isolateKeepDays: 7 }`，触发页渲染出的输入框 placeholder 是 `5（1-20）`、`6（1-60）` —— 单守上限那个 `6（1-60）` 是 `client.js:1350` 写死的，根本没读 `defaults.maxWakesPerHour`。

```js

```

  这条改完会**先红**：`client.js:1350` 把 `'6（1-60）'` 写死了。要么改实现，要么把用例标题改成实际口径 —— 别让标题继续声称一个不存在的能力。

### 3. `test/redact.test.mjs:42-63` —— 只要输出里出现 `***` 就算脱敏成功

```js
test('真实凭证形状：25 种里新增的 16 种都要脱掉（审核 M2/M3）', () => {
  ...
  for (const [name, input] of cases) {

  }
})
```

- **它现在测不出什么**：`includes('***')` 只要求任意位置出现标记。如果 `redact` 只替换了凭证**前缀**（比如把 `glpat-` 换成 `***`、后面 25 位原样留下），或者返回 `'***' + input`，这条仍然绿 —— 而这正是「凭证漏进模型上下文」的最坏形态。14 个样例里没有一个被验证「密钥本体消失」。
  另外标题写「25 种里新增的 16 种」，`cases` 数组实际只有 **14** 条：数字本身就对不上，少两条也没人知道。
- **建议**：用同文件第 4 行已经 import 的 `hasSecret` 做「脱完必须再无凭证」：

```js
const out = redact(input)
assert.equal(hasSecret(out), false, name + ' 还有凭证残留：' + out)
assert.notEqual(out, input, name + ' 一个字都没动')
```

  对「整串就是凭证」的 **10 条**再加 `assert.equal(out, '***')`；Google（残留 `***5`）、DB URL（残留 `***localhost:5432/db`）、Redis URL（残留 `***cache:6379`）、查询参数（残留 `https://x.example/a***`）这 4 条保留前后缀，改成断言 `!out.includes(<密钥片段>)` 即可（实测 14 条全部满足 `hasSecret(out) === false`）。顺便把标题的 16 改成 14，或补齐缺的两条。

### 7. `test/gate-lock.test.mjs:32-41` —— 锁目录是测试自己建的，`existsSync` 恒真

```js

  const lockPath = tmpLock()
  mkdirSync(lockPath)
  writeFileSync(join(lockPath, 'owner.json'), JSON.stringify({
    name: 'stale', pid: 999999, at: new Date(Date.now() - 3600_000).toISOString(),
  }))
  const release = acquireGate('unit-stale', { quiet: true, timeoutMs: 3000, lockPath })
  assert.ok(existsSync(lockPath), '应该已经拿到锁')
  release()
})
```

- **它现在测不出什么**：`lockPath` 在第 34 行就被 `mkdirSync` 建出来了，`existsSync` 必然为真。这条断言分不清「陈旧锁被清掉后重新建」和「压根没清、直接复用旧目录」，也看不出 `owner.json` 有没有换成当前进程。真正失败时是 `acquireGate` 等到超时抛 `GATE_BUSY` —— 那是抛错在兜底，不是这条断言在起作用。
- **建议**：断言锁的归属确实换了人：

```js
const owner = JSON.parse(readFileSync(join(lockPath, 'owner.json'), 'utf8'))
assert.equal(owner.pid, process.pid, '陈旧锁必须被当前进程接管')
assert.notEqual(owner.pid, 999999)
assert.ok(Date.parse(owner.at) > Date.now() - 60_000, 'owner.json 要是这一轮写的')
```

  再补一条反向用例：`pid` 用当前进程（活着的持有者）时，`acquireGate` 必须**不**清理、按 `timeoutMs` 抛 `GATE_BUSY`。

## 二、值得加强

拿不准的、或者「测到了但太松」的都在这里。按严重程度递减。

1. **`test/gitee.test.mjs:206-210`** —— 空标签名只断言 `res.ok === false`，不看 `reason`。`ensureGiteeLabel` 对任何失败（403 / 网络 / 空名）都返回 `ok:false`，这条分不出是「空名被拒」还是「请求失败」。建议加 `assert.equal(res.reason, 'empty-label')`。
2. **`test/watch.test.mjs:1546-1554`** —— `repo` 为 `.` / `..` 的四条只断言 `ok:false`。`parseRepoSpec` 对任意非法串（包括 `'bad'`）都返回 false，这条看不出是「相对段」被专门拦住。建议 `assert.match(res.error, /\.\.|相对|repo/)` 之类，或至少断言 `'o/..'` 与 `'o/r'` 走的是不同分支。
3. **`test/routes.test.mjs:139-151`** —— 标题「非法 action / 未知 id / 非 POST 都有明确响应」，四条断言只有状态码（400/404/405），`error` 文案一个字没看。建议每条补 `assert.match(res.json().error, /action|id|method/)`。
4. **`test/routes.test.mjs:1374-1382`** —— 凭证写入校验只看 400，不看 `error` 是「sshKeyPath 必须绝对」还是「ghConfigDir 必须绝对」——两条路径可以互相顶替。建议分别 `assert.match(...error, /sshKeyPath|绝对/)`、`/ghConfigDir/`。
5. **`test/routes.test.mjs:1226-1228`** —— 断路器用例的断言是 `/凭证已失效|auth/i.test(text)`。`"auth"` 这个分支几乎任何 JSON 都能命中，等于只有「凭证已失效」那一半有效。建议去掉 `|auth`，直接断言 `ack.error` 含「凭证」。
6. **`test/routes.test.mjs:361`** —— ETag 不匹配时只断言 `watchers.length > 0`，没断言返回的是「完整且最新」的内容。建议断言 `JSON.parse(third.body).watchers[0].id` 与创建时一致，并对比 `third.headers.etag !== '"stale"'`。
7. **`test/routes.test.mjs:380-383`** —— `assert.ok(list.length > 0, '应该有守')` 依赖前面用例留下的状态（同一个 `STATE_DIR`），且只看长度。建议在用例内自己建一条守再断言，或直接 `assert.ok(list.some((w) => w.repo === 'o/reason'))`。
8. **`test/routes.test.mjs:407`** —— `watch_start` 返回值只断言 `typeof res === 'string'`，不看 `watching o/parity`。建议 `assert.match(res, /watching o\/parity/)`。
9. **`test/client.test.mjs:1202-1224`** —— 两个原生时间选择器的断言是硬的（`type === 'time'`、起止 `aria-label` 都在）。但注释写的「跨夜要写出来（22:00-06:00）」只落到 `assert.ok(night.length > 0)` —— 渲染出任何一个节点都算过。建议断言跨夜时两个 time input 的 `value` 是 `22:00` / `06:00`，或断言有「跨夜」标记。
10. **`test/gate-lock.test.mjs:61-74`** —— T18 用例只断言「env 里的 token 不再是伪造值」。`acquireGate` 把 env 删掉（undefined）也能过。建议补：`owner.json` 存在、`owner.token === process.env.DSH_GATE_LOCK_TOKEN`、且 `owner.token !== 'forged-token-not-ours'`。
11. **`test/gate-lock.test.mjs:26-30`** —— 「重复释放不抛」只有 `doesNotThrow`，没验证第二次释放后锁目录已经没了、且没误删别人的。标题与断言一致，但补一条 `assert.ok(!existsSync(lockPath))` 更完整。
12. **`test/gh-format.test.mjs:51`** —— helper 里 `assert.ok(why.short.length > 0, ...)` 是「只看长度」。同文件其它断言都是具体文案（`/Gitee/`、`'私人令牌'`），这一条最松。`short` 只是把入参截到 200 字（`lib/gh-format.js:76-80`），建议断言它带着原始报错的关键词，例如 `assert.match(why.short, /不存在|Not Found/)`。

15. **6 处「只看真假」的 `assert.ok`**（`gitee.test.mjs:50`、`gitee.test.mjs:117` 的 `pr.pull_request`；`client.test.mjs:1267` 的 `head`、`client.test.mjs:1336` 的 `empty`、`client.test.mjs:1363` 的 `stat`；`routes.test.mjs:171` 的 `state.gh.skipped`）—— 值本身往后一句就不再被检查。其中 `pr.pull_request` 建议断言 `typeof === 'object' && pr.pull_request.url`；`state.gh.skipped` 建议 `assert.equal(typeof state.gh.skipped, 'string')` 并断言非空。
16. **源码文本断言**（`client.test.mjs:1492-1495`、`watch.test.mjs:1450`、`routes.test.mjs:1302-1308`、`meta.test.mjs:178`）—— `src.includes('xxx(')` 分不清「真调用」和「注释 / 死代码里提到」。它们挡住了「代码在但没接上」的一类事故，价值有，但强度上限就在这。建议至少配一条行为断言（本次审计里 `watch.test.mjs:1413` 的 `iso` 用例就是这个形态的范本：只做静态扫描，没有行为断言）。
