# 面板「死交互」审计（只读）

> 仓库：`D:\主工作区\projects\dsh-session-superagent`（`dsh-session-superagent` 0.9.214）
> 审计对象：`client.js`（2211 行，`h()` 手写 React）
> 范围：**点了有没有用 / 用了是不是客户以为的效果**。视觉、对比度、状态管理、断言强度前几轮已审，本轮不重复。

## 怎么跑出来的

1. `grep -n "onClick|onChange|disabled" client.js` 列候选 → 逐段打开上下文判定（`grep` 只给候选，结论全部来自读那一段）。
2. 用仓库自带的 `test/fixtures/panel-harness.mjs`（`loadClient()` / `render()` / `walk()`）把组件渲染成树，
   找节点 → 读 props → **直接调 `props.onClick()`**，用假 `fetch` 抓 `POST /watch`、`POST /credentials` 的 body。
3. 仓库那份 harness 的 `useState` setter 是 `() => {}`（重渲染跑不起来），所以「改控件 → 保存」这条链
   另用同源沙箱 + 会重渲染的极简 React 桩跑了一遍（`app()`：`useState`/`useRef` 真存活，`setState` 触发重渲染，
   `settle()` 反复渲染到稳定）。两份探针都放在 `/tmp` 下，**跑完已删**，仓库里不留痕迹。

判定口径：`onClick` 抛错 / 发出去了但缺字段 / 构造了动作却没人渲染 → **必须修**；
文案与行为对不上、反馈缺失、两个入口不一致 → **值得修**。

### M1 行内编辑器改「只处理这些标签 / 只看已指派 / 优先级五项」，点「保存」**一个字节都发不出去**

`client.js:1121-1125`（`saveEdit` 里挑字段的那段）：

```js
            const out = { repo: full.repo, sessionId: full.sessionId }
            for (const key of touchedRef.current) {
              if (Object.prototype.hasOwnProperty.call(full, key)) out[key] = full[key]
            }
```

`touchedRef` 收的是**控件名**，`full` 的键是**字段名**，两套名字对不上：

| 控件（`setField` 记下的键） | 源码 | `full` 里的键 | 结果 |
|---|---|---|---|
| `labels` | `client.js:1345` | `filters`（`client.js:1099`） | 丢弃 |
| `onlyAssigned` | `client.js:1348` | `filters`（`client.js:1101`） | 丢弃 |
| `priorityReopened` / `priorityComments` / `priorityLabels` / `priorityUnassigned` / `priorityStale` | `client.js:1353-1357` | `priority`（`client.js:1110-1116`） | 丢弃 |

`hasOwnProperty(full, 'labels')` 为 `false`，所以这一项直接被 `if` 吃掉；`priority*` 同理。
`full.filters` / `full.priority` 两个嵌套对象**永远进不了 `out`**。

**客户会看到什么（不一致的具体表现）**

展开一条主理鱼 → 把「只处理这些标签」改成 `bug,urgent` → 点「保存」→ 右下角跳出「已保存：owner/name」→ 编辑器收起。
再展开：标签框又是空的。同理，「只看已指派」拨开、五个「优先级」开关任意拨动，保存后全部弹回原样。
**提示说「已保存」，实际一个字段都没发。** 更坏的是同一屏里的「间隔（秒）」「目标/规则」「仅观察」是正常的
（真跑：body 里 `"intervalSec":300`、`"goal":"只修 P0"`、`"observe":true` 都在），
所以客户会认为「保存没问题，就是这几个开关坏了」，反复点。

真跑（`/tmp/sa-audit/react-probe.mjs`，改控件 → 点保存）：

```
[对照组 · 间隔（秒）改成 300]
  POST /watch body = {"repo":"a/b","sessionId":"session-a/b","intervalSec":300}
  带 filters ? false | 带 priority ? false | 带 intervalSec ? true

[T1 · 只处理这些标签 改成 bug,urgent]
  draft 后 = {... "labels":"bug,urgent" ...}
  POST /watch body = {"repo":"a/b","sessionId":"session-a/b"}
  带 filters ? false | 带 priority ? false | 带 intervalSec ? false

[T2 · 只看已指派 打开]
  draft 后 = {... "onlyAssigned":true ...}
  POST /watch body = {"repo":"a/b","sessionId":"session-a/b"}

[T4 · 优先级五项一起改]
  draft 后 = {... "priorityReopened":false,"priorityComments":false,"priorityLabels":false,"priorityUnassigned":true,"priorityStale":true ...}
  POST /watch body = {"repo":"a/b","sessionId":"session-a/b"}
```

`draft` 明明已经改对（说明控件的 `onChange` → `setField` 没问题），是提交时被过滤掉了。

**建议怎么改**

两种改法，选一种即可：

1. **建映射**（改动最小）：给 `setField` 加第二个参数记「字段名」，或者直接拿一张表
   `const FIELD_OF = { labels: 'filters', onlyAssigned: 'filters', priorityReopened: 'priority', ... }`，
   `out[FIELD_OF[key] || key] = full[FIELD_OF[key] || key]`。
2. **让 `touchedRef` 直接记字段名**：`setField(next, 'filters')` / `setField(next, 'priority')`，
   `saveEdit` 里不再做名字翻译。语义更直白，也不会因为以后加控件再漏一次。

配套：补一条回归用例——「改 labels/onlyAssigned/任一 priority → 保存 → body 里必须同时出现 `filters` 和 `priority`」。
现在 `test/client.test.mjs` 里没有一条用例碰过 `saveEdit` 或 `POST /watch`
（`grep -n "'/watch'\|saveEdit\|POST" test/client.test.mjs` 无输出），所以这个洞能活到 0.9.214。

### M3 「保存凭证」无条件下发 `ghConfigDir: ""` —— 只改 token 也会把已绑定的 gh 账号目录清掉

`client.js:1171-1177`：

```js
      const saveCredentials = () => run(async () => {
        const payload = {}
        if (token.trim()) payload.token = token.trim()
        if (giteeToken.trim()) payload.giteeToken = giteeToken.trim()
        if (ghDir.trim()) payload.ghConfigDir = ghDir.trim()
        else if (ghDir === '') payload.ghConfigDir = ''   // 显式清空 = 回到宿主账号
        await call('/credentials', { method: 'POST', body: JSON.stringify(payload) })
```

`ghDir` 的初值是 `useState('')`（`client.js:1013`），输入框（`client.js:1804`）也从来不回填服务端已存的值。
所以**只要客户不手打一遍那个目录，`ghDir` 永远是 `''`**，`else if` 分支永远命中。
服务端 `lib/index.js:2063` 对空串是 `delete next.ghConfigDir` —— 静默解绑。

**客户会看到什么（不一致的具体表现）**

设置 → 凭证，上面 `KeyValues` 明写「gh 账号：**已绑定独立配置目录**（评论挂智能体账号）」（`client.js:1800`），
下面「gh 账号目录」输入框是**空的**。客户只把新 token 粘进 Token 框、点「保存凭证」：
提示只说「凭证已保存」，一个字没提 gh 账号绑定被一起清掉 —— 之后所有评论改用宿主账号发。
上面那行会悄悄从「已绑定独立配置目录」变成「宿主当前登录的账号」，客户多半以为是插件抽风，
更不会想到是自己刚才点「保存凭证」造成的。界面上「已绑定」和实际行为直接矛盾。

真跑：

```
[界面显示] 含「已绑定独立配置目录」= true
           客户只动了 Token 框，gh 账号目录框是空的 = true
[T9]  POST /credentials body = {"token":"ghp_<redacted>","ghConfigDir":""}
  → 发出去的 ghConfigDir = "" （服务端 lib/index.js:2063 对空串执行 delete）
```

**建议怎么改**

把「没填」和「要清空」区分开，二选一：

1. 输入框初值回填服务端已存目录（`/state` 现在只回 `'configured'`/`'none'`，需要多回一个 `ghConfigDirPath`），
   保存时 `if (ghDir.trim() !== initial) payload.ghConfigDir = ghDir.trim()`；
2. 或者干脆不让这个框承担「清空」语义：删掉 `else if (ghDir === '')` 那行，另加一个独立的
   「解除绑定（回到宿主账号）」按钮，点它才发 `ghConfigDir: ''`。

顺带：`<Input type="password">` 那两个 token 框同理（留空 = 不改，这个语义是对的），只有 gh 目录框是错的。

### W4 「需要关注」的条数和「只看有问题的 (N)」不是同一口径

- 「需要关注」的标题数字是 `problems.length`（`client.js:1523`），一条守可能贡献 2 条（例如 `lastError` + `silentWakes`）。
- 「只看有问题的 (N)」的数字是 `watchers.filter(hasProblem).length`（`client.js:1696`），是**守的条数**。
- 判定集合也不同：`hasProblem`（`client.js:1446-1449`）没有 `lastReopened`（`client.js:1417` 会进 `problems`），
  反过来 `problems` 里的 `gh` / `cred` 两条是全局的、不属于任何守。

结果：同一屏上「需要关注 **5**」和「只看有问题的 (**3**)」并排出现；而且点「只看有问题的」会漏掉那条
「被重新打开过」的守 —— 客户明明在「需要关注」里看到它，点筛选后它却消失了。
建议统一成一个 `problems` 的派生集合（守维度 `Set`），两处都读它。
